# 《规聚：把规划工作聚到一起》25页汇报口播稿

> 建议时长：约10分钟。PPT页面只讲核心观点，视频页让视频承担主要展示；如果视频较长，可以按现场时间随时跳过或加速。

## 开场总述

今天汇报的是“规聚”，一个面向交通规划工作的 AI 一体化工作台。它不是简单增加一个聊天窗口，而是把规划资料、知识库、规范模板、专业技能、地图分析和最终成果，放到同一个可持续工作的环境里。

今天主要讲五件事：为什么要做、规划工作的基本流程是什么、规聚如何把知识和工具接入流程、目前已经有哪些功能，以及下一步如何继续建设。

## 01｜封面：规划工作，聚到一起（约20秒）

今天介绍的项目叫“规聚”。“规”代表规划成果、规划规则和规划知识；“聚”代表把分散在文件夹、电脑、软件和个人经验里的内容重新组织起来。

我们希望让规划工程师面对一个任务时，不需要在多个软件和多个目录之间来回寻找，而是可以在一个工作台里完成资料整理、分析判断、文本编制、地图表达和成果交付。

首页右侧的动画展示的就是这条链路：提交一个任务之后，系统读取资料、检索知识、调用能力，最后形成可以继续修改的成果。

## 02｜汇报路径：从最基本的规划工作流程出发（约20秒）

我们先不把规聚当成一张功能清单，而是回到最基本的规划工作流程：先找资料，再理解规则；然后做分析、形成判断；接下来写成文本、制作图表和地图；最后经过审查，形成可以交付的成果。

规聚的设计，就是围绕这条基本流程，把原来分散的环节连接起来。

## 03｜为什么要做规聚（约30秒）

规划工作从来不是单点任务。它既需要历史项目和基础资料，也需要规范、模板、专业经验和数据分析；最终还要形成报告、图表、地图和汇报材料。

过去这些内容大多分散在不同工程师的电脑和不同项目目录里。资料很多，但没有被充分检索和复用；经验很多，但没有形成组织资产。规聚要解决的，正是知识和成果之间断开的这一段。

## 04｜当前规划工作的痛点（约30秒）

第一，资料分散，文件、表格、地图和历史项目分布在不同位置。第二，知识难找，很多规范要求依靠个人记忆。第三，重复劳动，同一段内容要在文档、表格、图表和PPT之间反复搬运。第四，成果难追踪，过程中的修改、判断和经验很难沉淀下来。

所以我们需要的不是又一个孤立工具，而是一个能够承载完整任务上下文的工作台。

## 05｜项目解决方案：把资料、分析和成果放进一个闭环（约25秒）

规聚的核心思路可以概括为四句话：把资料变成上下文，把工具变成能力，把经验变成资产，把过程变成成果。

右侧的四个模块分别代表资料、知识、技能和成果。它们不是并列放置的四个入口，而是围绕同一个任务相互调用。资料提供基础，知识提供判断依据，技能负责执行，最终沉淀为可交付成果。

## 06｜AI如何赋能交通规划（约25秒）

AI 对交通规划的价值，不只是帮我们写几段文字，而是把规划工作中的不同能力连接起来。

它可以理解当前任务，读取文件和历史资料，检索规范和案例，调用地图、Office、数据分析等工具，再把结果重新组织成规划人员可以审阅和修改的内容。AI 负责提高组织、检索和执行效率，专业判断仍然由规划工程师把关。

## 07｜知识库是规划的核心资产（约30秒）

规划真正有价值的资产，往往不是某一次交付，而是长期积累下来的知识库。现在大量文本、案例和经验仍然静静躺在工程师的电脑里，没有形成组织层面的价值。

规聚首先要做的，就是把这些资料整理起来。我们给文本增加标签，识别标题、主题、项目类型和相互关系，让资料从单独的文件变成可以检索、关联和复用的知识体系。

未来我们不仅能找到某一篇资料，还能进一步发现不同文本之间的关联程度和相似关系。

## 08｜规划素材库：总结形成了14个规划所涉及的通用模板（约25秒）

这一页是新增的模板库查看页。我们从规划素材库中整理出了14个规划所涉及的通用模板，包括年度工作报告、五年规划、条文式规划文本、可研报告、线位论证、选址预审、交通影响评价、汇报材料、物流规划、研究报告、PPT汇报和素材库深挖等。

现场可以点击左侧目录，切换查看不同 Markdown 文件。这样模板不再只是一个文件夹，而是可以直接浏览、理解和调用的内容资产。

## 09｜规范与模板蒸馏（约25秒）

规划文本的格式和规范要求非常清晰，很多内容是可以通用的。我们对大量规划文本进行总结和蒸馏，提炼出章节框架、内容模板、格式要求、标题层级、标点和语气等规则。

这一步的价值，是让 Agent 更清楚“我们需要什么样的成果”，也让不同工程师在写作时有一套可以复用的共同标准。

## 10｜轻量化协同（约25秒）

规聚不是要求大家放弃现有工具，也不是重新建设一套封闭的软件系统。它可以和院里的 AVA 平台，以及 WorkBuddy、Trae 等工具结合，形成一个轻量化的一站式工作台。

在这里可以写报告、审阅材料、做数据分析、生成图表、调用地图，甚至继续出图。核心是把已有能力接进规划任务，而不是替换掉所有工具。

## 11｜平台整体形态（约20秒）

从界面上看，规聚由工作区与文件、技能、智能体、知识库、模板库和地图等模块共同组成。

左侧管理项目资料，中间负责阅读、编辑和查看成果，右侧是 Agent 协作区。不同模块不是孤立页面，而是围绕当前项目和当前任务共同工作。

## 12｜实现流程（约25秒）

一个完整任务大致经过六步：提出问题，读取上下文，检索知识，选择工具，调用能力，形成成果。

比如用户提出“请基于当前资料形成一份交通规划报告框架”，系统会先理解当前工作区，再查找相关规范和模板，随后调用文本或数据工具，最后返回一份可以继续编辑的结果。

## 13｜AI Agent协作（约30秒）

Agent 和普通问答最大的区别，是它不仅回答问题，还能执行任务。

它可以知道当前打开了哪些文件，能够引用哪些知识，应该调用哪一种技能，以及每一步执行产生了什么结果。用户看到的是一条可追踪的事件流，而不是一个突然出现、无法解释来源的答案。

这也使得任务可以被中断、检查、继续和恢复。

## 14｜Office文档工作台（约25秒）

规划成果最终大量落在 Word、Excel、PPT 和 Markdown 文件上。因此，规聚把文档查看、编辑和 Agent 协作放在同一工作区里。

工程师可以一边阅读原文，一边让 Agent 做提纲、修改、审查和格式整理；完成后仍然保留人工复核和继续编辑的空间。

## 15｜规范库与模板库（约25秒）

规范库提供结构和方法，模板库提供可以参考和复用的成果样式。两者结合起来，能够把“应该怎么写”和“可以参考什么样的成果”同时交给 Agent。

这一页重点强调的是，模板不是简单的空白文件，而是包含章节组织、表达方式和成果边界的工作方法。

## 16｜知识库与知识图谱（约30秒）

知识库解决的是资料如何管理和检索，知识图谱进一步解决资料之间如何关联。

系统可以从标题、标签、正文、目录关系、反链和相似内容等维度组织知识。点击一个节点，可以看到与它有关的其他资料，再回到原文继续阅读，也可以直接把文档引用给 Agent。

这样，历史项目、规范和经验才真正重新参与到今天的工作中。

## 17｜Skills技能体系（约20秒）

知识告诉 Agent 应该参考什么，Skills 则告诉 Agent 应该怎样完成一类工作。

交通规划中的文档处理、地图分析、数据统计、报告编制和图表生成，都可以沉淀成独立技能。技能被标准化之后，可以重复调用、持续优化，也可以由不同 Agent 组合使用。

## 18｜技能集合工作流（约20秒）

这一页展示多个技能如何组合成一个工作链。用户不需要自己记住每一个工具的调用方式，而是描述目标，系统根据任务选择合适的技能。

例如从 OD 数据清洗，到统计分析，再到热力图和汇报材料生成，可以串成一条连续流程。

## 19｜智能体广场（约20秒）

技能是相对底层的能力，智能体则是面向具体任务的工作伙伴。不同智能体可以分别服务于公文报告、地图分析、文本审查、数据分析和规划研究等场景。

未来可以把院内验证过的工作方法包装成更多专业智能体，降低重复配置的成本。

## 20｜规则与记忆（约20秒）

一个通用 Agent 还需要知道项目应该怎样工作。规聚通过项目规则、动态上下文和长期记忆，把文件命名、坐标规范、数据校验、用户偏好和历史经验纳入任务。

这样，Agent 才能从“通用助手”逐步变成“懂项目的协作伙伴”。

## 21｜GIS地图工作台（约25秒）

交通规划不能只停留在文字中，很多判断必须回到空间上验证。GIS 工作台提供图层管理、属性查看、空间绘制、GeoJSON 导入、分析区设置和专题出图等能力。

地图不仅是展示结果的地方，也可以成为 Agent 参与分析、修改和验证的工作空间。

## 22｜M2与M3分析：已跑通案例（约30秒）

目前已经跑通了几类案例：公交数据处理与可视化、地图专题和热力图生成、跨区域 OD 分析。

这些案例说明，规聚已经能够把数据导入、分析处理、地图表达和成果输出连接起来。它们更重要的价值，是为下一步继续蒸馏优秀经验、沉淀技能和构建专业 Agent 提供真实样本。

## 23｜会话、工作区与命令面板（约20秒）

规划任务通常不会一次完成，因此系统需要保存工作状态。规聚可以记录工作区、当前文件、会话、引用、打开的文档和界面模式。

用户可以中断后继续，也可以在不同项目之间切换，避免上下文混淆。

## 24｜技术架构（约25秒）

技术上可以概括为：前端是工作台，后端是控制面，Agent 是执行层，数据是持续沉淀的基础。

前端负责文档、地图、知识图谱和模板交互；后端负责文件、会话、知识和地图接口；Agent 负责流式事件和工具调用；数据层保存本地工作区、会话、Markdown 索引、GeoJSON 和相关素材。

## 25｜项目价值与下一步（约30秒）

规聚当前最重要的价值，是把规划院已有的资料、知识、技能和成果组织成一个可持续使用的体系。

下一步有四个方向：第一，进一步蒸馏优秀案例经验；第二，坚持做加法，优先做插件和能力接入，而不是重构成一个封闭软件；第三，构建整个规划院的知识体系；第四，面向外部单位和更多行业，拓展聚合 Agent 的商业化应用。

最后总结一句：规划真正的价值在知识库，而规聚要做的，就是让知识被找到、被调用、被执行，并最终回到规划成果中。

## 现场讲解提示

1. 第1页先讲项目定位，点击任务演示按钮后让自动事件流播放一轮。
2. 第2页明确“基本规划工作流程”，为后面所有功能建立主线。
3. 第8页可现场点击2—3个模板，不建议14个全部逐一打开。
4. 视频页只讲视频对应的一个能力点，不要边播边翻页。
5. 第22页重点讲“已经跑通”，第25页重点讲“为什么值得继续建设”。
