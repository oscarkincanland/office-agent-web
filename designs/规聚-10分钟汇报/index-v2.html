是连续的上下文

03

成果重复加工研究、写文档、做图表、做 PPT 反复切换

04 · TEMPLATE DISTILLATION

模板不是内容样式，
而是 Agent 的行为规范

把汇报、研究、规划和地图经验拆成目标、输入、步骤、约束、输出与检查，让 Agent 知道“应该怎样做事”。

目标这次任务要解决什么问题
输入需要哪些文档、图层和数据
步骤先查什么、再分析什么、如何验证
约束不能猜测，资料不足要主动询问
验收来源可追溯，成果可继续编辑

交通规划汇报模板

放大：模板中的“资料不足时主动追问”“引用来源”“输出结构”“检查清单”，会直接影响 Agent 的工作行为。
小突破：把“Prompt 经验”变成工程师可审阅的模板规范。

05 · COLLABORATION

工程师和 Agent，分别负责什么

ENGINEER

工程师负责判断

  • 定义问题与目标
  • 选择方法与模板
  • 处理例外与不确定性
  • 确认结论和最终成果
共同推进
一个工程任务
AGENT

Agent 负责推进

  • 读取上下文与资料
  • 拆解计划并主动追问
  • 调用知识、地图和 Office 工具
  • 持续反馈过程与产物
表达重点：Agent 不是替工程师下结论，而是减少检索、搬运和重复加工。

10 · ENGINEERING DETAILS

工程细节放大镜：规聚的几个小突破

01

模板约束行为

把经验从 Prompt 变成可审阅、可复用、可检查的工作规范。

工程师可以直接检查 Agent 为什么这样做，而不是只看最终答案。
02

地图成为工具状态

Agent 不只看文字，也能读取图层、要素、属性和空间关系。

规划结论可以回到具体道路、枢纽和图层上验证。
03

成果可以回写

知识、地图和 Agent 结论最终回到工程师熟悉的 Office 成果中。

工程师继续批注和修改，Agent 再根据反馈完善。
04

引用可以追溯

文档来源、知识库路径、地图要素和工具调用都有上下文。

这让 Agent 输出更适合进入正式的工程审查流程。
05

任务可以续接

工作区记忆、历史会话和产物追踪，让协作不从零开始。

“接着做”是工程任务真正需要的能力。
06

不确定时先询问

Agent 遇到输入不完整时主动澄清，不用猜测替工程师做决定。

把不确定性显式化，是工程协作的基本习惯。
