# 任务中心与地图交互完整修改意见

## 一、基线与目标

当前基线：`v0.9.10`，提交 `8b596b79`。

本轮目标不是重做整个工作台，而是解决 Agent 工作过程中“状态不透明、Todo 不实时、地图互相污染、地图工具被遮挡”的核心问题。

目标体验：

> 用户可以同时让 Agent 写报告、整理资料和制作地图，并在一个独立的任务中心查看每个任务的进度；当前对话、地图和文档互不干扰，地图操作也不会造成卡顿。

## 二、确认纳入本轮的功能

### 1. 顶部独立任务中心

- 在顶部工具栏放置任务图标，与历史、地图、知识库同级；
- 不再把并行任务列表塞进对话输入区；
- 悬停显示执行中、排队中、已完成、失败数量；
- 点击打开任务列表；
- 点击某个任务查看该任务的 Todo、事件、产物和错误；
- 任务详情不切换当前对话、文档或地图。

### 2. 实时 Todo

- Todo 的唯一可信来源改为服务端任务步骤；
- 不再只依赖最终回复里的 Markdown 勾选项；
- 每个步骤支持：未开始、执行中、已完成、失败、阻塞；
- Agent 每完成一个步骤立即通过事件更新；
- 当前对话只显示简短状态，完整 Todo 放在任务详情中；
- 页面刷新后可以恢复任务状态和已完成步骤。

### 3. 多任务执行

- 独立任务可以并行执行，例如报告编写和地图分析同时运行；
- 默认最多同时运行 2 个任务，其他任务进入队列；
- 同一文档或同一正式地图图层发生写入冲突时自动排队；
- 每个任务绑定独立的 `runId`、`threadId`、工作区和产物；
- 任务之间不能共用 Todo、事件流和临时地图结果。

### 4. Agent 忙碌时的输入策略

默认采用排队模式：

- 排队：当前任务完成后执行；
- 注入上下文：加入当前任务的后续上下文，不立即打断；
- 中断执行：明确取消当前步骤后执行新指令；
- 中断前保留已经完成的步骤、事件和产物；
- 普通输入不能静默覆盖正在执行的任务。

### 5. 地图状态隔离

- 浙江道路、行政区和底图作为共享只读基础图层；
- 热力图、OD、等时圈、可达性等结果默认属于当前任务临时图层；
- 临时图层按 `workspaceId + threadId + runId` 隔离；
- 只有用户明确执行“保存到项目图层”后才进入正式图层树；
- 新对话使用相同基础图层，但不继承其他对话的临时分析结果；
- 任务中心点击地图任务时，只显示该任务的图层。

### 6. 地图结果自动刷新

- Agent 导入 GeoJSON、生成 OD 或保存分析结果后，服务端发送 `file_changed` 和 `map_action` 事件；
- 前端收到事件后刷新图层树和当前任务图层；
- 普通地图移动不触发 `style.json` 重载和全量图层重绘；
- “刷新地图界面”和“刷新图层”保留为两个明确操作；
- 失败时显示具体原因，不停留在“地图加载中”。

### 7. Agent 识别当前地图位置

- 地图拖动和缩放时只更新本地状态；
- 停止操作约 600–800ms 后记录中心点、缩放级别和可视范围；
- 不在地图移动过程中调用 Agent；
- 下一次发送指令时自动附加最新地图视图；
- 提供“注入当前视图”按钮，允许用户立即加入上下文；
- 对重复坐标做去重，避免高频更新导致卡顿。

### 8. 地图工具栏与 Agent 面板分离

- 可达性、导出、图层刷新和地图分析按钮固定在地图内容区；
- Agent 面板使用右侧独立布局，占用空间而不是覆盖地图工具；
- Agent 面板展开时地图自适应缩小，收起时恢复；
- 小屏幕下地图工具收纳到“地图工具”菜单；
- 导出和可达性任务的进度显示在任务中心，但操作入口仍留在地图工具区；
- 所有按钮需要保留可见、可点击、可定位的状态。

## 三、推荐技术结构

### 服务端

新增统一任务状态层，任务事件至少包括：

```text
run_started
step_started
tool_started
tool_finished
file_changed
map_action
step_finished
run_finished
run_failed
run_cancelled
```

每个事件带有 `runId`、递增序号、时间和任务作用域。服务端负责保存当前步骤状态，前端只负责展示，不再自行猜测任务是否完成。

### 前端

将当前单一 `runState` 改为任务集合：

- `TaskCenterStore`：管理所有任务摘要；
- `TaskDetailStore`：按需加载某个任务的完整步骤和事件；
- `ChatPanel`：只绑定当前对话和当前任务；
- `MapPanel`：只绑定当前地图视图和任务图层；
- `TaskCenterPopover`：顶部任务图标、统计和任务列表；
- `TaskDetailPanel`：Todo、事件、产物和错误详情。

事件按 `runId` 路由，重复事件按 `eventId` 或序号去重。断线重连后通过任务 ID 补齐缺失事件。

## 四、分阶段实施

### 第一阶段：任务数据和实时事件

- 统一服务端任务与步骤状态；
- 为工具事件补充 `runId` 和步骤序号；
- 将 Todo 更新从最终 Markdown 解析迁移到服务端事件；
- 验证刷新页面后状态可恢复。

### 第二阶段：顶部任务中心

- 增加顶部任务图标和数量徽标；
- 增加任务列表、任务详情和事件时间线；
- 对话栏只保留当前任务摘要；
- 验证两个任务可以分别查看。

### 第三阶段：队列、注入和中断

- 实现默认排队；
- 增加上下文注入；
- 增加明确中断、取消和重试；
- 验证中断不会丢失已完成步骤。

### 第四阶段：地图隔离和地图事件

- 给地图结果增加任务作用域；
- 修复导入、编辑、分析后的图层刷新事件；
- 接入当前地图视图上下文；
- 分离地图工具栏和 Agent 面板；
- 验证多轮对话不会污染图层。

### 第五阶段：验证与发布

- 执行 `npm run verify`；
- 测试并行报告、地图、导出和可达性任务；
- 测试浏览器刷新、断线、失败和取消；
- 更新 `变更日志.md`；
- 版本从 `v0.9.10` 升级为 `v0.9.11`，后续按 `v0.9.x` 管理。

## 五、明确不纳入本轮的内容

以下内容可以单独立项，避免和任务中心、地图状态重构相互牵连：

- Word 完整分页和原版版式渲染；
- 超大 PPT 的高保真渲染与替代渲染引擎；
- Pi Agent 模型扫描和本地模型列表校准；
- 历史会话标题自动识别与空会话清理；
- 全局记忆自动沉淀和用户偏好审批流程。

## 六、验收标准

1. 顶部任务图标不占用对话输入区。
2. 两个任务可以同时执行，并分别显示状态和 Todo。
3. Todo 在步骤完成后实时打勾，不需要等整轮任务结束。
4. 新指令默认排队，并可选择注入或中断。
5. 地图移动不触发模型请求和全量重绘。
6. Agent 能在下一次指令中获得当前地图视图。
7. 地图生成结果自动进入当前任务图层并刷新图层树。
8. 新对话不会显示其他对话的临时图层。
9. Agent 面板展开时，可达性、导出和刷新入口仍可用。
10. 任务失败、断线、刷新页面后，状态和错误信息可恢复。
