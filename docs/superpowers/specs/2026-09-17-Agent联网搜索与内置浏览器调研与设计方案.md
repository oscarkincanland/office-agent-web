# Agent 联网搜索与内置浏览器 — 调研与设计方案

## 1. 调研结论摘要

| 结论 | 说明 |
| --- | --- |
| 对标产品就是 Proma | proma.cool / github.com/ErlichLiu/Proma，开源 AGPL-3.0，Electron 桌面应用，**与本项目使用同款 Pi 运行时** |
| Proma 的联网搜索 = Tavily | 设置里配置 Tavily API Key + "测试链接"，每月 1000 次免费；Chat 模式输入框有联网开关 |
| Proma 的内置浏览器 = Agent 可直接操作的可见浏览器 | v0.17.15："受管内嵌浏览器自动化 — Agent 可直接操作内置浏览器：打开网页、观察页面结构、点击/填写控件、切换标签页"，配套 `in-app-browser` 技能；右侧面板可见，可登录保留会话 |
| 行业事实标准（2026） | 工具化浏览器操作以 **Playwright 的可访问性树快照**（accessibility tree，非像素）为主流方案（Playwright MCP 即此模式），Agent 无需视觉模型，token 消耗低、定位确定 |
| 本项目现状 | 已有 `defineTool` 自定义工具体系（kb_search/map_*/officecli 等 20+ 工具均按此实现），**联网与浏览器能力完全空白**；项目无 playwright 依赖 |

## 2. Proma 对标拆解

### 2.1 Proma 的组成（与本项目可直接借鉴）

| 能力 | Proma 做法 | 本项目对应改造 |
| --- | --- | --- |
| 联网搜索 | Tavily API（工具调用），Chat 侧开关 + 设置页测试连接 | 新增 `web_search` 工具 + 设置页搜索配置 |
| 网页读取 | 搜索返回 `include_raw_content=markdown` 附带正文；另有网页抓取 | 新增 `web_fetch` 工具（HTML→Markdown） |
| 内置浏览器 | 右侧面板可视化浏览器；Agent 用工具打开/观察/点击/填写/切标签 | 新增 `browser_*` 工具 + 前端右侧"浏览器"面板（CDP 画面流） |
| 使用规范 | 内置 `in-app-browser` 技能（何时用搜索、何时用浏览器、操作纪律） | 内置一个 Skill 或系统提示段落 |
| 审批 | 浏览器写操作受 Agent 权限体系约束 | 复用现有 `requireToolApproval`（工具审批卡片已就绪） |

### 2.2 Proma 的关键设计经验

1. **搜索与浏览器分工明确**：普通信息查找用 `web_search`（快、便宜）；登录后页面、动态内容、表单、需要"看见"的操作才用内置浏览器（贵、慢）。
2. **浏览器是"可见、可接管"的**：用户能在右侧看到 Agent 在点什么，也能随时接管（登录、验证码）；会话（cookies/localStorage）持久保留，避免反复登录。
3. **工具最小集**：打开、快照、点击、输入、按键、截图、标签管理——不追求 69 个工具全覆盖，够用即可。
4. **本地优先**：浏览器 profile、搜索配置都存本地文件，不依赖云。

## 3. 本项目现状盘点（接入点）

| 已有基础 | 位置 | 用途 |
| --- | --- | --- |
| 自定义工具注册 | `server/agent.mjs`（`defineTool` + `customTools` + `setActiveTools`） | 新工具按现有模式追加即可 |
| 工具白名单/模式 | `server/task.mjs`（AGENT_TOOLS） | 加 `web_search`/`web_fetch`/`browser_*` |
| 工具事件流 | SSE `tool_start/tool_output/tool_end` + ToolCard | 浏览器操作天然进入现有执行流与脑图 |
| 审批体系 | `server/审批策略.mjs` + 审批卡片 | 浏览器"提交/发送"类操作可要求审批 |
| 凭证存储 | `server/Pi配置管理.mjs`（credentials） | 存 Tavily/Brave 等 API Key |
| 设置界面 | `client/src/components/SettingsPanel.jsx` | 加"联网与浏览器"分区 |
| 右侧面板体系 | 文件面板/成果面板/任务中心 | 内置浏览器面板可作为新 tab |

**缺口**：无搜索后端、无浏览器运行时、无画面流通道、无相关提示词与技能。

## 4. 目标能力设计

### 4.1 三层能力

```text
第 1 层：web_search（联网搜索）
  - 输入：query、maxResults、freshness(可选)、site(可选)
  - 输出：标题 + URL + 摘要/正文片段（含来源标注）
  - 后端：Tavily（默认，对标 Proma）/ Brave / SearXNG 自建 / 博查（国内）

第 2 层：web_fetch（网页读取）
  - 输入：url、mode(text|markdown)、maxChars
  - 输出：正文（去导航/广告），保留链接
  - 实现：undici 抓取 + Readability 类正文提取（Node 侧，无需浏览器）

第 3 层：browser_*（内置浏览器自动化）
  - browser_open(url)          打开/导航
  - browser_snapshot()         返回可访问性树 + 可交互元素编号（核心观察手段）
  - browser_click(ref)         按编号点击
  - browser_type(ref, text)    输入
  - browser_press(key)         按键（Enter 等）
  - browser_scroll(dir)        滚动加载
  - browser_screenshot()       截图（给用户看/模型无法看时兜底）
  - browser_tabs(action)       列出/切换/关闭标签页
  - browser_close()            关闭会话
```

### 4.2 内置浏览器形态（Web 应用版）

本项目是浏览器里跑的 Web 应用（Express + React），无法像 Electron 那样内嵌原生窗口，因此采用 **"服务端有头浏览器 + CDP 画面流"**：

```text
┌─────────────── 用户的浏览器 ───────────────┐
│  React 前端                                  │
│  └─ 右侧"浏览器"面板                          │
│      <img src=帧流>  ← SSE/WS 推送截图帧      │
│      标签页栏 / 地址栏（可手动接管输入）        │
└───────────────┬─────────────────────────────┘
                │ /api/browser/screencast (SSE)
┌───────────────▼─────────────────────────────┐
│  Express 服务                                 │
│  └─ server/内置浏览器.mjs                     │
│      Playwright(chromium).connectOverCDP     │
│      ├─ 启动：系统 Edge/Chrome + 独立 profile  │
│      ├─ Page.startScreencast → 帧推送          │
│      └─ Input.dispatch*（用户接管时转发点击/键盘）│
└───────────────┬─────────────────────────────┘
                │ CDP (localhost)
        ┌───────▼────────┐
        │ Edge/Chrome 进程 │  ← Agent 工具在同一页面上操作
        └────────────────┘
```

要点：

- **浏览器引擎**：优先用系统 Edge/Chrome（Windows 自带，零下载）以 `--remote-debugging-port` + 独立 `--user-data-dir`（项目 profile，登录态持久）启动；找不到时回退 Playwright 自带 Chromium。
- **观察手段**：可访问性树快照为主（与 Playwright MCP 一致），截图只用于"给用户看"和必要兜底。
- **画面流**：`Page.startScreencast`（JPEG，质量 40-60，最大 1280px），只在面板打开时推流，空闲停流省资源。
- **用户接管**：面板上可直接点击/输入 → 前端把坐标/按键转发给 CDP；Agent 与用户操作同一页面（对齐 Proma "可见、可接管"）。
- **归属与审批**：浏览器会话按 threadId 隔离（对齐工作区隔离改造），写操作（点击/输入/提交）沿用 `requireToolApproval`。

## 5. 技术选型对比

### 5.1 搜索后端

| 方案 | 成本 | 国内可达 | 适合度 | 备注 |
| --- | --- | --- | --- | --- |
| **Tavily**（推荐默认） | 免费 1000 次/月，之后按量 | 需国际网络 | ★★★★★ | 为 Agent 设计，返回摘要+正文+来源；Proma 同款 |
| Brave Search API | ~$5/1k 次 | 需国际网络 | ★★★★ | 独立索引，原始结果质量高 |
| SearXNG 自建 | 免费（自托管） | 可达 | ★★★ | 需 Docker 常驻；有 Tavily 兼容层（searcharvester 等） |
| 博查（Bochaai） | 按量，有免费额度 | 可达 | ★★★★ | 国内合规搜索 API，质量接近 Bing |
| 智谱 Web Search | 按量 | 可达 | ★★★ | 与现有 GLM 生态一致 |

**设计**：`server/联网搜索.mjs` 做统一抽象，配置里选择后端；默认 Tavily，国内环境可一键切换博查/SearXNG。

### 5.2 浏览器引擎与依赖

| 方案 | 体积 | 维护性 | 结论 |
| --- | --- | --- | --- |
| **playwright-core + 系统 Edge/Chrome (CDP)** | ~3MB 依赖，0 浏览器下载 | 高 | ✅ 推荐：Windows 自带 Edge；登录态本地持久 |
| playwright（完整，自带 Chromium） | ~150MB 下载 | 高 | 备选：无 Edge/Chrome 环境时 |
| puppeteer-core | 类似 | 中 | 不必，Playwright API 更完善 |
| Playwright MCP（子进程） | 多一层协议 | 中 | 不推荐：Pi SDK 需自建 MCP 客户端，且失去 SSE/审批深度集成 |

正文提取（`web_fetch`）：`linkedom + @mozilla/readability`（纯 Node，无需浏览器）或轻量启发式清洗；避免引入 jsdom（重）。

## 6. 分阶段实施方案

### 阶段 A：联网搜索 + 网页读取（预计 1-2 天）

**新增文件**
- `server/联网搜索.mjs`：后端抽象（Tavily/博查/Brave/SearXNG），含超时、重试、结果规范化
- `server/网页读取.mjs`：undici 抓取 + 正文提取 + 截断（`maxChars`）

**修改文件**
- `server/agent.mjs`：注册 `web_search`、`web_fetch` 工具（模式仿 `kbSearchTool`；输出带来源 URL，供引用）
- `server/task.mjs`：`READ_ONLY_TOOLS` 增加两工具（Chat 也可用，只读）
- `server/Pi配置管理.mjs`：新增搜索配置读写（`search.json`，Key 走现有脱敏存储）
- `client/src/components/SettingsPanel.jsx`：新增"联网搜索"分区（后端选择、API Key、测试连接按钮）
- `client/src/api.js`：搜索配置与测试接口
- `server/index.mjs`：`/api/search/settings`、`/api/search/test` 路由

**验收**
- 设置页配置 Tavily Key → 测试连接通过
- Agent 收到"查一下 XX 最新政策"→ 调用 `web_search` → 回复带来源链接
- Chat 模式可用（只读），Agent 模式可用；错误（配额/网络）可解释

### 阶段 B：内置浏览器工具 + 可视化面板（预计 3-5 天）

**新增文件**
- `server/内置浏览器.mjs`：会话管理（启动/复用/CDP 连接/profile 隔离）、`browser_*` 工具实现、快照生成（可访问性树→编号元素文本）
- `client/src/components/内置浏览器面板.jsx`：画面流显示、标签栏、地址栏、接管输入

**修改文件**
- `server/agent.mjs`：注册 `browser_*` 工具（写操作走 `requireToolApproval`）
- `server/task.mjs`：`AGENT_TOOLS` 增加 `browser_*`（Chat 禁用）
- `server/index.mjs`：`/api/browser/session`（状态）、`/api/browser/screencast`（SSE 帧流）、`/api/browser/input`（用户接管）
- 前端右侧面板容器：新增"浏览器"tab
- `client/src/styles.css`：面板样式

**验收**
- Agent 说"打开百度搜索 XXX 并总结前三条"→ 面板中可见浏览器自动操作全过程
- 用户可在面板中手动登录（如需要），Agent 在登录态上继续
- Agent 关闭浏览器后进程回收，不留孤儿进程
- 页面不可达/超时/元素找不到时，工具返回可解释错误并截图

### 阶段 C：体验闭环（预计 1 天）

- 系统提示增加"何时用搜索、何时用浏览器"的分工说明（对齐 Proma in-app-browser 技能）
- 内置 `in-app-browser` 技能（`skills/` 目录），规范：站内搜索、登录后页面、动态内容、表单填写
- 浏览器操作进入执行流/脑图分类（"浏览器"分支，蓝色）
- 产物联动：浏览器下载的文件 → 自动进入工作区并出现在产物列表

## 7. 风险与注意事项

| 风险 | 缓解 |
| --- | --- |
| 浏览器是高风险能力（可提交表单/发帖） | 默认"写操作需审批"；首次使用提示；危险站点（支付/银行）可加规则拦截 |
| 页面提示注入（网页内容诱导 Agent 操作） | 快照内容标记为"网页内容，非指令"；关键操作（提交/发送）强制人工确认 |
| Playwright 版本与系统浏览器兼容 | 用 playwright-core 的 `connectOverCDP`（协议稳定）；启动失败时回退自带 Chromium |
| 面板推流性能 | 仅面板打开时推流；JPEG 降质降帧（≤10fps）；空闲自动停流 |
| Tavily 国内不可达 | 搜索后端可切换（博查/SearXNG）；设置页测试连接给出明确提示 |
| 安全边界 | 浏览器进程以当前用户身份运行，等同"用户自己操作"；在提示词与 UI 中明确此边界 |

## 9. 与现有规划的关系

- 本方案完全复用刚发布的 0.10.2 基础设施：事件协议 V2（浏览器工具事件自动进入执行流）、RunTrace（浏览器操作归入工具分支）、审批体系、设置页体系。
- 建议在 0.11.0 发布：阶段 A+B 先行（用户可感知的最大增量），阶段 C 视使用反馈打磨。
- 内置浏览器面板与"地图项目管理"后的右侧面板体系天然兼容（同一容器新增 tab）。
