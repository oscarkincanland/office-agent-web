# 并行任务与实时 Todo 设计

## 1. 目标

将当前“对话栏内解析 Todo、单个 runState、任务完成后才更新”的模式，改为项目级任务中心：

- 每个 Agent 任务都有独立的任务身份、Todo、事件流、产物和错误状态；
- 执行过程中实时更新步骤，而不是等整轮对话结束后一次性完成；
- 顶部工具栏只显示一个任务中心图标和数量提示，不增加对话栏高度；
- 新指令默认排队，用户可选择注入上下文或中断当前任务；
- 点击任务后查看该任务详情，不切换当前文档、地图和对话，也不污染其他任务。

## 2. 范围与非目标

### 本次范围

1. 任务注册与状态管理。
2. 实时 Todo 与 Agent 事件流同步。
3. 顶部任务中心入口和独立详情面板。
4. 多任务的输入排队、上下文注入和中断选项。
5. 任务与地图临时图层、文档产物的关联标识。

### 暂不包含

- 不重写 Agent 的模型调用协议；
- 不把任务中心改造成完整项目管理软件；
- 不默认把临时地图分析结果写入正式项目图层；
- 不删除现有对话历史，旧历史只做兼容展示。

## 3. 用户交互

### 3.1 顶部任务中心

在顶部工具栏与“历史、地图、知识库”等入口同级放置任务图标：

- 无任务时显示普通图标；
- 有执行中任务时显示数量徽标和轻微状态提示；
- 鼠标悬停显示摘要：执行中、排队中、已完成、失败数量；
- 点击打开任务中心浮层或独立侧面板，不挤占对话栏和地图内容区。

### 3.2 任务列表

任务按状态分组：

- 执行中：显示当前步骤、已完成步骤数、最近事件和取消按钮；
- 排队中：显示排队位置、等待原因和取消按钮；
- 已完成：显示产物数量、完成时间和打开入口；
- 失败：显示错误摘要、重试和查看事件按钮。

每个任务卡片至少包含：任务名称、所属工作区、创建时间、当前 Agent、进度、关联地图/文档入口。

### 3.3 任务详情

点击任务卡进入详情视图：

- Todo 列表：未开始、进行中、已完成、阻塞；
- 事件时间线：工具开始、工具完成、文件变更、地图动作、错误；
- 产物列表：文件、地图图层、分析结果；
- 任务输入和最终输出；
- 返回任务列表，不改变当前聊天内容。

### 3.4 新指令处理

Agent 忙碌时发送新指令，默认进入排队。发送前或发送后提供三种操作：

1. 排队：等待当前任务完成后执行；
2. 注入上下文：将新内容加入当前任务的下一次上下文，不立即打断；
3. 中断并执行：取消当前步骤，保存已完成事件后执行新指令。

中断必须明确显示确认状态，不能通过普通输入悄悄覆盖当前任务。

## 4. 数据模型

```js
{
  id: "run_xxx",
  threadId: "thread_xxx",
  workspaceId: "workspace_xxx",
  title: "生成玉环—台州 OD",
  status: "queued|running|completed|failed|cancelled",
  progress: { completed: 2, total: 4 },
  currentStepId: "step_xxx",
  steps: [
    {
      id: "step_xxx",
      title: "读取 OD 数据",
      status: "pending|running|completed|failed|blocked",
      startedAt: null,
      finishedAt: null,
      error: null
    }
  ],
  events: [],
  artifacts: [],
  inputQueue: [],
  mapScope: "task-overlay",
  createdAt: "...",
  updatedAt: "..."
}
```

Todo 的唯一来源从“解析最终 Markdown”调整为服务端任务步骤；Markdown 勾选项仅作为兼容输入，不再覆盖服务端实时状态。

## 5. 事件流与状态流转

### 5.1 服务端

`beginRun` 创建任务后立即发送 `run_started`。每个 Agent 工具和工作步骤都发送：

- `step_started`
- `tool_started`
- `tool_finished`
- `file_changed`
- `map_action`
- `step_finished`
- `run_finished` 或 `run_failed`

服务端在收到事件时同步更新任务持久化状态，断线重连后可通过任务 ID 补齐事件。

### 5.2 前端

前端维护任务集合，而不是单个全局 `runState`：

- SSE 事件按 `runId` 路由到对应任务；
- 任务中心订阅所有任务摘要；
- 当前聊天只订阅当前任务的必要消息；
- 任务详情按需读取完整事件，避免一次渲染全部历史；
- 事件顺序以服务端序号为准，重复事件幂等处理。

### 5.3 状态流转

```text
queued -> running -> completed
                 -> failed
                 -> cancelled
queued -> cancelled
```

任务步骤必须遵守单向状态流转。异常退出时，当前步骤标记为 `failed` 或 `blocked`，不能直接把整条 Todo 列表显示为完成。

## 6. 与地图、文档的关系

- 任务创建时绑定 `workspaceId`、`threadId` 和当前文件；
- 地图分析默认写入当前任务临时图层；
- 任务中心中点击地图产物，只定位到该任务的图层，不覆盖其他会话图层；
- 文档产物显示任务来源、生成时间和文件路径；
- 只有用户明确执行“保存到项目图层”时，临时图层才进入正式图层树。

### 6.1 地图视图上下文

- 地图拖动和缩放只更新前端本地视图状态，不触发模型请求、不重建底图和图层；
- 地图停止交互约 600–800ms 后，记录中心点、缩放级别和可视范围；
- 视图状态按 `workspaceId + threadId + runId` 保存，避免不同对话互相污染；
- 下一次发送指令时，自动附加最新视图上下文；
- 提供“注入当前视图”按钮，允许用户立即把当前地图位置加入对话；
- 连续移动使用防抖和坐标去重，避免高频事件导致界面卡顿。

### 6.2 地图工具与 Agent 工作区分离

可达性、导出、图层刷新、地图分析等按钮属于地图工作区，不应被 Agent 面板覆盖。布局上采用以下边界：

- 地图工具栏固定在地图内容区的顶部或左侧，不放入对话消息流；
- Agent 使用独立的可调整宽度侧栏，采用正常布局占位，不使用覆盖地图工具栏的绝对定位；
- 地图与 Agent 面板通过 `ResizeObserver` 联动尺寸，面板展开时地图缩小可视区域；
- 小屏幕下地图工具收纳到“地图工具”菜单，但仍保持可达性和导出入口可见；
- Agent 生成地图时只通过任务事件更新地图状态，不改变地图工具栏的层级和点击区域；
- 导出、可达性等长耗时操作显示在任务中心中，但操作入口始终留在地图工具区。

## 7. 错误处理与恢复

- SSE 断线：任务中心显示“连接中断”，自动重连并按事件序号补齐；
- Agent 调用失败：保留已完成步骤和错误事件，允许重试当前步骤；
- 浏览器刷新：从 `/api/runs` 恢复任务摘要，从任务详情接口恢复 Todo 和事件；
- 任务重复事件：通过 `eventId` 或服务端序号去重；
- 用户关闭任务中心：只关闭视图，不取消后台任务。

## 8. 验收标准

1. 启动两个独立任务时，顶部图标能显示“2 个执行中”，对话栏不被任务列表撑高。
2. 任一任务完成一个步骤后，任务卡和详情 Todo 在下一次事件到达后立即更新。
3. 点击任务 A 的详情不会切换任务 B 的对话、地图图层或当前文件。
4. Agent 忙碌时输入新指令，默认进入队列，并能明确选择排队、注入或中断。
5. 刷新页面后，执行中的任务、已完成步骤和失败原因仍可恢复。
6. 事件流中出现文件变更或地图动作时，任务详情能显示对应产物和来源。
7. 旧会话没有结构化步骤时，仍能以“历史消息”方式打开，不伪造 Todo 进度。
8. 地图移动不会触发模型请求、底图重载或全量图层重绘。
9. Agent 面板展开、收起和调整宽度时，可达性、导出和图层刷新入口仍可点击。

## 9. 分阶段实施建议

### 第一阶段：任务状态基础

服务端统一 `runId` 事件模型，前端将单个 `runState` 改成任务集合，先保证实时状态和刷新恢复。

### 第二阶段：顶部任务中心

加入顶部任务图标、数量徽标、任务列表和详情面板；保留对话栏中的简短当前状态。

### 第三阶段：输入策略

实现默认排队、上下文注入和明确中断，补充取消、重试和断线恢复。

### 第四阶段：地图与文档联动

将临时图层、文件变更和任务产物绑定，完成多任务之间的隔离和定位。
