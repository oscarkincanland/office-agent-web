## 3. 根因归类

### A. 环境/身份类（**本轮已修复**）
- 沙箱身份（`CodexSandboxOffline`）导致写操作在 create 阶段被 OS 拒绝：`review_copy` 3/3 失败、`officecli` 5 次、临时产物发布 `EPERM` 导致 3 个 Run 直接 failed。→ 今天 14:39 已换成 admin 身份启动并复验通过。
- `grep` 依赖的 ripgrep 在受限身份下找不到且无法下载（7 次，2026-09-10 ~ 09-21）。本机已装 ripgrep 15.1（WinGet）且代码包自带 `rg`，admin 身份的 PATH 里可用；建议在下一个任务里用一次 `grep` 复验，若仍失败则显式指定 rg 路径。

### B. 并发/写锁类（**建议改代码**）
- 33 次「文件正在被其他任务修改：.」，集中在两个时间窗：**09-10 07–08 时（16 次）**、**09-17 09 时（16 次）**。
- 核对时间线：这两个窗口里同一工作区同时存在 2 个以上的 Run（例如 09-17 的 09:14–09:20 一个 93 次工具调用的长任务还在跑，用户在 09:26–09:43 又连发 4 个任务）。
- 结论：不是锁泄漏，而是**同一工作区多 Run 并行**；先起的 Run 持工作区级写锁，后起的 Run 每次写入都被拒并触发重试，白耗调用。
- 建议：同一工作区串行化（新任务在已有活动 Run 时排队/提示），或把工作区级锁缩小到"发布阶段"短锁。

### C. 文件占用类（用户操作侧，可优化提示）
- OfficeCLI 21 次 `The process cannot access the file ... because it is being used by another process`（WPS/Excel/预览窗口占用）。
- 建议：保持现有"关闭 WPS/Word 后重试"提示；在批量编辑前先自动 `officecli close`，并在同一文档连续失败 2 次后暂停询问用户，而不是继续重试。

### D. 模型误用工具（**建议改提示词/工具描述**）
- `Required argument missing for command: 'view'` 4 次、`Unrecognized command or argument 'paragraph'` 2 次、`--limit` 2 次（实测 OfficeCLI 1.0.151 不支持 `--limit`）、`文件路径必须是当前工作区内的相对路径` 2 次、`禁止从系统根目录执行全盘搜索` 8 次、`长期记忆不能通过 Bash 直接修改` 4 次。
- 这些合计约 22 次，都属于"提示词里能写清楚"的浪费：建议在 `officecli` 工具描述里固定合法参数集合（`--json/--find/--compact/--fields/-h`）、强调相对路径、强调搜索必须限定工作区、记忆只能走 `memory_update`。

### E. 供应商/网络类（运维侧）
- `agent_error` 63 次：`Connection error.` 30、请求被中断类 11、`400 status code (no body)` 6、`503 Upstream request failed` 3、`401 invalid api key` 3、token 过期 1。
- 影响：至少 8 个 Run 因此 failed（如 09-20 06:36–07:40 连续 5 个 failed 全部是 Connection error）。
- 建议：模型通道增加失败重试与 provider 切换（项目里已有 `api-resilience` 技能/思路），并在 401 时直接给出"重新登录/更新密钥"的提示。

### F. 数据超限类
- `officecli` 报 `decompression_bomb`：`龙港6至7月刷卡数据.xlsx` 超过 300 万个 XML 元素被拒。
- 建议：对这类大表设置 `OFFICECLI_MAX_DOM_ELEMENTS`（服务环境变量）或改用 `xlsx` 库分片读取，并在工具描述里说明该限制。

## 5. 结论与优先级

1. **P0 身份/权限**：已修复（admin 身份重启 + 工作区探针通过）。
2. **P1 同工作区串行化**：并发写锁冲突是当前"可避免失败"里占比最高的一类（33 次）。
3. **P1 提示词收紧**：OfficeCLI 参数白名单、相对路径、搜索范围、记忆通道（约 22 次/12 天）。
4. **P2 供应商重试**：63 次 agent_error 需要通道级重试/切换。
5. **P2 重复调用抑制与步骤状态分级**：直接降低 token 消耗与噪音。
6. **P3 大文件限制说明**：`decompression_bomb` 需要环境变量或换读取路径。
