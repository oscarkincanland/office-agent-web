# 规聚最后阶段模型调用稳定性与交付报告

日期：2026-09-01  
版本：v0.9.34  
范围：Agent 模型调用、Pi Runtime、Run 状态、启动服务版本、诊断接口；不包含桌面端。

## 一、结论

本次“Agent 不回复”由三个因素叠加造成：

1. 3001 端口上实际运行的是旧版 `0.9.27` 服务，而工作区代码已经是 `0.9.33`，导致当前 Runtime 接口不存在，前后端行为不一致。
2. 切换到当前服务后，`opencode-go/hy3` 的一次真实请求在 Pi 内部重试 3 次，均为 `Request timed out.`。
3. 原代码没有把 Pi 结算消息中的错误继续抛到上层，因而 Run 被错误记录为 `completed`，用户只能看到没有最终文本的对话。

其中第 2 项是触发故障，第 3 项是造成“无回复且看起来没有失败”的确定性代码缺陷，第 1 项是让问题更难观察和复现的运行管理缺陷。

## 二、证据与边界

| 检查项 | 结果 | 判断 |
| --- | --- | --- |
| 3001 服务版本 | 发现旧服务为 `0.9.27`；重启后为当前代码版本 | 存在服务版本漂移 |
| 当前认证 | `opencode-go` 认证配置存在，接口只读取脱敏状态 | 不是已确认的缺少密钥 |
| 模型目录 | `opencode-go/hy3` 在本地目录中存在 | 不是已确认的模型不存在 |
| 真实 Agent Run | Skills/Office 预检通过，Pi 3 次 `Request timed out.` | 发生了模型/传输层间歇性超时 |
| 基础非流式请求 | 当前端点返回 HTTP 200 和 `OK` | 端点并非持续不可用 |
| 基础流式请求 | 当前端点返回 HTTP 200，多块流式响应 | 流式通道具备可用性 |
| 带高推理和工具参数请求 | 当前探测返回 HTTP 200 | 尚无证据证明工具列表是本次唯一根因 |

这些成功探测只能说明检查时端点、密钥和基础请求可用，不能保证上游服务没有瞬时超时，也不能替代生产请求的完整回放。

## 三、本阶段修改

### 1. Agent 失败传播

- 为 Pi 结算错误增加 `PI_SETTLED_ERROR`，保留 `lastSettledError`，在 `session.prompt()` 正常返回但结算消息带错误时主动抛出。
- 保留现有有限重试和错误分类：超时、网络异常、限流可重试；鉴权、权限、模型不存在等错误不可盲目重试。
- Runtime 捕获该错误后进入失败健康状态，Run 层生成 `failed`，事件流和前端均收到 `agent_error`。

### 2. 诊断与版本一致性

- 新增 `GET /api/agent/diagnostics?client=...&thread=...`。
- 诊断内容包括服务版本、当前模型是否在目录、当前模型是否被目录标记可用、认证是否已配置、Runtime/调度器快照和最近失败记录。
- API Key 不返回；失败日志复用已有脱敏信息。
- `启动规聚服务.ps1` 启动前比较端口服务版本与本地 `package.json` 版本，版本不一致时明确报错并要求先关闭旧 Node 服务。

### 3. 回归覆盖

- `npm.cmd run test:final`：结算错误捕获、超时/鉴权分类、Run 失败状态、版本闸门。
- `npm.cmd run test:phase7`：原有并发写入、取消清理、重启恢复、Office 真实样本回归，并新增诊断接口检查。

## 四、使用方式

启动后可用浏览器或接口检查：

```text
http://127.0.0.1:3001/api/agent/diagnostics?client=你的客户端ID&thread=你的会话ID
```

如果启动脚本提示端口已有不同版本服务，应先关闭旧 Node 服务，再重新执行 `npm.cmd start`。不要通过刷新浏览器来规避版本不一致，因为浏览器刷新不会替换已经驻留的后端进程。

## 五、未被本阶段承诺的内容

- 没有修改桌面端。
- 没有把偶发上游超时包装成“模型永久正常”；真实网络仍可能需要重试或切换模型。
- 没有未经用户确认自动推送远程仓库。
- 没有引入自动切换供应商的隐式策略，避免在用户不知情时改变模型、计费或数据边界。
