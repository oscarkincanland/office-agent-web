# Open Plan 桌面端智能体内核与插件体系落地计划

## 1. 执行摘要

Open Plan 已经具备 React/Vite + Express + Pi Agent SDK 的基础，不需要重新开发一套大模型 Agent 内核。本计划将现有 Web 工作台逐步演进为 Windows 优先的桌面端工具：

```text
Open Plan 产品层
├── 桌面壳（第一阶段采用 Electron）
├── Agent Host（本地 Node/Express 服务）
├── Agent Runtime Adapter（Pi 默认，可替换）
├── Agent Profile（通用、Office、知识库、地图、报告、分析）
├── Tool Pack / Plugin Registry（内置工具包与外部插件）
├── 模型与供应商配置中心
├── 权限、审批、会话、运行记录
└── React 工作台界面
```

核心决策：

1. Pi 作为第一版内置 Agent Runtime，不复制 Pi 源码。
2. Open Plan 自己定义 Runtime Adapter、Agent Profile、插件清单和权限策略。
3. OMP 作为子 Agent、插件、模型目录、记忆和工程体验的参考，不直接作为 Open Plan 的底层依赖。
4. 现有 Web 端继续保留，桌面端复用现有 REST/SSE 能力。
5. 先完成单 Agent、稳定会话和配置迁移，再增加多 Agent 与 OMP RPC。

本计划是架构落地计划，不包含本轮代码实施。每个阶段都有独立验收门槛，未通过前不进入下一阶段。

## 2. 当前基线

### 2.1 已有能力

当前项目已经在 [package.json](../../package.json) 中依赖 `@earendil-works/pi-coding-agent`，本地实际安装版本为 `0.83.0`。后端 [server/agent.mjs](../../server/agent.mjs) 已使用：

- `createAgentSession`：创建 Pi 会话。
- `ModelRuntime`：读取和扫描模型目录。
- `DefaultResourceLoader`：加载上下文、技能和 Agent 文件。
- `SessionManager`：管理会话文件。
- `customTools`：接入 Office、知识库、地图、询问和记忆工具。
- Pi 事件订阅：转换为前端可消费的 token、thinking、tool、ask 和 agent_end 事件。

当前 Open Plan 已经有以下领域工具或领域服务：

- OfficeCLI 文档读取和修改。
- 知识库搜索、读取和引用。
- 地图状态读取、样式修改、图层导入和分析。
- 模板库、交通规划素材库和报告工作流。
- TaskEnvelope、运行记录、产物追踪、记忆提议和工作区上下文。

### 2.2 当前配置事实

当前 Pi 配置目录为：

```text
C:\Users\admin\.pi\agent\
├── models.json
├── models-store.json
├── auth.json
└── settings.json
```

当前模型目录已经包含多个供应商和模型。项目代码也已经区分 `getModels()`、`getAvailable()` 和 `/api/models`，后续必须保持这种区分，不能把“目录中存在”“已配置凭据”和“当前可调用”混为一谈。

### 2.3 当前主要约束

- 本地安装版本是 Pi `0.83.0`，公开主线版本已经继续变化，必须锁定依赖并通过适配层隔离升级风险。
- 当前会话、运行记录和工作区路径仍有项目目录耦合，不能直接作为桌面安装版的最终目录方案。
- 当前 Pi 和 Open Plan 都能执行文件、命令和外部工具，权限边界必须由桌面版补齐。
- 当前项目工作区存在大量未提交的地图、汇报和离线交付改动，后续实现必须新开功能分支，不能混入这些现有改动。

## 3. 目标与非目标

### 3.1 目标

- 双击启动一个类似桌面端的 Open Plan。
- 保留现有 Web 版和本地开发模式。
- Pi Agent 能够作为进程内 Runtime 内置到桌面应用。
- 支持通用助手、Office 助手、知识库助手、地图助手、报告助手和数据分析助手。
- 兼容 Pi 的模型、供应商和技能配置思路。
- API Key 不暴露给 React 渲染进程，不默认明文写入应用目录。
- 内置工具具有明确的权限、审批、取消和运行审计能力。
- 未来可以通过 RPC 接入 OMP 或其他 Agent 引擎。
- UI 操作与 Agent 工具保持能力对等，Agent 的写入能实时反映到界面。

### 3.2 非目标

- 第一阶段不重写 Pi 的 Agent loop。
- 第一阶段不直接引入 OMP 的 Bun/Rust 全量运行时。
- 第一阶段不实现通用的任意第三方插件执行平台。
- 第一阶段不重写地图、知识库和 Office 前端。
- 第一阶段不承诺多 Agent 自动协作、自动合并和无人值守执行。
- 第一阶段不将 `models-store.json` 设计成用户手工维护的模型数据库。
- 第一阶段不把 API Key、会话文件和项目数据提交到 Git。

## 4. 架构决策

### 4.1 Runtime 决策

第一版采用 Pi 内嵌模式：

```text
React
  ↓ REST/SSE 或桌面 IPC
Open Plan Agent Host
  ↓ PiRuntimeAdapter
Pi createAgentSession / ModelRuntime / SessionManager
  ↓
Pi Agent Core + Pi AI + Provider API
```

Open Plan 不直接让前端调用 Pi SDK。所有会话、模型、工具、凭据和事件都经过 Agent Host，避免把 Node 文件权限和 API Key 暴露到渲染进程。

### 4.2 Runtime Adapter 接口

新增一层稳定接口，Pi 只是第一个实现：

```ts
interface AgentRuntimeAdapter {
  createSession(options): Promise<AgentSessionHandle>;
  prompt(sessionId, message, attachments?): Promise<void>;
  steer(sessionId, message): Promise<void>;
  followUp(sessionId, message): Promise<void>;
  abort(sessionId): Promise<void>;
  setModel(sessionId, modelId): Promise<void>;
  listModels(): Promise<ModelCatalog>;
  refreshModels(): Promise<ModelCatalog>;
  subscribe(sessionId, listener): () => void;
  dispose(sessionId): Promise<void>;
}
```

事件统一为 Open Plan 自己的协议：

```text
session_created
agent_start
turn_start
token
thinking
tool_start
tool_output
tool_end
ask_user
file_changed
agent_error
agent_end
session_disposed
```

Pi 的原始事件只在 `PiRuntimeAdapter` 内转换，前端不依赖 Pi 事件字段。

### 4.3 Agent Profile

Profile 不是新的 Agent 内核，而是同一个 Runtime 的配置：

```ts
interface AgentProfile {
  id: string;
  name: string;
  engine: "pi" | "omp-rpc" | "remote";
  model: string;
  thinkingLevel: string;
  systemPrompt: string;
  toolPacks: string[];
  workspacePolicy: string;
  approvalPolicy: string;
  memoryPolicy: string;
}
```

第一批内置 Profile：

| Profile | 工具范围 | 默认策略 |
|---|---|---|
| 通用助手 | 文件、搜索、基础对话 | 工作区内读写，外部操作审批 |
| Office 助手 | OfficeCLI、文档、模板 | 修改文档前保留运行记录 |
| 知识库助手 | 知识库搜索、读取、引用 | 默认只读，输出引用来源 |
| 地图助手 | 地图读取、样式、图层、分析 | 演示数据与正式数据分离 |
| 报告助手 | 素材库、模板、Office、导出 | 先读取规范，再生成成果 |
| 数据分析助手 | CSV/Excel/OD/图表工具 | 显示数据来源和记录数校验 |

### 4.4 桌面壳决策

第一版优先使用 Electron：

- 现有后端已经是 Node/Express。
- OfficeCLI 主要服务 Windows 文档场景。
- 当前 React 前端可以直接加载。
- 桌面主进程可以管理窗口、文件选择、托盘、凭据和本地服务生命周期。

Tauri 保留为后续优化方向。只有当 Electron 包体积、资源占用或系统集成成为明确问题时再评估迁移。

### 4.5 OMP 决策

OMP 只进入两个位置：

1. 作为设计参考：插件、Profile、子 Agent、记忆、模型注册表和审批机制。
2. 作为未来可选 Runtime：独立进程启动 OMP，通过 RPC 接入，不与 Pi 共享内部对象。

是否真正支持 OMP Runtime，必须在 Pi 版桌面 MVP 稳定后通过单独 POC 决定。

## 5. 数据和目录设计

### 5.1 桌面应用数据目录

应用安装目录只放程序和静态资源，运行数据统一放用户数据目录：

```text
%APPDATA%\OpenPlan\
├── config\
│   ├── profiles.json
│   ├── models.json
│   └── plugins.json
├── sessions\
├── runs\
├── plugins\
├── cache\
└── logs\
```

具体目录名可以在实现时按现有命名规范调整，但必须满足以下原则：

- 安装目录只读也不影响运行。
- 会话、运行记录和缓存可清理、可迁移、可备份。
- API Key 不直接放在 React 可访问的 JSON 文件中。
- 每个工作区、线程和运行任务可以追溯。

### 5.2 工作区目录

工作区仍然由用户选择，可以是：

- 当前项目的 `office-workspace`。
- 独立的交通规划项目目录。
- 外接硬盘或网络同步目录。

桌面端增加工作区管理器，记录：

```text
workspaceId
displayName
absolutePath
lastOpenedAt
defaultProfile
```

Agent 的路径工具必须继续限制在当前工作区或经过授权的外部文件根目录内。

### 5.3 Pi 配置兼容层

兼容策略如下：

| Pi 文件 | 桌面端处理 |
|---|---|
| `models.json` | 作为自定义供应商/模型的导入来源，必要时通过适配器写回 |
| `models-store.json` | 作为扫描缓存和目录来源，不提供普通用户手工编辑入口 |
| `auth.json` | 只做一次性导入和兼容读取，桌面端新写入使用系统安全存储 |
| `settings.json` | 导入默认模型和思考级别，映射到 Open Plan Profile |
| `.pi/skills` | 作为技能导入来源，加载前展示权限和来源 |
| OMP `models.yml` | 后续做只读导入适配，不直接混写 Pi JSON |

## 6. 分阶段实施计划

### 阶段 0：基线冻结与接口设计

工作量级：1—2 个工作日。

#### 任务

- 新建功能分支，例如 `feature/desktop-agent-runtime`。
- 记录当前分支、工作区和未提交文件，不清理用户现有改动。
- 固定当前 Pi 版本，第一阶段不同时做 Pi 升级。
- 对现有 `AgentManager`、模型目录、会话、SSE 事件做调用链梳理。
- 定义 `AgentRuntimeAdapter`、`AgentProfile`、`ToolPack`、`ModelCatalog`、`PermissionPolicy` 类型。
- 把现有 Pi 事件转换为 Open Plan 事件协议。
- 明确 `/api/agent/*`、`/api/models`、会话恢复和 SSE 的兼容要求。

#### 交付物

- Runtime 接口设计文档。
- Agent Profile 初始清单。
- 事件协议清单。
- 目录迁移设计。
- Pi 版本锁定记录。

#### 验收

- 现有 Web 端行为没有变化。
- 可以画出一次完整调用链：用户输入 → API → AgentManager → Pi → 工具 → 工作区 → SSE → UI。
- 所有新接口都有明确的错误和取消语义。

### 阶段 1：Pi Runtime Adapter

工作量级：3—5 个工作日。

#### 任务

- 将现有 `createAgentSession`、`ModelRuntime`、`SessionManager` 调用集中到 Pi Adapter。
- 保留现有自定义工具，不在本阶段重写 Office、知识库和地图逻辑。
- 统一 `prompt`、`steer`、`followUp`、`abort`、`setModel` 和 `dispose`。
- 修复和固化 Pi `isStreaming` 与外部 `busy` 不一致时的重试策略。
- 将工具调用输入、输出、错误和耗时统一写入运行记录。
- 增加 Adapter 单元测试和一次真实 Pi 会话冒烟测试。

#### 目标文件范围

- `server/agent.mjs`：保留兼容入口，减少直接暴露 Pi 对象。
- 新增 Runtime Adapter 模块。
- 新增 Agent 事件归一化模块。
- 新增 Adapter 测试模块。

#### 验收

- Web 端仍可以流式对话。
- 可以中止正在运行的任务。
- 可以向正在运行的任务发送 steer/follow-up。
- 工具调用失败会回到 Agent，而不是只在服务器日志中静默失败。
- 会话恢复后仍能读取历史和继续对话。
- `npm run verify` 通过。

### 阶段 2：桌面壳与本地 Agent Host

工作量级：3—5 个工作日。

#### 任务

- 增加 Electron 主进程。
- 主进程启动本地 Agent Host 子进程。
- 启动后等待 `/api/status` 健康检查，再加载 React 界面。
- 处理服务启动失败、端口占用、服务退出和窗口关闭。
- 保留 Web 开发模式：`npm start` 仍可以独立运行。
- 桌面端默认只监听回环地址。
- 桌面端 API 使用一次性本地 Token 或 IPC 认证，不允许无意暴露到局域网。
- 增加文件选择、打开工作区、在资源管理器中定位文件等桌面能力。

#### 桌面启动流程

```text
Electron 启动
  → 创建用户数据目录
  → 启动 Agent Host
  → 等待 /api/status
  → 校验工作区和 Pi 配置
  → 加载 React
  → 建立 SSE
```

#### 验收

- Windows 双击后能启动并显示主界面。
- Agent Host 未启动时界面显示可理解的错误和重试入口。
- 关闭桌面窗口后 Node 子进程和文件监听器都能退出。
- 安装目录不可写时仍能正常运行。
- 无 Token 时不会把服务监听到非回环地址。
- Web 版和桌面版可以同时启动且互不污染会话。

### 阶段 3：模型、供应商与凭据中心

工作量级：2—4 个工作日。

#### 任务

- 设计 Open Plan 内部模型结构：`provider`、`modelId`、`displayName`、`capabilities`、`source`、`availability`。
- 读取 Pi 内置目录、`models.json`、`models-store.json` 和凭据状态。
- 将模型状态拆成：
  - 目录中已配置。
  - 已有有效凭据。
  - 供应商可访问。
  - 当前模型可用。
  - 视觉、工具调用和推理能力。
- 设置页支持新增、删除和测试供应商。
- API Key 通过 Windows Credential Manager、Electron safeStorage 或 Tauri keyring 保存。
- 保留从 `C:\Users\admin\.pi\agent` 导入的入口。
- 对导入的配置进行备份，写入前保留未知字段，避免配置丢失。
- 模型刷新默认不主动联网，用户明确点击后才刷新。
- 所有供应商错误显示脱敏信息，不记录 API Key。

#### 验收

- 导入当前 Pi 配置后，默认模型和可用模型与现有 Web 端一致。
- UI 能区分配置模型数和当前可用模型数。
- 修改 API Key 后无需重启即可让新会话使用新凭据。
- 删除凭据后模型会正确变为不可用，而不是仍显示可调用。
- 网络失败、凭据错误、模型不存在三类错误可以分别识别。
- 日志和运行记录中不出现完整密钥。

### 阶段 4：Agent Profile、Tool Pack 与插件体系

工作量级：4—7 个工作日。

#### 任务

- 建立 `AgentProfileRegistry`。
- 将 Office、知识库、地图、报告和交通分析工具按 Tool Pack 注册。
- Profile 只声明工具包和策略，不复制工具实现。
- Profile 切换时建立新会话或显式更新系统提示词，禁止静默混用上下文。
- 为每个工具增加：输入 schema、风险等级、允许路径、是否需要审批、是否支持取消。
- 兼容 Pi Skills 的导入，但显示来源、版本和权限。
- 增加 MCP Server 注册清单，外部 MCP 默认以独立进程运行。
- 暂不允许普通用户直接加载任意进程内 TypeScript 插件。
- 对可信内置插件提供版本、依赖和能力说明。

#### 第一批内置 Tool Pack

| Tool Pack | 包含能力 | 高风险操作 |
|---|---|---|
| `office` | OfficeCLI、文档读取、批注、生成 | 覆盖原文、批量修改 |
| `knowledge` | 知识库扫描、搜索、全文读取 | 外部根目录访问 |
| `map` | 地图项目读取、样式、图层、分析 | 写入正式图层、重建瓦片 |
| `planning-report` | 规划素材、规范、模板、报告 | 生成和覆盖交付文档 |
| `traffic-analysis` | OD、流量、断面、图表 | 使用不完整或演示数据 |

#### 验收

- Agent Profile 切换后工具集合和系统提示词可审计。
- 所有 UI 可执行的核心动作，Agent 都有对应工具或组合能力。
- 地图演示数据与正式图层继续分离。
- 文档修改、地图正式保存、外部目录访问和进程执行都有审批入口。
- 插件加载失败不会拖垮整个桌面应用。
- 插件版本和权限可以在设置页查看。

### 阶段 5：会话、任务、运行记录与恢复

工作量级：3—5 个工作日。

#### 任务

- 将会话存储从项目安装目录迁移到用户数据目录。
- 会话按工作区和线程隔离。
- 保存 Profile、模型、工作区、输入引用、工具事件和产物清单。
- 支持暂停、取消、继续、恢复和从节点 fork。
- 保留 TaskEnvelope 的目标、引用、工作流、输出格式和约束。
- 运行结束时固定输出：来源、修改文件、产物、假设、未完成项和下一步。
- 让 Agent 生成的文件变化通过共享服务、文件监听或事件总线立即反映到 UI。
- 加入运行失败后的可恢复状态，避免只留下“处理中”状态。
- 运行记录支持回看，不默认进入 Git。

#### 状态生命周期

```text
创建任务
  → 创建运行记录
  → 创建/恢复会话
  → 写入输入和上下文
  → Agent 工具循环
  → 工作区文件变化
  → 产物快照
  → agent_end
  → 完成/部分完成/失败
```

#### 验收

- 关闭桌面应用后重新打开可以恢复未完成会话。
- 取消任务后不会继续执行后续工具调用。
- Agent 已经生成文件但最后一步报错时，产物仍可见。
- 运行记录能反查模型、Profile、工具和文件变化。
- 同一工作区的不同线程不会共享错误的 Agent 上下文。

### 阶段 6：多 Agent 和 OMP RPC 预研

工作量级：5—10 个工作日，作为第二期，不阻塞桌面 MVP。

#### 任务

- 设计 `AgentCoordinator`，使用多个隔离的 Pi 会话完成角色分工。
- 第一批只支持有限角色：规划、执行、审查。
- 子任务使用结构化结果，不通过解析自然语言拼接结果。
- 每个子 Agent 有自己的 Profile、工具集、模型和工作区权限。
- 只允许共享明确的任务资料和结果，不默认共享全部上下文。
- 增加主 Agent 对子 Agent 的取消、超时和重试能力。
- 做 OMP 独立进程 RPC POC，验证启动、模型、工具事件、审批和会话恢复。
- 对比 Pi 内置多会话与 OMP RPC 的安装体积、启动耗时、事件兼容性和维护成本。

#### OMP 采用条件

只有同时满足以下条件才进入正式集成：

- OMP RPC 能稳定运行于目标 Windows 环境。
- OMP 与 Open Plan 的凭据隔离方案明确。
- 工具事件和审批协议不需要大规模重写。
- OMP 的 Bun/Rust 运行时不会显著增加安装和更新复杂度。
- 有明确的 Open Plan 场景需要 OMP 的 LSP、DAP、子 Agent或原生工具。

否则继续使用 Pi Runtime + Open Plan 自有协调层。

### 阶段 7：打包、升级、发布和回滚

工作量级：3—5 个工作日。

#### 任务

- 生成 Windows 安装包和便携版。
- 检查 Node/Electron、Pi SDK、OfficeCLI、地图资源和模板资源的分发许可。
- 提供首次启动诊断：Node、OfficeCLI、Pi 配置、凭据、网络和工作区权限。
- 版本升级前备份 Profile、模型配置、会话和运行记录。
- Pi SDK 升级采用单独变更，不与桌面壳大改合并。
- 失败升级可回滚到上一版本。
- 建立离线安装包测试和 U 盘拷贝测试。
- 文档说明模型、供应商、工作区、插件和权限配置方式。

#### 验收

- 新机器安装后可以完成最小启动和本地工作区选择。
- 没有 API Key 时仍能打开应用并进入配置页。
- 无 OfficeCLI 时文档相关能力有明确降级提示。
- 升级不丢失会话、Profile 和模型配置。
- 旧版本运行记录可以读取或有迁移提示。
- 安装包、便携版和开发模式都通过冒烟测试。

## 7. 系统级影响分析

### 7.1 交互链路

#### 用户对话链路

```text
用户输入
→ React Chat
→ /api/agent/prompt 或桌面 IPC
→ Agent Host
→ AgentRuntimeAdapter
→ Pi Session.prompt
→ LLM 返回文本或工具调用
→ Tool Pack 执行
→ 工作区/数据库/外部服务变化
→ Agent 事件归一化
→ SSE/IPC
→ React 更新消息、产物、地图和任务状态
```

#### 模型配置链路

```text
设置页修改供应商
→ ModelConfigService 校验
→ 安全存储更新凭据
→ Pi ModelRuntime 刷新
→ ModelCatalog 重新计算
→ /api/models 返回 configured/available 分项
→ 前端刷新模型选择器
```

#### 插件链路

```text
插件安装或启用
→ Manifest 校验
→ 依赖与权限检查
→ PluginRegistry 注册 Tool Pack
→ Profile 选择工具
→ PermissionService 拦截高风险调用
→ Agent 事件与运行记录留痕
```

### 7.2 错误传播

| 错误位置 | 处理方式 | 用户可见结果 |
|---|---|---|
| 供应商网络错误 | Pi Adapter 归一化并保留原始分类 | 显示重试、切换模型或检查网络 |
| 凭据错误 | 脱敏、标记 provider 不可用 | 引导重新配置 Key |
| 模型不存在 | 配置层校验和降级 | 默认模型不被静默替换 |
| 工具参数错误 | Tool schema 校验后回传 Agent | Agent 可修正参数 |
| 工具执行错误 | 抛出结构化工具错误 | 任务可继续、重试或终止 |
| 用户审批拒绝 | 生成明确的 blocked 结果 | Agent 说明未执行原因 |
| 进程崩溃 | Host 健康检查和重启 | 会话进入可恢复状态 |
| UI 断开 | SSE/IPC 重连和事件回放 | 不丢失已完成运行记录 |

### 7.3 状态风险

- 应用安装目录不可写：通过 AppData 迁移解决。
- 会话恢复使用错误工作区：会话必须保存 `workspaceId` 和绝对路径校验结果。
- 模型目录缓存过期：显示刷新时间和来源，不把缓存当可用性证明。
- Agent 写入文件但 UI 没刷新：统一通过共享服务或文件事件触发更新。
- 任务完成但产物未登记：在 `agent_end` 后执行工作区快照和运行记录收尾。
- 插件加载后权限变化：Profile 启动时重新计算权限，不能只在安装时校验。
- 凭据更新后旧会话继续使用旧 Token：明确旧会话策略，新会话优先使用最新凭据。

## 8. 权限和安全设计

### 8.1 权限级别

建议至少划分：

| 级别 | 能力 |
|---|---|
| L0 | 只读当前工作区 |
| L1 | 写入当前工作区 |
| L2 | 访问用户授权的外部目录 |
| L3 | 执行本地进程或脚本 |
| L4 | 网络请求、供应商配置和插件安装 |

默认 Profile 只开放 L0/L1。L2—L4 必须按工具和操作触发审批。

### 8.2 必须审批的操作

- 覆盖或批量删除文件。
- 写入当前工作区之外的路径。
- 执行 PowerShell、Shell 或外部程序。
- 修改 Pi 模型配置和供应商凭据。
- 安装或启用外部插件。
- 修改正式地图图层或重建大批量瓦片。
- 上传文件或调用外部网络服务。

### 8.3 凭据规则

- React 渲染进程不能读取完整 API Key。
- 日志、SSE 事件和运行记录不能包含完整 API Key。
- 导入 `auth.json` 时只做一次性迁移并提示用户迁移成功。
- 删除供应商时同步处理安全存储中的凭据。
- 调试日志默认关闭请求体和 Authorization 头。

## 10. 版本和分支策略

### 10.1 分支

- 当前地图、汇报和离线包改动保持原样。
- 新建独立功能分支：`feature/desktop-agent-runtime`。
- Runtime Adapter、桌面壳、配置中心、插件体系分开提交。
- 不在同一个提交中同时升级 Pi、改桌面壳和重构工具。

### 10.2 依赖

- 第一阶段固定 Pi `0.83.0`，先完成适配层。
- Pi 升级单独建立兼容性任务，比较 `createAgentSession`、`ModelRuntime`、工具激活、会话和事件字段。
- 依赖版本尽量锁定，升级必须更新变更记录和回归结果。

### 10.3 回滚

- Runtime Adapter 可以切回旧的 `AgentManager` 调用路径。
- 桌面端 Host 启动失败时保留 Web 版启动路径。
- 模型配置写入前备份原文件。
- Profile 和插件配置支持版本号和迁移失败回退。
- 桌面升级失败时保留上一版本和用户数据目录。

- 是否只支持 Windows，还是第一版同时支持 macOS/Linux。

## 15. 总体完成标准

当以下条件全部满足时，才认为 Open Plan 桌面端 Agent 基础架构完成：

- [ ] Web 版和桌面版共用同一套 Agent Runtime Adapter。
- [ ] Pi 会话、模型、工具和事件不直接泄漏到 React 层。
- [ ] 用户可以导入或配置模型和供应商，且凭据安全存储。
- [ ] 至少 5 个 Agent Profile 可以稳定运行。
- [ ] Office、知识库、地图和报告工具可以按 Tool Pack 管理。
- [ ] 高风险操作有权限和审批机制。
- [ ] 会话、运行记录和产物可以恢复和审计。
- [ ] 工作区文件变化可以实时反映到 UI。
- [ ] 桌面端在安装目录不可写时仍能运行。
- [ ] Pi 升级可以通过 Adapter 和回归测试控制风险。
- [ ] OMP 是否接入已经通过独立 POC 得出结论，而不是在主项目中盲目引入。
- [ ] `npm run verify`、桌面冒烟、模型配置、权限和恢复测试全部通过。
