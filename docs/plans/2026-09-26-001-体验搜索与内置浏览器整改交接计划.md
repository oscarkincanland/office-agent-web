# 规聚 v0.11.11：体验、联网搜索与内置浏览器整改交接计划

日期：2026-09-26。性质：只读诊断和实施交接；本轮不修改业务代码、不保存搜索凭据、不启动真实搜索或内置浏览器。以下行号基于当前工作树，实施前用符号名重新定位。工作树已有大量未提交修改（包括 `App.jsx`、`styles.css`、`agent.mjs`、`index.mjs`、`task.mjs`、`内置浏览器.mjs` 等），请先逐文件审阅 diff，不要覆盖、重置或直接清理。

## 1. 核查结论与边界

1. **Web Search 已接入，但当前默认后端不可用。** `server/联网搜索.mjs` 实现 Tavily、SearXNG、Jina、博查；`server/index.mjs:1668-1696` 提供设置和连接测试接口；`server/agent.mjs:1590-1645` 注册 `web_search`/`web_fetch`；`server/task.mjs:14-44` 允许 Chat、Office、Work 使用，Review 有意排除；`client/src/components/SettingsPanel.jsx:1089-1140` 提供配置 UI。当前 `.oaw/search.json` 不存在，本地脱敏读取显示选中 Tavily 且未发现 Tavily Key；运行界面也显示“联网搜索·未配置 / Tavily”。因此不能说“功能没写进去”，只能说“当前选中后端尚未完成配置”。服务进程环境变量与真实外网连通性未做独立探测，不能宣称所有后端均不可用。
2. **状态展示有确定性偏差。** `SettingsPanel.jsx:1090-1093` 的徽标只检查任一 Tavily/博查 Key 或 SearXNG URL，不检查 *当前选中后端*，且漏掉免 Key 的 Jina；因此可能“当前后端不可用却显示已配置”，也可能“Jina 可尝试但显示未配置”。`SettingsPanel.jsx:405-415` 的测试只发送后端名，不会测试尚未保存的新 Key/URL；“测试连接”应说明验证的是已保存配置，或支持安全地测试草稿。已填凭据不等于已连通。
3. **内置浏览器不是系统浏览器嵌入，而是独立 Chromium/Edge + CDP + SSE 截图流。** 入口在 `App.jsx:1386,1459-1476`，后端在 `server/内置浏览器.mjs`，流接口在 `server/index.mjs:1698-1796`。运行界面可见浏览器空状态、地址输入和快速打开入口；本轮没有启动网页会话，因此以下浏览器性能判断是代码风险，不是现场压力测试结果。
4. **前一轮 UI 审查的六组问题应作为同一批整改范围。** 暗色气泡不可读、窄屏三栏挤压、文档预览裁切、产物状态误导、地图与智能体入口不顺畅、任务中心窄屏与原始事件暴露。前轮在 934px/480px 视口及现有数据上复现；截图存于 `.oaw/audits/2026-09-26-ux/`（被 git 忽略，不应作为唯一交接证据）。

## 3. 搜索工作包实施细化

### 3.1 配置与状态

- 后端统一返回 `selectedBackend`、`configured`、`connectivity`（`untested/ok/failed`）和可解释原因，前端只消费这一份状态，避免复制 `backendReady` 规则。`jina` 可以是“免 Key 可尝试”，**不是**未经测试的“连接成功”。
- `searchSettingsSave` 当前发送空 Key 表示保持旧值；补一个显式“清除凭据”动作，防止无法撤销配置。`server/联网搜索.mjs:78-116` 目前把进程环境变量合并后在保存时一并写入 JSON；避免环境凭据意外落盘，并为密钥文件设置最小权限、禁止日志/测试输出泄露。不要在计划实施中提交 `.oaw/search.json`。
- 搜索设置页的“测试连接”要么先保存草稿再测且清楚提示，要么以只存在于该次请求的草稿测试，测试后不持久化；同时防并发/过时响应覆盖新状态。`/api/search/test` 返回错误类别、耗时和少量去敏摘要即可。
- 基础后端选择可由用户决定：Tavily/博查需本人提供 Key，SearXNG 需实例地址，Jina 可不填 Key 尝试但可能受网络/限流影响。本轮不代替用户选择、购买或输入密钥。

### 3.2 检索与阅读链路

- 当前 Chat/Office/Work 的 `web_search` 在工具白名单中，Review 排除是合理策略；工具注册不代表模型一定会主动调用。为“查最新”设计明确触发与状态事件，但保留模型判断和用户关闭联网的能力。搜索失败应分类为未配置、认证、配额、网络、超时、无结果；只对可恢复错误有限次数重试。
- `web_fetch` 直接读取任意 http(s) URL 且默认随重定向；若正文短/失败则拼到 `r.jina.ai`，有 SSRF 与内网 URL 外传风险。需检查 DNS 解析后的目标和每次重定向；对本地服务阅读另做受控能力，不让通用网页工具访问。把读取上限放在流消费处；Jina 回退需显式 opt-in 或限公开网址；不要把凭据 URL 传给第三方。
- 搜索结果和网页都是不可信资料；回答的“来源”必须指向实际打开/检索的 URL，错误时不得编造引用。`server/agent.mjs:901` 已有提示词，可保留并配合结构化事件和测试，而非只靠提示词。

## 4. 内置浏览器工作包实施细化

### 4.1 安全与生命周期

- `server/内置浏览器.mjs:630-645` 当前无条件 `--no-sandbox`、`--in-process-gpu`，本机浏览开放网页时风险较高。先在 macOS/Windows 分别验证默认沙箱启动；仅在受控开发环境以显式开关降级，不能默认关闭。Chrome 官方文档也把 macOS `--no-sandbox` 视为不安全的临时排障手段（见文末）。
- CDP 重连 `tryReuse()` 目前只读 `.oaw-devtools-port` 后探测端口，应该验证对应 profile/进程标识；端口复用或外部本地进程不能被接入。CDP 只绑定 loopback，profile 目录按会话隔离并限制权限；会话退出、服务监督重启、进程崩溃分别测试，避免锁清理误杀其他浏览器。
- `browserReset` 会关闭当前会话并杀该 profile 进程。`内置浏览器面板.jsx:123-153` 在**任何** `browserOpen` 错误后自动重置，需只针对明确的启动/锁异常；一般 DNS/证书/HTTP/导航超时不应销毁已登录会话。用户可手动“修复浏览器”并看到“将关闭现有标签”的提示。

### 4.2 Agent 与用户协作

- 当前“接管操作”仅改 React `takeover`，tooltip 甚至说明 Agent 仍可继续；服务端 `lastUserInputAt` 只用于近 3 分钟阻止 Agent 关闭浏览器，不阻止同时点击/输入/切标签。建议后端持有 `{owner, leaseExpiresAt, reason}`，所有 Agent 写操作统一检查；用户接管时 Agent 仅可观察或等待，UI 显示“等待你交还”；交还后可恢复。超时/断线需避免永久锁定。
- 用户触发的 `resize`、观察等不应被算作用户“接管输入”；当前 `browserUserInput:1045` 在识别 action 前刷新 `lastUserInputAt`，ResizeObserver 也会发该接口，应拆分“布局同步”和“人为交互”。Agent 导航/切标签与用户操作之间应有可预测的冲突解决和审计事件。

### 4.3 性能与可用性

- 目前 CDP `Page.startScreencast` 质量 90、最大 2400×1600、每帧采样 1；后端仅每 90ms 广播最新帧，但 CDP 仍编码每帧且 SSE `res.write` 没有检查背压，前端每帧 `setFrame(base64)` 导致 React 重渲染。建议根据实际面板像素尺寸和活跃/隐藏状态动态设置较低质量/采样，限制最大帧字节、单订阅者待发队列；遇到 `res.write()===false` 丢旧帧、保最新帧；空闲/隐藏时 `Page.stopScreencast`，恢复时发送最新帧。先测流量和 CPU，再定默认预算。CDP 官方定义了 `everyNthFrame`、`quality`、`maxFramesInFlight` 和 `stopScreencast`，可依契约实现。
- 搜索地址栏 `normalizeNavUrl()` 已支持关键字转 Bing；保留此能力但区分“网页地址”和“搜索词”，展示目标站点和联网状态。为标签切换/输入队列增加超时与取消，断线重连后校正当前 tab/viewport/frame；浏览器标签采用真实 button/tab 键盘语义，焦点可见。
- 观察界面曾有 934px 三栏挤压，`App.jsx:1459-1476` 的浏览器侧栏又有最小 340px；在窄屏采用叠层或单面板切换，不把对话压成不可读窄列。

## 5. 统一验收与回归矩阵

1. **配置矩阵**：Tavily 无 Key、Tavily 有 Key 但网络断开、博查 Key 错误、SearXNG URL 不可达、Jina 无 Key、非当前后端有 Key、草稿未保存、清除 Key。分别核对徽标、测试提示、`web_search` 错误和 Agent 话术；不在测试记录中输出 Key。
2. **网页安全矩阵**：`web_fetch` 输入 `file:`、`javascript:`、`localhost`、`127.0.0.1`、私有 IP、DNS 解析到私网、公开站点重定向到私网、超过下载上限、短正文、Jina 回退。拒绝场景无外部请求/外传；公开正常页面有来源和截断标记。
3. **浏览器协作矩阵**：首次启动、复用、浏览器崩溃、服务重启、无效 URL、导航超时、标签切换、用户接管时 Agent 点击/关闭、交还、接管者断线；浏览器失败不得无提示丢失标签/登录态。`--no-sandbox` 只允许受控开发开关。
4. **性能矩阵**：1080p/窄栏/隐藏面板下各运行 5 分钟，记录平均/峰值帧字节、SSE 流量、主进程 CPU、前端帧率、交互延迟；慢客户端不应累计无限缓冲；隐藏面板明显降载。
5. **UI 矩阵**：深浅主题与 480/768/934/1280px 视口。用户气泡对比度 ≥4.5:1；Word 预览全文可达；地图主体可用；任务中心无横向溢出且 15 条任务均可访问；产物“待固定”与实际可点按钮数量一致；智能体入口动作名称与实际行为一致。
6. **测试执行顺序**：先补针对新契约的单元/集成测试，再运行 `npm run test:search`、`npm run test:browser`、`npm run test:artifacts`、`npm run test:task-center`、`npm run test:a11y`、`npm run test:perf-budget`、`npm run build`、`npm run verify`。注意现有 `scripts/联网搜索测试.mjs` **会临时写入并恢复/删除真实 `.oaw/search.json`**，应先改成隔离临时配置路径或确保服务停用和备份，不能在用户正在运行的配置上直接执行。`npm run test:browser:live` 会启动浏览器并访问外部 Bing，放在隔离环境、征得相应授权后执行。

## 6. 交付定义

每个工作包交付：修改前可复现证据、改动文件与接口契约、自动化测试、在两个主题和目标视口上的截图/录屏、性能或安全复核结果、已知限制。集成负责人确认没有覆盖现有未提交改动，也没有把密钥、profile、截图、搜索历史写入版本库。优先完成 P0 后再合并交互优化；不要把“代码已接入”当作“功能已可用”，也不要把“已保存凭据”当作“已连通”。
