# 地图模块 Agent 化改造方案（v1 · 初稿）

日期：2026-10-09。目标：把当前"多面板 GIS 工作台"改造成**以自然语言为主入口的地图可视化平台**，并让地图能力接入平台既有的**工作区**概念。

### 1.2 Agent 能力现状（已有的部分）

`server/agent.mjs:1736-1964` 已注册 6 个地图工具：

| 工具 | 行号 | 能力 |
| --- | --- | --- |
| `map_read` | 1738 | 读项目配置 / 图层清单 / 样式 |
| `map_edit` | 1773 | 改样式：setVisibility / setPaint / move / add（**直接写 style.json**，无审批门） |
| `map_import` | 1852 | GeoJSON → 图层（有审批门，走 write lock） |
| `map_analyze` | 1903 | 生成分析并 `emitChannelSafe("map_action")` 推给前端 |
| `map_save_analysis` | 1926 | 把上一次分析落盘为正式图层（有审批门） |
| `map_clear_analysis` | 1952 | 清除临时分析 |

前端回流链路已通：`map_action` 事件（`server/事件注册表.mjs:97`）→ `ChatPanel.jsx:2328` → `MapPanel.handleMapAction`（`MapPanel.jsx:1352`）→ `mapRef.showAnalysis`。视口上下文也通：`MapViewer moveend → onViewportChange`（`MapViewer.jsx:507`）→ `App.mapContexts`（`App.jsx:188`）→ 拼进用户消息（`ChatPanel.jsx:2604`）。

**结论：管道已通，但"货源"是假的。**

### 1.3 核心缺陷（按严重度）

**P0-1｜Agent 够不到真实数据。** `map_analyze` 只调 `createDemoAnalysis`（`server/index.mjs:4613`，`server/map-analysis.mjs` 内存演示）。真实分析端点——`/api/map/traffic-bandwidth`、`/api/map/od-lines`、`/api/map/road-structure`、`/api/m3/*`、`/api/demo/cambodia-od`——**没有任何 Agent 工具封装**。自然语言说"做新昌公交 OD 分析"目前做不到。

**P0-2｜临时图层会被 `setStyle` 清空。** `MapViewer.applyStyle`（`:617-672`）用全量 `setStyle(style, {diff:false})`，随后手工重放 4 类状态。但重放清单里**只有 MapViewer 自管的 `analysis` payload**（`:669-671`），**不包括**：
- MapPanel 自己的 `od-*`（`MapPanel.jsx:296-318`）、`iso-*`（`:975-1009`）、`route-*`（`:931-957`）、`draw-*`（`:1089-1123`）
- M2/R3/柬埔寨面板直接 `mapRef.current.getMap().addSource/addLayer` 的层（`M2宏观分析.jsx:25`、`M3公交分析.jsx:21`、`柬埔寨OD面板.jsx:40`）

后果：**改个样式颜色，分析结果就消失**。

**P0-3｜五套分析实现读五种数据源、返回五种形状。** M2（`map.mjs:1071-1216`）、M3 新昌（`map.mjs:1220-1365` + `m3-xinchang.mjs`）、M3 旧 CSV（`map.mjs` 内）、柬埔寨（`柬埔寨OD.mjs`）、演示（`map-analysis.mjs`）——返回 `{geojson,stats}` / `{points,lines,stats}` / `{geojson,lines,stats}` 各不相同。

**P1-1｜图层真相被劈成两半。** `map.config.json`（id/name/type/group/visible）与 `style.json`（paint/layout/order/visibility）各存一半，`id/source` 靠约定对齐。删图层要额外走 `/api/map/layer/delete`。

**P1-2｜找不到"要改哪一层"。** `map_edit` 的 `layerId` 是样式层 id（如 `highways`），但业务层分组在 config 的 `group`——Agent 想"隐藏所有公路"没有表达方式。

**P1-3｜工具栏 33+ 控件平铺。** 详见 §4。

**P2｜重复与死代码**：bbox 计算 6 份、`parseShapefile` 2 份、临时层清理 3 份、组名常量 3 份、`MapViewer` ~10 个零调用方法、`M3BusPanel`/`XinchangBusPanel`/旧版柬埔寨面板未被引用。

**P2｜数据损坏**：`MapViewer.jsx:233,257` 含 U+FFFD 替换字符（`区划编�`），依赖该字段名做过滤的指令会静默失效。

**P2｜底图字形不可达**：实测 `https://glyphs.openfreestyle.com/Noto%20Sans%20Regular/0-255.pbf` 报 `ERR_NAME_NOT_RESOLVED`（`maptiler-basic` 依赖）。地图能渲染但标注文字会缺字形。

## 2. 目标定义

### 2.1 用户要的形态

> 一个完整的 Agent，通过自然语言输入输出，在地图上显示可视化的平台，也要有工作区的概念。

拆解为三条可验收的目标：

| 目标 | 可验收表述 |
| --- | --- |
| **G1 自然语言是主入口** | 用户说"把新昌的公交 OD 画成流向图，流量小于 50 的不要"，地图上出现正确图层；全程不打开任何面板/不点任何参数控件 |
| **G2 结果可留存、可追溯** | 每次可视化都产出一条**图层资产**（不是临时层），归属到具体一轮 Run，可在「本轮产物」里看到、可回滚 |
| **G3 地图属于工作区** | 地图数据集是工作区内的资产（`<workspace>/maps/...`），换工作区就换数据集；Agent 在对话里知道"我现在在哪个工作区、有哪些地图数据" |

### 2.2 非目标（明确排除）

- 不做通用 GIS 平台（不做投影变换、栅格分析、拓扑校验）。
- 不替换 MapLibre；不引入 PostGIS / 空间数据库。
- 不重写 MapViewer 的渲染层（它工作正常且是纯 MapLibre StyleSpec）。
- 不删除现有面板（收敛，不删除；高级用户仍可打开）。

## 3. 目标架构

### 3.1 分层

```
┌─────────────────────────────────────────────────────────────┐
│ ① 意图层  自然语言  →  MapAction DSL（结构化动作）           │
│   Agent 工具面：map_visualize / map_query / map_edit_layer   │
├─────────────────────────────────────────────────────────────┤
│ ② 计划层  MapAction DSL → 渲染计划（layers + style + extent）│
│  纯函数：数据描述符 → MapLibre style fragment + 统计摘要      │
├─────────────────────────────────────────────────────────────┤
│ ③ 执行层  图层仓库（唯一写入口）/ 临时层注册表（唯一重放源）  │
├─────────────────────────────────────────────────────────────┤
│ ④ 渲染层  MapViewer（保留，改为只接受声明式批操作）           │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 关键设计决策

**D1：一个统一的"分析描述符"取代五套形状。**

新增 `server/map-visual.mjs`，所有分析出口统一返回：

```js
{
  v: 1,
  id: "od-xinchang-2026-10-09",
  dataset: { workspace, project: "zhejiang-map", sources: ["m3-od"] },
  kind: "flow" | "heatmap" | "choropleth" | "categorical" | "points",
  title: "新昌公交 OD 流向（≥50 人次）",
  geojson: <FeatureCollection>,          // 必填：几何
  stats: { count, min, max, avg, ... },  // 必填：统计摘要
  style: {                                // 可选：渲染建议（纯数据，非 MapLibre 表达式）
    field: "flow", ramp: "viridis", widthRange: [1, 8], radiusRange: [4, 20],
  },
  provenance: { generatedBy: "agent", runId, at },
}
```

**所有** M2/M3/柬埔寨/演示端点改为产出这个形状（内部保留原实现，外层包一层适配）。`map_analyze` 的 `analysis` 参数从 3 个演示类型扩展为**数据集 + 可视化类型**。

**D2：图层仓库（唯一写入口）+ 临时层注册表（唯一重放源）。**

- **图层仓库** `server/图层仓库.mjs`：合并 config.json 与 style.json 的读写，对外只暴露 `listLayers / addLayer / updateLayer / removeLayer / setStyle`。**消灭"真相劈成两半"**。
- **临时层注册表** `client/src/图层注册表.js`：任何临时层（分析 / 测量 / 绘制 / OD / 等时圈）登记为 `{ id, owner, spec }`，`applyStyle` 后**统一按注册表重放**。**消灭 P0-2**。
- 禁止再用 `getMap().addSource()`；MapViewer 只暴露 `applyLayerOps([...])`。

**D3：图层寻址从"样式层 id"升级为"选择器"。**

`map_edit_layer` 的 target 接受三种形式，Agent 按用户措辞自由选：
- `id:highways`（精确）
- `group:公路网`（分组）
- `name:~高速`（名称模糊匹配，走 config）

**D4：工作区作为地图的一等上下文。**

- 地图数据集路径从固定的 `office-workspace/maps/<name>` 改为 **`<workspace>/maps/<name>`**（即跟随当前工作区）。
- 平台 `project`（`server/项目管理.mjs`，与 workspace 1:1）增加一个派生字段 `mapDatasets: [{ name, layers, updatedAt }]`。
- Agent 新增 `map_datasets` 工具：列出当前工作区的地图数据集；`map_visualize` 默认使用当前工作区。

**D5：写操作分级（沿用平台既有审批机制）。**

| 操作 | 级别 | 依据 |
| --- | --- | --- |
| 生成临时可视化 | 免审批 | 不落盘 |
| 保存为正式图层 | 审批（已有 `requireToolApproval` 先例，`agent.mjs:1875`） | 新文件 |
| 改样式 / 删图层 | 审批 | 改既有资产 |
| 读数据集 / 查统计 | 免审批 | 只读 |

## 4. 工具栏简化方案

### 4.1 现状：33 个常驻控件（实测）

`MapPanel.jsx:1427-1598` 平铺 33 个控件，其中**已确认重复**：

| 重复 | 证据 |
| --- | --- |
| 「可达性」按钮 与 分析菜单里「可达性与路径规划」 | `:1528` 与 `:1520` 同指 `setIsoOpen` |
| 「示例数据」菜单的清除/撤销/保存 与 Agent 的 `map_clear_analysis`/`map_save_analysis` | `:1539-1541` vs `agent.mjs:1952/1926` |
| 「分析工具」菜单 6 项 vs 「示例数据」菜单 5 项 | `:1519-1524` vs `:1537-1541` |
| 一个按钮的 active 依赖 6 个状态 | `:1510` |

### 4.2 简化方案：33 → 9（三组分 + 溢出菜单）

```
[项目 ▾] [底图 ▾] [区域 ▾]   |   [图层] [可视化 ▾] [数据 ▾]   |   [视图 ▾] [导出] [返回]
   ↑ 场景           ↑ 内容操作            ↑ 输出        ↑ 会话
```

| 组 | 控件 | 收纳原来哪些 |
| --- | --- | --- |
| **场景** | 项目下拉（含新建/复制/重命名/归档/删除）、底图下拉、区域下拉（含下钻/范围/搜索/标注） | `:1430-1497, 1556-1580`（原 12 个） |
| **内容** | 图层（打开左栏）、可视化（打开统一面板）、数据（导入/重建瓦片） | `:1499-1534`（原 8 个） |
| **输出** | 导出报告图 | `:1545` |
| **会话** | Agent 开关、返回 | `:1551-1555, 1597` |
| （浮动） | 测量 / 绘制 / 清除 | 保留为画布上的浮动工具条（`:1769-1784`） |

**原则**：单次会话里"切了就不再改"的（项目、底图）降到下拉；"每轮都可能用"的（可视化、数据、导出）保留一级；测量/绘制是**画布操作**，从顶栏移到画布浮动条（它们现在是顶栏按钮 + 弹出菜单，与地图操作位置分离）。

### 4.3 「可视化」统一面板取代 6 个分析面板

据 §1.3 P0-3，六个面板本质是同一条流水线。收敛为一个 `可视面板`：

- 输入区：**一个自然语言输入框**（默认）+ 一个「高级」折叠（暴露数据集/类型/阈值，给不用自然语言的场合）。
- 输出区：图层卡片（可切显隐/删除）+ 统计摘要 + 「保存为图层」。
- 六个旧面板：M2/M3/柬埔寨的**后端端点保留**，前端改为统一面板的"预设"（点开即把对应描述符填入）。

**旧面板不删除**，但不再出现在主路径。

## 5. 分阶段实施

| 阶段 | 内容 | 交付 | 可独立验收 |
| --- | --- | --- | --- |
| **P0** 管道加固 | 临时层注册表 + `applyLayerOps` + 修 U+FFFD + 删死代码 | 分析结果不再被样式变更清空 | 改样式后分析层仍在 |
| **P1** 统一描述符 | `map-visual.mjs` + 5 个端点适配 + Agent `map_visualize` 工具 | 自然语言能出真实数据可视化 | 说一句话出图 |
| **P2** 图层仓库 | `图层仓库.mjs` 统一 config+style 读写；选择器寻址 | Agent 能"隐藏所有公路" | 分组操作生效 |
| **P3** 工具栏收敛 | 33 → 9 + 统一可视面板 | 界面简化 | 目视验收 |
| **P4** 工作区贯通 | `maps/` 跟随 workspace + `map_datasets` 工具 | 地图属于工作区 | 换工作区换数据 |

**依赖**：P0 必须先做（否则 P1 产出的图层会被 P3 的样式重放清掉）。P1 与 P2 可并行。P3 依赖 P1（面板要接统一描述符）。
