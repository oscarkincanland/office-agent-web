# 测试策略：每阶段一轮验收

上级：`2026-10-09-010-地图与Agent平台化-总体计划.md`。
**用户要求**：每个阶段进行一轮测试。

---

## 1. 三层测试（每阶段都跑）

| 层 | 内容 | 命令 | 通过标准 |
| --- | --- | --- | --- |
| **L1 静态** | 构建 + 既有回归 | `npm run build` + `npm run test:*`（40 个） | 构建成功、40/40 通过 |
| **L2 阶段专属** | 该阶段新增功能的源码级断言 | 见 §2 各阶段的测试文件 | 全绿 |
| **L3 端到端** | 浏览器实测该阶段的验收场景 | Playwright 脚本 | 场景表全过 |

**增量原则**：每阶段只新增自己的 L2 脚本与 L3 场景，**不改 L1 的既有断言**（除非产品规则变更，那时同步更新并在变更日志里写明）。

## 3. 端到端测试脚本模板

每个阶段的 L3 用一个独立 Playwright 脚本（放在 `C:/Users/<user>/AppData/Local/Temp/` 或仓库 `scripts/` 下，按是否要长期保留决定）。

**模板骨架**（本会话已验证可用）：

```js
// 1. 启动 chromium（用本机 ms-playwright）
// 2. 打开 http://127.0.0.1:3002
// 3. 进入地图：点击"能力" → "地图"
// 4. 切换模式：主对话点 .conversation-mode-option.work（地图内无开关，见 X2）
// 5. 发送指令：page.locator("textarea").first().fill(...) + press("Enter")
// 6. 等待完成：轮询 .chat-body .msg.assistant 的 streaming 标记
// 7. 读取事实：
//    - 服务端：fetch("/api/map/project?name=zhejiang-map") 读 style.layers
//    - 事件：读 .oaw/runs/<最新>.json 的 events（找 map_action / tool_start）
// 8. 断言并截图
```

**关键技巧**（本会话实测得出）：
- 地图入口不在按钮文案里，走 `openExternalModule("map")`（`App.jsx:1475`），实际是「能力」菜单 → 「地图」。
- 地图模块内**没有模式开关**（X2），需先返回主对话切 Work 再进地图。
- 判断工具是否真被调用：读 Run JSON 的 `tool_start` 事件，**不要**只看 UI 工具卡（卡片可能不显示）。
- 底图/图层变化的判定：对比 `/api/map/project` 返回的 `style.layers` id 集合。

## 4. 每阶段的验收门槛（Definition of Done）

一个阶段算完成，必须同时满足：

1. **L1**：`npm run build` 成功 + 全部 `test:*` 通过（40 个）。
2. **L2**：该阶段新增的源码断言脚本全绿。
3. **L3**：该阶段的浏览器场景全部通过，并有截图或 JSON 证据。
4. **文档**：该阶段文档里的"验收"表逐条勾选。
5. **回滚**：确认回滚方式可用（小改动不必实测，大改动需验证）。
6. **变更日志**：写明本阶段改了什么、影响哪些既有行为。
