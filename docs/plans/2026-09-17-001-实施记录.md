### 备注

- `complete_task` 状态影响展示而非 Run 终态：Run 的 completed/failed/cancelled 仍由服务端执行结果决定；completion 是给用户看的"任务语义"。

- 折叠摘要文案示例：`已调用 6 个工具 · 5 成功 · 1 失败 · 2 个文件变更 · 部分完成`。
- 修正产物校验终态：混合场景跳过失败文件继续发布；**全部待发布文件校验失败时 Run 落为 failed**（恢复阶段一测试的语义期望，`server/runs.mjs`）。

## 补充修复（对话切换性能 / 产物噪音）

### 问题与根因

| 问题 | 根因 |
| --- | --- |
| 对话切换慢（实测会话列表 5.5s 冷 / 2.0s 热） | ① `/api/sessions` 对 247 个 JSONL **全量读取**（34.9MB）后逐行解析找标题；② 文本缓存上限 160 < 247 → 每次都缓存击穿重读；③ `listSessionFiles` 仅为拿头部也全量读文件；④ `listRuns` 解析全部 479 个 Run JSON（含 before/after 快照）后，又对前 200 个**重复 loadRun 一次** |
| 工作产物出现垃圾（`_head.py`、`_*_log.txt`、`__pycache__` 等） | agent 执行中用 bash/python 产生的临时脚本与日志被快照 diff 归入 artifacts，产物列表无噪音过滤 |

### 改动清单

| 文件 | 类型 | 改动内容 |
| --- | --- | --- |
| `server/index.mjs` | 修改 | 新增 `readFileHead`（只读文件头 64KB）、`readSessionHeaderCached`（头部指纹缓存）、`sessionMetaFor`/`buildSessionMeta`（元数据指纹缓存 + 增量标题扫描，上限 2MB）；`listSessionFiles` 改用头部缓存；`/api/sessions` 全部走元数据缓存 + Run 映射表 + 项目按 cwd 记忆化；`SESSION_TEXT_CACHE_LIMIT` 160→400；`emitChannel` 补齐 `streamId/protocolVersion` 并用受保护写入 |
| `server/runs.mjs` | 修改 | 新增 Run JSON 解析缓存（500 上限，mtime+size 指纹，saveRun 失效）；`getRun` 拆出 `publicRunView`，`listRuns` 复用避免二次加载；新增 `isNoiseArtifactPath`（临时/调试/缓存文件判定）并接入 `filterRunChanges`；`filterRunChanges` 兼容字符串路径（修复此前 `file_changed` 事件可能为空的问题） |
