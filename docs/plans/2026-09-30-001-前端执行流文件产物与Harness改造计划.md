# Open Plan 前端、执行流、文件产物与 Harness 改造计划

日期：2026-09-30。定位基线：本地 `open-plan@0.11.11`。

本文是交给实施 Agent 的修改说明。当前仅新增本计划文档，未实施业务代码修改。实施时以函数名、事件名和选择器为定位依据；下列行号是本次审查的导航点，代码更新后可能移动。

## 1. 目标、依据与范围

目标：用户快速看到结论，能随时查看执行证据、工具调用和文件差异；长任务可以暂停、恢复，失败如实表达；预览文件时不会因为工作区混用、异步加载或资源释放不完整而出现错误文件、空白、图片遗漏。

Proma 参考来自用户提供的两张截图：一张显示“文件 / 改动”及项目文件、会话文件分区；另一张显示模型信息下方的一行折叠执行过程。已观察到的参考原则是：正文优先、过程可折叠、文件与改动有明确入口。未实际验证 Proma 的动画、完整状态机及其他隐藏交互，不将这些作为已确认事实。

已检查当前浏览器界面、源码，并运行以下既有测试：`test:conclusion`、`test:run-trace`、`test:artifacts`、`test:progress-narration`，均通过。它们包含纯函数、文件操作和静态契约检查，不能代替浏览器完整任务验证。

当前浏览器中的长模板总结来自 8 月的历史消息。源码已经有禁止固定五段总结的提示，不能以历史文本证明新版本仍然生成该模板。当前可确认的问题是：前端仍展示多层结果、重复文件清单，旧历史缺少统一的紧凑展示方式。

核心范围：对话与过程、结论、文件改动、产物、记忆建议、任务中心、主题与布局、Word/PPT/PDF/图片预览，以及与这些界面直接相关的 loop 和事件契约。地图、智能体广场、浏览器的入口一致性在后续阶段处理；不在本次计划中扩展新的 MCP 或插件能力。

## 2. 最终界面与交互约定

一轮任务以 `runId` 为单元呈现：

```text
用户问题与引用
助手：模型 · 时间
  执行过程：3 次工具调用 · 用时 12 秒                 [展开 / 隐藏]
  结论正文
  [文件改动 2] [交付产物 1]                         （没有则不出现）
  [记忆建议 1]                                     （仅有待审核建议时出现）
```

- 运行中：执行过程显示当前动作和必要的等待原因；详细工具记录在展开区内部滚动。正文持续流式显示，工具参数、输出和旧进度叙述属于过程详情。
- 已结束：执行过程自动收起为一行。只留下一个最终回答，不再自动追加“总结”“结果摘要”“经验总结”等独立正文卡。
- 失败、部分完成、等待审批或用户回答：显示明确的状态和可以执行的动作；这些状态不能因为隐藏过程而消失。
- 文件改动：显示本轮真实新增、修改、删除；最多在正文下显示 3 条，其余进入改动面板。
- 交付产物：只包含明确的用户交付文件；缓存、临时文件、内部记忆和运行记录不自动计入。
- 右侧工作面板：`预览 / 改动 / 产物`。默认保留用户当前视图，空白时不长期挤占正文；窄窗口以抽屉承载。
- 不对模型答案统一截成固定字数。短问答直接回答；交付任务先用 1–3 句说结果，细节按任务需要提供。不能用截断隐藏风险、未完成项或用户明确要求的完整内容。

```ts
type RunView = {
  runId: string;
  lifecycle: string;              // 运行状态，与目标是否达成分开
  outcome: { status: string; source: string; summary: string; incomplete: string[]; blockers: string[] } | null;

  progress: { phase: string; currentAction: string; waitingReason: string | null };
```

约束：snapshot 与事件合并按明确的 runId、消息版本、工具 toolCallId 和文件身份进行；空事件不能清除已有权威数据；不同 Run 的迟到事件不能改变当前输入框或气泡。

### A02. 一个终态、一个最终回答

定位：

- [server/index.mjs](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/server/index.mjs:3329)：`executeAgentRun` 及所有异常/恢复结束路径。
- [runs.mjs](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/server/runs.mjs:511)：`recordRunFinalText`；同文件 `finishRun`（694）。
- [ChatPanel.jsx](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/components/ChatPanel.jsx:2093)：`run_finished` 和 `upsertRunSummary`。

实施方法：

1. 保留已经存在的 `finalMessageId`、finalTextVersion 和幂等写入。正文只由这条最终消息消费；重连时 replace/补全同一消息，不能 append 第二份答案。
2. `task_completed` 只代表模型声明。最终状态在产物校验、发布及取消结果汇总后，由 `finishRun` 确定；不得在 `complete_task` 被调用时抢先结束 UI。
3. 新界面不再把 `agent_summary` 追加为系统消息。它暂时作为旧数据适配入口；服务端新路径停止用它发送“共处理 N 个文件：全部文件名”的正文。
4. 逐项处理当前 `RunSummary` 内容：状态进入过程头行；未完成/阻塞显示短提示；验证结果进验收详情；工具进过程；改动进改动面板；产物进入交付列表；通用“下一步”删除，只显示真实需要用户行动的事项。
5. 旧历史保留原始消息及旧摘要数据，但 UI 可以聚合为一轮。不得重写持久化历史、调用模型重新总结整段历史，或删掉已有答案。
6. 临时显示状态不得默认为 completed；缺失状态显示“状态待同步”，收到权威终态再更新。

验收：同 Run 重复接收 assistant_final、agent_summary、run_finished 后仍只有一条最终答案；失败不显示成功；用户刷新后的文字、文件和状态与刷新前一致。

## 5. 第二阶段：对话、执行过程、布局与任务中心（P1）

### B01. 拆分 ChatPanel 并按 Run 渲染过程

定位：[ChatPanel.jsx](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/components/ChatPanel.jsx:2854) 的 `chat-topbar`，`ExecutionFlow`（3945）、`Message`、`ThinkingBlock`（3644）、`RunSummary`（3283）。

拟新增：`RunConversation.jsx`、`RunActivity.jsx`、`RunResultLinks.jsx`、`useRunEvents.js`。先抽出投影和事件处理，再移动渲染组件；每次抽取保持现有行为可验证，不一次性重写 4000 行文件。

实施方法：

- 以 runId 关联用户消息、助手消息与工具记录；每轮渲染一个 RunConversation。
- 思考摘要、工具卡、进度叙述进入 RunActivity。工具 start/output/end 已能归约，直接复用，不重新数原始 SSE 事件。
- 过程头行显示工具次数、当前动作、耗时；事件数量只在调试详情展示。
- 当前 Run 运行时允许展开；收到权威终态后默认收起。正在手动查看输出的用户可固定展开，避免突然合上内容。
- 审批与提问采用显式卡片并保持可操作，隐藏过程时提供同一审批/问题入口。
- 自动滚动只在用户跟随底部时执行；回看历史时保留锚点，工具展开、收起及图片加载不把页面拉到底。
- 原始工具输出分页/截断显示并提供加载更多；避免大型字符串同时保存在多个 UI 状态里。

### B03. 中央正文与右侧工作区

定位：[App.jsx](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/App.jsx:143) 的 previewOpen/previewLayout；`handleRunFinished`（1023）；预览面板渲染（1432 起）。

## 6. 第三阶段：文件改动与交付产物（P0–P1）

### C01. 文件变更来源与归属

定位：[runs.mjs](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/server/runs.mjs:117) 的 snapshotWorkspace、filterRunChanges（411）、changedFiles（594）、finishRun（694）；`写入协调.mjs` 的暂存、发布与写入事件。

文件回滚操作明确列出目标；只有 before blob 可用且当前文件与 Run.after 相符时直接回滚，否则报告冲突供用户选择。删除记录必须可见，新增文件的撤销与恢复旧文件的回滚文案分开。

### C02. 内容差异接口与面板

定位：[成果管理.mjs](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/server/成果管理.mjs:187) 的 diffSummary，`server/index.mjs` 的 Run 路由，`client/src/api.js`。

拟新增 `server/文件差异.mjs` 与 `client/src/components/FileChangesPanel.jsx`。拟新增只读接口：`GET /api/runs/:runId/changes/:changeId/diff`；changeId 必须由服务端 Run 记录解析到合法文件，不能接受任意路径直接读取。

实现顺序：

1. UTF-8 文本/Markdown/CSV/JSON：按真实 before/after 计算增删行，返回摘要和分页 hunks。区分文本换行/编码和真实内容变更。
2. Word：解析段落、表格和媒体关系，给出段落增加/删除/修改及图片数量变化；用序号、结构位置与内容指纹做匹配。复杂段落对齐失败时显示“不支持精确对齐”，不把匹配猜测当事实。
3. PPT：按 slide 标识和 shape 标识比较文本、媒体及页增删；先提供页级摘要，再按需渲染前后页。
4. PDF/图片/二进制：显示大小/hash/尺寸或页数变化，提供前后预览；没有可用历史内容时说明不能对比。

diff 按需计算，缓存键包含 beforeHash、afterHash、算法版本；设置输入字节、解析时间和响应大小上限。不要在每次 run_finished 中同步解析全部 Office 文件。

## 7. 第四阶段：预览一致性、图片与目录（P0–P1）

### D01. 统一文件身份与预览状态（先做）

定位：[App.jsx](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/App.jsx:659) 的 open；[DocViewer.jsx](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/components/DocViewer.jsx:495)；[server/index.mjs](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/server/index.mjs:877) 的 raw/html/comments/watch/outline；`client/src/api.js`。

App.open 将 `{ workspaceId, cwd, relativePath, revision }` 放入 doc 对象，并传给所有子预览组件。拟新增 `client/src/文件地址.js`，统一生成 raw、html、comments、annotations、outline、watch 地址；每一条请求显式带同一 cwd/文件标识。响应附带 file identity，组件核对后才展示。后端继续校验允许工作区/外部引用，不能放开任意绝对路径。

revision 以服务端文件 version/hash 为优先，刷新时再重新获取版本；不能把 Date.now 当文件真实性标记。为 fetch 添加 AbortController、渲染 generation；切文件、关闭标签、切工作区后旧加载结果不能写入新预览。

共享状态：loading、ready、partial、unsupported、failed。iframe onload 仅表示页面已加载，不等于内容成功。服务端预览返回明确错误；HTML 预览可发送限定来源、含文件身份的 ready/partial/error 消息给宿主。

### D02. Word 图片、目录和分页

定位：[DocxViewer.jsx](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/components/DocxViewer.jsx:179) 的 renderDoc/brokenImages、buildOutline（260）；[文档目录.js](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/components/文档目录.js:1)、[文档分页.js](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/components/文档分页.js:1)。

实施方法：

- 解析 OOXML relationships 与实际媒体，记录应渲染媒体和不支持格式。不能以 DOM 中 0 个 img 判定图片都已正常显示。EMF/WMF、链接图片、损坏媒体分别给具体状态；不要自动改用户源文件来修预览。
- 以图片 load/error/decode、字体 ready 和渲染 generation 管理就绪；超时的 pending 图片计入 partial。Base64 只作为受控重试，不让每个大文档无条件双份渲染。
- 大文件将 zip/XML解析移到 worker，设解压预算；主线程不进行完整大型媒体解码。退出时释放 blob URL、监听器、observer 和过期任务。
- XML 用命名空间感知解析替代正则；补样式 basedOn 继承、段落级 outlineLvl；排除 outlineLvl=9 的正文及目录域生成条目。heading 编号与标题文本分开，不人为重新编号替代原文编号。
- 每个标题生成稳定 headingId，保留源段落位置、级别与全文。映射 DOM 优先按结构顺序/样式及渲染锚点；文本匹配只为兜底，必须带未定位状态。相同标题或前 24 字相同不能跳到另一处。
- 分页在资源稳定后、原始未缩放坐标下测量；切缩放不叠加旧缩放计算。只在需要时做一次重分页；克隆或移动 DOM 时保留段落锚点、页眉页脚关系、批注和链接。
- 浏览器分页显示为“预览页”，不得保证与 Word 原始排版页码一致。高保真路径的页码单独表达。

Word 图片丢失与复杂目录错位必须用用户文档复现后记录“源包包含 → 渲染器产出 → 资源加载 → 分页后 DOM”的逐层证据。

### D03. PPT 渲染与 HTML 回退

定位：[PptxViewer.jsx](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/client/src/components/PptxViewer.jsx:1)、[office.mjs](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/server/office.mjs:190) 的 withPreviewCopy/renderHtml，以及 index HTML 路由（978）。

只允许同一 viewer 同时执行一个 renderSlide；页码/缩放/尺寸请求采用 latest-wins 队列，防止旧页晚完成覆盖新页。go/jump 只设置目标页，由一个 effect 渲染，移除按钮和 effect 双重渲染路径。

卸载、中止、切文档或渲染器时中止请求并释放资源。先核对已安装 pptxviewjs 的真实释放接口；若没有 destroy/dispose，则清除 viewer 引用和所属对象 URL/监听器，不虚构库 API。Canvas backing size 按 viewport、DPR 和内存上限管理，保留 slide 原始宽高比。

依据已验证的不支持元素、渲染失败或资源预算切换回退，而不只看 100MB 阈值。OfficeCLI 返回码非零时明确失败；renderHtml 不能只把 stdout 当成功。临时副本删除前确认输出资源已经内联或可通过受控资产接口访问，否则相对图片/字体地址可能失效。资源失效目前是待样本验证风险。

## 8. 第五阶段：loop、预算与稳定性（P0–P2）

### E01. 将运行生命周期与工作阶段分开

定位：`agent.mjs` 的 prompt/subscribe/abort、[轮次预算.mjs](/Volumes/移动固态硬盘/工作文件夹/office-agent-web-feature-knowledge-base/server/轮次预算.mjs:1)、`Pi运行时管理.mjs`、`运行轨迹.js` 的 PHASE_ORDER。

生命周期：queued → running → waiting_user / waiting_approval → running → finalizing → completed / failed / cancelled。若现有后端用事件表达 waiting_approval，先在投影层统一，不立即批量迁移存储枚举。

工作阶段：计划 → 执行 → 验证 → 交付。验证失败需要再次执行时，阶段允许回到执行并增加 attempt；只有生命周期终态不可倒退。当前只许阶段单向前进的逻辑需调整，避免修复后续步骤仍被标为“交付”。

### E02. 调度预算和重复失败门禁

拟新增 `server/运行预算.mjs`，管理模型回合、工具次数、有效运行时长、连续失败、重复无进展和输出预算。默认保留 25/45 轮作为兼容基线，实际数值由设置/任务配置决定；等待用户、审批、用户接管时间不计入有效执行时长。

在下一模型回合及工具实际执行前评估预算，不能只在 turn_start 发 steer。软预算触发一次明确的暂停与继续选择；用户继续是显式授权增加预算。硬预算停止新的任务工具，允许当前已开始写入安全收尾、验证已落盘文件和记录终态；最多一个受限收尾回合，不能因此再次修改文件。

工具参数以完整规范化参数指纹/hash 比较，文件 read 的版本变化和合理轮询单独处理；当前截前 300 字的指纹不能作为硬拒绝键。同样错误连续两次且没有状态改变时停止该操作并发出明确诊断。重复成功读取已有结果可以复用；用户主动重复要求不被误拦截。

对于 SDK 内置工具，实施前核对当前 Pi 版本支持的工具包装/扩展执行拦截方式，统一接入门禁。不能在 tool_start 事件已执行之后仅发提醒，就宣称实现了硬预算。

### E03. 进度与收尾时延

定位：`轮次预算.mjs` 的 turn-progress、`agent.mjs` 的 completion_nudge（3074）。

进度优先由 todo_updated、工具边界、验证结果产生；同阶段连续读文件合并成“正在读取材料”。只有任务持续较久、发生阶段改变、错误或需要用户判断时生成新的短进度；不每 6 轮强制模型在正文重复三段内容。状态推断应来自结构化事件，删除 recentNarration 正则猜正文的方式。

短只读任务无 complete_task 时，允许权威运行结束并标“已答复 / 未单独验收”，不自动补一次模型请求。复杂写入任务缺声明且目标不明确时才进行限时收尾提醒；提醒调用限制为 complete_task，不能依赖提示词禁止新工具。补声明失败保留主回答和客观验收，不将已有正确答复丢弃。

增加 timestamps：admitted、firstModelEvent、firstVisibleText、modelEnd、verificationEnd、finished。区分首事件延迟、模型执行和后台收尾延迟；思考 token 到达不等于用户已看到有效答复。

### E04. SSE、取消与资源

保留现有 streamId/序号代际隔离、终态幂等、Runtime 单飞恢复及写入锁。新增 UI 投影不能另建一套无代际游标的重连逻辑；当前工作产物 EventStream 的独立订阅应与共享订阅口径对齐。

重连先获取当前 Run snapshot，再补游标之后的事件；被淘汰的 token 不可丢失最终文本。tool_end 晚到、终态重复、旧 Run 回放和切工作区应有确定处理规则。终态后无遗留“工具执行中”记录，无法确认结果的工具标为中断/未知。

取消向模型、等待队列、子 Agent、浏览器操作及可取消工具传播；无安全中断能力的写入等待一次提交边界再结束。服务重启先标等待恢复，用户选择后继续，不自动重放曾经执行过的写入。

预览/浏览器/Pi/OfficeCLI 有独立清理范围；关闭预览不能销毁当前 Agent runtime。OfficeCLI 全局并发限制继续保留。补查 SSE history、Run.events、工具输出和 frame 的字节预算，不仅按条数限制。大 diff、预览转换不得长期阻塞 Node 主线程。

Mac 稳定性验证应收集服务退出码、Runtime 错误、浏览器 console、峰值 RSS、活动 preview/watch/child 数量；目前没有足够证据把全部崩溃归因到某一渲染库。

### E05. 地图、智能体广场和内置浏览器的一致入口（后续）

定位：`AgentMarket.jsx`（56）、`MapPanel.jsx`（158，分析 1354 起）、`内置浏览器面板.jsx`（28）、`App.jsx` 的外部模块开关。

智能体卡提供明确的“使用此智能体”，带入工作区、任务和 profile，创建 Run 前预览能力范围；管理/编辑入口与使用入口分开。地图发送给 Agent 的是项目、选中图层及操作目标的结构化引用，地图分析按相同 RunView 展示过程和结果，保留演示数据提示。浏览器接管期间运行状态显示“等待你交还”，暂停有效执行预算；截图帧更新不重渲染全部对话。模块切换保留输入草稿、当前 Run 和预览身份。

行为测试优先，静态正则断言随设计更新，不把旧布局规定当产品验收。尤其 `对话流性能回归测试.mjs` 当前断言过程必须固定顶部，与新内联设计冲突；实施 B01 时必须更新此断言，并增加真实展开/收起/滚动行为检查，不能只删断言让测试变绿。

既有相关脚本：任务结论事件流、执行轨迹归约、SSE 协议、成果可信度、任务中心可信度、主任务流、审批作用域、启动恢复、写入锁、重复调用、动效、无障碍窄屏、性能流量基线。按工作包运行对应集合，最终再做一次跨层回归。

必须覆盖的浏览器与运行场景：

1. 纯问答、单次读取：只有答案和可选过程，无“文件 0 项”结果卡，无收尾补模型请求。
2. 多步生成文件：工具过程滚动，最终结论一次，改动与交付各自正确，原始工具输出按需查看。
3. 20–50 个文件：正文仍可读；目录分组、显示更多和 diff 不溢出；内部文件不误列为产物。
4. 一部分工具失败、产物格式失败、用户取消：状态如实显示；失败文件不能被当作通过验收的交付；已实际改动仍可查看。
5. 审批/提问/接管：隐藏过程仍能找到需要行动的位置；等待时间不触发硬执行预算。
6. 重复事件、agent_end 早于 run_finished、迟到 tool_end、断网重连、刷新：无重复答案或文件、无动画重播、无永久 busy。
7. 两工作区各有同名 docx/pptx/pdf，两个 Run 同时写不同文件：文件身份与变化归属正确。
8. Word 样本：嵌入/浮动/链接图片、页眉页脚、跨页表格、同名标题、样式继承、无分页符、字体延迟；核对图片、目录锚点和预览页码。
9. PPT 样本：4:3/16:9、图片/图表/文本框、缺失媒体、大文件；快速翻页与缩放后最终显示目标页，反复开关不积累资源。
10. PDF/图片：扫描/文本 PDF、缺失字体、损坏文件、旋转页、SVG、异常扩展名；错误可理解，不静默空白。
11. 390/768/1024/1440px、200% 缩放、亮暗主题、键盘操作、reduce-motion：正文与输入可用，浮层不被裁切，无不可见文字。
12. Mac 连续打开关闭预览和任务中心、长任务与 SSE 重连：活动资源回落；记录峰值内存及退出原因。设置明确资源预算后再判断是否通过，不能只凭“暂时没有崩溃”。

性能验收以 W0 同模型/同样本的基线比较：记录首事件、首可见正文、终态延迟、主线程长任务、网络负载和内存。界面重构不得增加模型调用数；恢复后不得重新执行已完成的写入；无声明的简单只读任务应消除当前 completion_nudge 的额外模型开销。

## 10. 迁移、交付与回退

先以内部 `runUiV2` 功能开关灰度新界面；该开关仅控制显示，旧数据仍可用。旧 agent_summary/products 转为投影输入，保留原始 Run 和审计信息。新字段向后兼容，缺失字段降级显示；不要一开始改写全部历史。

每个工作包独立提交，避免混合依赖升级、数据库迁移和全局主题重写。W1 完成后再拆 UI，W4 完成后再调渲染；先解决身份和语义，再做动画和视觉润色。

最终交付应包含：代码定位与变更表、事件与 FileChange 契约、设置迁移说明、复现样本与验证结果、前后界面截图、资源/延迟数据、未支持格式及回退方式。若样本仍有丢图或目录未定位，标注具体格式和边界，不用“预览已经完备”替代验证。

本计划推荐的第一批实现是 W1 + W4：先统一任务结果与文件身份，两者是后续过程界面、文件差异和预览稳定性的基础。
