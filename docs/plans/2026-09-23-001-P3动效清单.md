# 动效清单

本清单是 P3「动效治理与微交互落地」的第一项交付物：为每一类动效登记**触发条件、持续时间、可中断性、静态回退、读屏播报**，作为「只保留对主任务有意义的动画」的判定依据，也是 `scripts/动效治理测试.mjs` 的对照表。

## 0. 统一闸门（先于任何局部样式）

| 项 | 约定 |
| --- | --- |
| 系统偏好 | `prefers-reduced-motion: reduce` → `client/index.html` 内联脚本在**首帧前**写入 `<html data-reduce-motion="1">`，`client/src/界面外观.js` 在运行时继续同步 |
| 产品档位 | 设置 → 外观 → 动效档位 → `off` → `<html data-motion-level="off">` |
| 优先级 | 系统「减少动效」> 产品「完整动效」；产品「关闭动效」> 每个局部样式 |
| 作用范围 | 只关闭**持续动画**与**装饰性入场**；颜色、文字、边框、图标、计数等静态等价信息全部保留 |
| 不覆盖 | 地图 / 内置浏览器模块的交互过渡（避免一条全局 CSS 规则误杀必要过渡） |
| 实现位置 | `client/src/styles.css` 末尾「P3 · 统一动效闸门与一次性反馈」（单份 `:is()` 清单，避免两处漂移） |
| 程序化滚动 | 统一走 `motionScrollBehavior()`（`client/src/界面外观.js`）：闸门命中时返回 `"auto"`，立即落定 |
| 文本揭示 | 统一走 `isMotionReduced()`：闸门命中时一帧揭示完整回复，不逐字重打 |

> 说明：闸门用属性选择器而非 `@media (prefers-reduced-motion)` 直接命中，是为了让「系统偏好」与「产品开关」共用**同一份**关闭清单。系统偏好在首帧前由内联脚本落成属性，等价于媒体查询，且不会出现两套清单漂移。

## 1. 动效登记表

| 场景 | 触发条件 | 元素 / 实现 | 持续时间 | 可中断性 | 静态回退 | 读屏播报 |

## 2. 刻意保留、收敛与新增

- **保留**：运行态低频呼吸点（已放慢至 1.8–2.6s）、会话运行指示、加载旋转（仅真实等待时可见）。
- **收敛**：「完整动效」仍是默认；跑马灯默认样式为流光，但滚动与灯效已分层，长名字一定会滚动（修复了旧版「流光覆盖滚动导致名字既被截断又不动」）。
- **新增**：面板一次性入场、结果卡一次性淡入、阶段颜色过渡、被改文件短时高亮。
- **不新增**：烟花/彩纸/成功音效、进度卡循环跳动、每 token 级动画。

## 3. 已知取舍

1. **跑马灯在关闭动效时不滚动**：按计划 4.2「关闭/减少动效时静态文字、完整标题和状态色标」，此时显示省略号，完整名字由 `title` 与无障碍树提供（组件始终写入 `title`）。
2. **文件改动高亮不做「历史回放」重播**：`fresh` 标记只在 `run_finished` 且 `runId` 等于当前活跃 run 时写入；恢复历史会话不触发，避免上百行同时闪动。
3. **结果卡淡入在历史恢复时也生效一次**：时长仅 160ms、纯 `opacity`，不构成「重播长动画」；若后续真实走查认为干扰，可改为只对最新一轮生效。
4. **闸门依赖 JS 落属性**：应用本身完全依赖 JS 运行，故不保留纯 CSS 的媒体查询副本，以避免同一份关闭清单维护两遍；内联脚本保障首帧前生效。

## 4. 回归覆盖

`npm.cmd run test:motion`（`scripts/动效治理测试.mjs`）校验：

- 跑马灯滚动层/灯效层分离，6 种样式 × 3 个档位的宿主与档位处理齐全；
- 尺寸稳定性（独立测量元素、字体晚到、`ResizeObserver`、面板开合补算）；
- 从样式表**推导**出的「无限动画清单」与期望清单完全一致（新增无限动画未纳入闸门时会直接失败）；
- 闸门清单覆盖全部持续动画宿主，且不含过期条目、不含地图/浏览器选择器；
- 闸门之后不再出现未纳管的持续动画；
- 流式揭示与程序化滚动的「立即落定」；`behavior: "smooth"` 不再硬编码；
- 一次性反馈与文件高亮的触发条件、上限与闸门覆盖。
