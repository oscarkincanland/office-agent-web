## 改动点

### 0.1 Chat 模式开放只读地图工具（核心，一行）

**位置**：`server/task.mjs:12-15`

```js
// 现状
const READ_ONLY_TOOLS = Object.freeze([
  "read", "grep", "find", "ls", "ask_user", "kb_search", "kb_read", "context_read", "skills_search", "skills_read",
  "web_search", "web_fetch",
]);
```

**改为**追加三个只读地图工具：

```js
const READ_ONLY_TOOLS = Object.freeze([
  ...现有一切,
  // 地图只读能力（D1）：查询数据集、生成临时可视化、清除临时结果。
  // 不包含 map_edit / map_import / map_save_analysis —— 写操作仅在 Work 模式。
  "map_read", "map_analyze", "map_clear_analysis", "map_datasets",
]);
```

**为什么这三个算只读**：
- `map_read`（`agent.mjs:1738`）：只读项目配置与样式。
- `map_analyze`（`:1903`）：只出临时层，不落盘；实测 Run `artifacts: []`、`touchedPaths: []`。
- `map_clear_analysis`（`:1952`）：只发前端事件，不写文件。
- `map_datasets`（本阶段新增，见 0.2）：只列数据集。

**为什么写工具不进 Chat**：`map_edit`（`:1837` 写 style.json）、`map_import`（`:1888` 写 layers/）、`map_save_analysis`（`:1940` 写 layers/）都会落盘——符合 D1"增加新图层还得 work 模式"。

**必须同步**：`scripts/任务结论事件流测试.mjs:114`（工具→分类映射表），否则该测试失败。

### 0.2 新增 `map_datasets` 只读工具

**位置**：`server/agent.mjs`（与其余地图工具同区，`:1736-1964`），并在 `:2275` 的 `AGENT_TOOLS` 与 0.1 的 `READ_ONLY_TOOLS` 同时登记。

**职责**：列出"当前可用的地图数据"——共享数据集 + 当前工作区图层 + 每个项目的图层清单。这是 D2"图层入口"在 Agent 侧的对应能力，也是 E1 验收项。

  （空）

**参数**：无（或可选 `workspace`）。**免审批**。

### 0.3 权限模型：为共享/私有图层定义规则

**位置**：`server/审批策略.mjs:18-40` 的 `DEFAULT_RULES` 数组末尾追加。

**规则**（沿用既有 `tool + pattern → action` 与"最后匹配生效"语义）：

```js
// 地图图层：共享数据集默认需授权，工作区自有图层直接放行
{ tool: "map_edit",  pattern: "shared/*",    action: "ask" },
{ tool: "map_import", pattern: "shared/*",   action: "deny" },   // 不允许往共享集里加
{ tool: "map_save_analysis", pattern: "shared/*", action: "deny" },
{ tool: "map_edit",  pattern: "workspace/*", action: "allow" },
```

**说明**：
- 现有 `map_edit` 已经调用 `requireToolApproval`（`agent.mjs:1801`），本步只是**给它更细的粒度**：把"要编辑的目标图层归属"编码进 `pattern`。
- 需要在阶段 1 的图层仓库里，把 `layerId` 解析为 `shared/<id>` 或 `workspace/<id>` 前缀，审批才能匹配到。
- 阶段 0 可先落地规则表与解析函数骨架，真正生效在阶段 1（因为现在还没有 shared/workspace 的物理区分）。

### 0.6 临时层注册表（修 X5，审查 R2 提前至本阶段）

**为什么必须在阶段 0**：0.1 开放 Chat 出图后，用户立刻会生成临时层；而 `MapViewer.applyStyle`（`:617-672`）用全量 `setStyle({diff:false})` 重建样式，其重放清单（`:669-671`）**只含 MapViewer 自管的 analysis payload**，不含 6 处外部 `getMap().addSource()` 加进去的层。中间窗口期用户会遇到"改个样式颜色，分析结果就没了"。

**新文件** `client/src/图层注册表.js`：

```js
// 登记：{ id, owner: "analysis"|"measure"|"draw"|"od"|"iso"|"route", spec }
registerTemporaryLayer(id, owner, spec)
listTemporaryLayers()
clearTemporaryLayers(owner?)
```

**重放接入点**：`MapViewer.jsx:617-672` 的重放序列

```
相机(:620-623) → 下钻(:635-647) → 底图显隐(:650-657) → 运行时标注(:658-668)
→ analysis payload(:669-671) → 【注册表其余项】← 新增
```

**幂等要求**：重放前按 `id` 移除既有 source/layer（参考现有 `analysisIdsRef`，`:360-429`）。

**迁移 6 处直接 `getMap().addSource()`**：

### 0.5 底图字形（修 X7）✅ 已按方案 B 完成

**位置**：`server/map.mjs`（`GLYPHS_URL` 常量，单一来源）。

**原状**：`https://glyphs.openfreestyle.com/{fontstack}/{range}.pbf`，域名不可解析，影响 **15 个标注图层**（`highways-label`、`roads-trunk-label`、`roads-province-label`、`boundary-city-label` 等全部道路与行政区注记），字体统一 `["Noto Sans Regular"]`。

**采用方案 B（自托管），落地三件事**：
1. `scripts/生成地图字形.mjs`：从系统 Noto Sans（`C:/Windows/Fonts/Noto Sans SC (TrueType).otf`）用 `maplibre-font-maker-node` 生成 MapLibre 兼容 SDF PBF 分片，16 个区间（基本拉丁 / 拉丁扩展 / 通用标点 / CJK 符号 / 常用汉字 12 片），输出到 `client/public/glyphs/Noto Sans Regular/`，约 2.6 MB。支持 `--check` / `--force` / `--font <path>`。
2. `server/map.mjs`：`export const GLYPHS_URL = "/glyphs/{fontstack}/{range}.pbf"`，`getDefaultStyle` 与 `getProject` 都用它；`getProject` 读取时把存量 style 的旧地址就地升级为内存新值。
3. `scripts/迁移地图字形地址.mjs`：迁移**磁盘上**的存量 `style.json`（前端地图直接读该文件，只改内存不生效）。干跑列出、`--apply` 写入；**zhejiang-map 已迁移**。

**为什么必须迁移磁盘文件**：`MapViewer` 用 `STYLE_PATH = /api/map/data/<p>/style.json` 直接 fetch 磁盘文件，服务端 `getProject()` 的内存改写对它无效——这是本次实测发现的坑（浏览器仍在请求旧域名）。

**字形区间取舍**：未生成整个 CJK 区（会产出上千 PBF、数十 MB），只覆盖常用汉字；遇到生僻字缺字形时按需在 `RANGES` 补区间并重跑（脚本幂等，`--force` 覆盖）。

**验收实测**：字形请求 `0 → 2` 次且全部 200，路径 `/glyphs/Noto Sans Regular/0-255.pbf`；`Unable to load glyph range` 告警清零；`highways-label`(4) / `roads-trunk-label`(1) / `roads-province-label`(5) 注记要素正常渲染。
