# Open Plan 桌面端前端构建规范与原型方案

## 1. 设计目标

桌面端前端不是把 Web 工作台缩进一个窗口，而是把“资料—知识—分析—成果”组织成一条可观察、可恢复、可审计的 Agent 工作流。

首版前端需要让用户在一个窗口内完成四件事：

1. 选择工作区和 Agent Profile。
2. 发起任务并看到 Agent 正在做什么。
3. 查看工具调用、执行计划和权限等待。
4. 找到最终文件、图表、报告和运行记录。

原型入口：`/?prototype=desktop`。默认入口继续使用现有交通规划工作台。

## 2. 视觉方向

采用“夜班规划控制台”方向：深石墨背景承载长时间工作，荧光黄绿只用于行动和关键状态，橙色用于等待确认，暖白色用于成果卡片和文档预览。

- 背景：深蓝黑，不使用纯黑。
- 主色：黄绿色 `#d8ff4d`，表示可执行、已连接、可继续。
- 警示：橙色 `#ff8a3d`，表示等待确认或需要关注。
- 成果：暖白 `#f4f0e6`，与 Agent 运行区形成明确层级。
- 字体：正文使用系统中文无衬线；大标题使用中文衬线字体，建立“工程控制台 + 规划报告”的区分。
- 质感：细网格、状态点、窄边框、编号标签、轻量入场动画；不使用紫色渐变和通用 SaaS 卡片堆叠。

## 3. 页面骨架

桌面端固定为三层结构：

```text
窗口工具栏
└── 应用壳
    ├── 一级导航 Rail：工作台 / 运行记录 / 模型与供应商 / 插件中心
    ├── 主工作区：当前任务、对话、工具调用和运行时间线
    └── 检查器 Inspector：执行计划 / 工作区 / 产物 / 权限
```

推荐尺寸：

- 窗口最小尺寸：`1180 × 760`。
- 左侧 Rail：`72px` 收缩态，`244px` 展开态。
- 主工作区：最小 `620px`，优先保证对话和工具事件可读。
- 右侧 Inspector：`320px`，窄屏时下沉为抽屉。
- 运行时间线使用纵向流，不把工具调用隐藏在普通聊天气泡中。

## 4. 设计 Token

所有新增桌面端组件必须使用 `--dp-*` 变量，不直接散落颜色和间距值。现有 Web 工作台继续使用既有 `--accent` 等变量，两个命名空间不互相覆盖。

| 类别 | Token | 基准值 | 用途 |
| --- | --- | --- | --- |
| 背景 | `--dp-bg` | `#091018` | 应用底色 |
| 面板 | `--dp-panel` | `#101923` | Rail、主面板 |
| 面板二级 | `--dp-panel-2` | `#14212c` | 输入区、事件卡 |
| 边框 | `--dp-line` | `#263746` | 分隔和卡片边界 |
| 文字 | `--dp-text` | `#edf1e7` | 主文字 |
| 次文字 | `--dp-muted` | `#81909b` | 辅助说明 |
| 行动 | `--dp-accent` | `#d8ff4d` | 主要按钮、在线状态 |
| 等待 | `--dp-warn` | `#ff8a3d` | 审批、风险操作 |
| 辅助 | `--dp-cyan` | `#6de4d4` | 数据、知识和连接 |
| 成果 | `--dp-paper` | `#f4f0e6` | 产物卡片、报告预览 |
| 圆角 | `--dp-radius` | `14px` | 主卡片 |
| 间距 | `--dp-unit` | `4px` | 所有间距为 4 的倍数 |

## 5. 组件分层

新增组件按以下层次组织，禁止在页面组件中直接堆叠所有业务逻辑：

```text
页面层
├── DesktopShell        窗口壳、导航、全局状态
├── WorkbenchView       当前任务和运行区
├── RunsView            运行记录和恢复入口
├── ProvidersView       模型、供应商和凭据状态
└── PluginsView         Agent Profile、Tool Pack 和权限

业务组件层
├── AgentHeader         Agent 身份、模型、运行状态
├── EventTimeline        assistant / tool / approval 事件
├── TaskPlan             可勾选执行计划
├── WorkspaceTree        工作区文件和当前上下文
├── ArtifactShelf        产物、预览和导出
└── PermissionGate       高风险操作确认

基础层
├── Icon                统一线性图标
├── Button / Badge      交互状态
├── Panel / Divider     布局容器
└── StatusDot           在线、运行、等待、失败
```

文件命名遵循现有项目规则：React 组件使用 `.jsx`，样式使用 `.css`，设计文档使用中文文件名；组件名称表达业务语义，避免 `Card1`、`PanelNew` 这类临时名称。

## 6. Agent 状态和事件规范

前端不通过猜测按钮颜色判断 Agent 状态，统一消费运行事件：

```js
{
  runId,
  type: "run.started | assistant.delta | tool.started | tool.completed | approval.required | run.completed | run.failed",
  timestamp,
  title,
  summary,
  toolName,
  riskLevel: "low | medium | high",
  artifactIds: [],
  recoverable: true
}
```

状态显示规则：

- `ready`：允许发送任务。
- `running`：显示当前工具和停止按钮，禁止重复启动同一任务。
- `waiting_approval`：固定显示审批原因、影响范围和允许/拒绝操作。
- `completed`：展示产物、运行耗时和下一步建议。
- `failed`：展示失败节点、错误摘要、重试和复制诊断信息。

## 7. 交互规范

- 任务输入必须带有当前工作区、Agent Profile、模型和输出格式上下文。
- 发送任务后，输入框变成可中止状态；不使用无反馈的“加载中”。
- 工具调用至少显示：工具名称、目标、参数摘要、耗时、结果和是否修改文件。
- 文件修改、命令执行、网络访问和删除操作按照风险等级进入 `PermissionGate`。
- 任务完成时固定显示“读取来源、修改文件、产物、假设、下一步”五项摘要。
- 双击产物打开预览；右键提供复制路径、定位文件、回滚本次运行。
- 所有重要操作支持键盘：`Ctrl/Cmd + K` 打开命令面板，`Enter` 发送，`Esc` 关闭抽屉或弹层。

## 8. 响应式和可访问性

- `>= 1280px`：三栏完整布局。
- `840px–1279px`：Rail 收缩，Inspector 变为可展开抽屉。
- `< 840px`：主工作区单栏，事件详情和产物用底部抽屉呈现。
- 交互控件最小点击区域 `32px`，主按钮不低于 `40px`。
- 状态不能只依赖颜色，必须同时有文字或图标。
- 输入框、按钮、导航项均提供可见焦点态和 `aria-label`。
- 动画默认不超过 `220ms`；检测到 `prefers-reduced-motion` 时关闭入场和脉冲动画。

## 9. 性能和工程约束

- 原型和正式页面均不得在首屏引入不必要的大型地图、图表或 Office 解析库。
- 运行时间线采用增量渲染，超过 200 条事件时按窗口裁剪或折叠旧事件。
- 产物预览和文档解析必须懒加载，失败时保留下载和定位文件入口。
- CSS 使用页面命名空间，禁止为单页新增全局 `button`、`.panel` 等泛选择器。
- 所有异步请求都要有成功、空数据、失败、重试四种状态。
- `npm run build` 和项目 `npm run verify` 是合并前门槛。

## 10. 原型验收标准

- 可以在 `/?prototype=desktop` 打开，不影响默认工作台。
- 可以切换一级导航、会话、Agent Profile、模型和 Inspector 标签。
- 可以输入任务并模拟一次运行，看到用户消息、工具调用和完成事件。
- 可以看到执行计划、工作区文件、产物和模型连接状态。
- 窄窗口下不出现横向溢出，主任务区仍可操作。
- 原型代码使用独立 `desktop-prototype` 命名空间，未覆盖现有主题和组件样式。

## 11. 皮肤系统规范

皮肤只改变颜色、字体、边框、背景纹理和局部密度，不改变任务、会话、事件、文件和产物的数据结构。所有皮肤必须通过 `--dp-*` Token 实现，禁止在组件 JSX 中判断皮肤后写两套布局。

当前原型提供四套方向：

| 皮肤 | 适用场景 | 视觉重点 |
| --- | --- | --- |
| 夜航控制台 | 默认 Agent 运行 | 深石墨、荧光黄绿、运行时间线 |
| 暖白规划稿 | 报告阅读和成果审阅 | 暖白纸张、低对比边框、衬线标题 |
| 蓝图地图作业 | GIS、OD 和数据分析 | 蓝图蓝、青色数据线、网格背景 |
| 终端信号站 | 高密度工程操作 | 等宽字体、绿色信号、紧凑信息 |

皮肤切换要求：

- 切换不刷新页面，不丢失当前会话、输入内容和 Inspector 标签。
- 用户选择写入本地 UI 偏好；正式版迁移到用户级设置文件。
- 每套皮肤都要通过文字、图标和颜色共同表达状态，不能只靠颜色。
- 新皮肤必须覆盖窗口栏、Rail、主工作区、文档区、输入区和弹层六类区域。

## 12. 网页工作区融合规范

桌面端不复制一套新的文件和对话逻辑，而是在同一窗口提供两种观察方式：

```text
Agent 控制台：任务目标 → 运行事件 → 执行计划 → 产物与权限
网页工作区：会话/文件 → 文档阅读 → ChatPanel → 知识库/模板库/地图
```

两种模式必须共享：

- 当前会话和工作区。
- Agent Profile、模型和供应商。
- 运行事件、工具调用和任务完成摘要。
- 当前文件、引用、产物和权限状态。

网页工作区保留现有 Web 版的三栏心智模型：左侧会话与文件树，中间 DocViewer 风格文档区，右侧 ChatPanel 风格对话区；知识库、模板库和地图以左侧能力入口呈现。桌面端只增加窗口壳、皮肤切换、运行观察和恢复能力。

模式切换验收：

- 从 Agent 控制台切换到网页工作区，当前会话、模型和输入内容仍然保留。
- 在网页工作区输入任务后，任务事件能回到同一个运行时间线。
- 在文档区切换文件后，上下文标签能反映当前文件。
- 从网页工作区切回 Agent 控制台，执行计划和产物状态不重置。
