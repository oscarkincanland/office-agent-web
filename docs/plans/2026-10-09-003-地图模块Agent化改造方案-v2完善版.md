## 0. 第一优先：X1 产品级断链（实测确认，一句话可修）

**问题**：地图 6 个工具只登记在 `AGENT_TOOLS`（`server/task.mjs:28`，即 Work 模式），Chat 模式的 `READ_ONLY_TOOLS`（`:12-15`）一个 map 工具都没有。而 `capability_plan` 又**正确识别**了地图意图（`:106,116`）。二者不一致的后果：

真机实测（`run_c897ebce`）：在地图模块用自然语言说"显示义乌热力图"→ `capability_plan` 标注 `map: enabled` → 但 `mode_policy` 是 chat、无 map 工具 → Agent 14 次调用全是 `ls/read/grep` → 回答"受只读模式限制无法渲染" → **地图零变化**。

**修复**：先决策语义，再改一行白名单。

| 选项 | 做法 | 效果 |
| --- | --- | --- |
| **A（推荐）** 临时可视化算只读 | `map_read` / `map_analyze` / `map_clear_analysis` 加入 `READ_ONLY_TOOLS`；`map_edit` / `map_import` / `map_save_analysis` 留在 `AGENT_TOOLS` | Chat 模式即可出图；写操作仍需 Work + 审批 |
| B 全部要求 Work | 在 `capability_plan` 把 `map` 的 `status` 从 `planned` 升级为 `required`，并在前端提示"请切到 Work 模式" | 用户多一步操作 |

**这一步必须先做**，否则后续所有 P0–P4 都没有验收场景（用户根本无法用自然语言出图）。

## 3. 目标架构（含 review 修正）

### 3.1 分层

```
① 意图层  NL → 工具调用（map_visualize / map_query / map_edit_layer）
② 计划层  可视化描述符 → { geojson, stats, styleHint }（纯函数）
③ 执行层  图层仓库（config+style 唯一写入口）
          临时层注册表（applyStyle 唯一重放源）
④ 渲染层  MapViewer（保留，只接受声明式批操作）
```

### 3.2 D1 统一可视化描述符 —— **兼容 C1**

**新增** `server/map-visual.mjs`，统一描述符：

```js
{
  v: 1,
  id, title, kind,           // flow | heatmap | choropleth | categorical | points
  geojson,                   // FeatureCollection
  stats,
  styleHint: { field, ramp, widthRange, radiusRange },
  provenance: { generatedBy, runId, at },
}
```

**关键：不替换既有端点响应（C1 兼容）。** `scripts/验证脚本.mjs:165-174` 契约了 10 个地图端点，必须全部保持 200 与原字段。做法：

- **保留** `/api/map/*` 与 `/api/m3/*` 的现有响应形状（`geojson` + `stats` 顶层）。
- **新增**统一入口 `GET /api/map/visual?dataset=&kind=&threshold=`，内部把现有端点适配为描述符。
- Agent 的 `map_visualize` 只走新入口；旧端点继续服务原有面板与验证脚本。

### 3.3 D2 图层仓库 + 临时层注册表 —— **补 M3 精确插入点**

**图层仓库** `server/图层仓库.mjs`：统一 config + style 读写，对外 `listLayers / addLayer / updateLayer / removeLayer / setStyle`。

**临时层注册表** `client/src/图层注册表.js`：
- 登记项 `{ id, owner: "analysis"|"measure"|"draw"|"od"|"iso"|"route", spec }`。
- **重放插入点**：`MapViewer.applyStyle` 的重放序列（`MapViewer.jsx:620-671`）在 **`:669` 之后、`:672` 之前**追加注册表重放，顺序为：相机 → 下钻 → 底图 → 标注 → analysis payload → **注册表其余项**。
- **幂等要求**：重放前先按 `id` 移除既有 source/layer（现有 `analysisIdsRef` 是同类做法，`:360-429`）。
- **禁止** `getMap().addSource()`：需迁移 `MapPanel.jsx:296-318, 931-1009, 1089-1123` 与 `M2宏观分析.jsx:25`、`M3公交分析.jsx:21`、`柬埔寨OD面板.jsx:40`。

### 3.4 D3 图层寻址选择器 —— **修正 E2**

`map_edit_layer`（在 `map_edit` 基础上扩展，不新建工具）的 target 接受：
- `id:highways`
- `group:公路网`
- `name:~高速`

**理由**：`map_edit` 已有 `setVisibility`/`setPaint`/`move`/`add` 四个动作与审批锁（`agent.mjs:1779-1784, 1801, 1837`），只需把 `layerId: String` 放宽为选择器解析。**不新建工具**，避免 C4 的白名单膨胀。

### 3.5 D4 工作区语义 —— **按 Q1 决策，且复用 M1 既有链路**

**Q1 选 A（推荐，改动小）**：
- 保持 `MAPS_ROOT = WORKSPACE_DIR/maps`（`server/map.mjs:19`）不变，不动 346 MB 存量，`工作区隔离回归测试` 不受影响。
- 新增 `map_datasets` 工具：列出**当前 `task.mapProject` 可用项目 + 每个项目的图层清单**。
- Agent 的"当前地图项目"继续走既有 `task.mapProject` 链路（`task.mjs:137,164`），**不另起一套**。

**Q1 选 B**：
- 需 `MAPS_ROOT` 从常量改为函数 `mapsRoot(workspace)`；**同步改写** `scripts/工作区隔离回归测试.mjs:51`（`mapsRoot` 来源）与 `:70-118` 五个用例。
- 需迁移策略（复制 or 软链 or 仅新建走新路径），346 MB 存量数据要给出迁移脚本与回滚。

**补 M2**：`App.jsx:188-190` 的 `mapContexts` 按 thread 存，导致**换会话回退默认项目**。方案需明确：是否把"当前地图项目"提升为按 workspace 存（与 Q1 答案联动）。

### 3.6 D5 写操作分级 —— **修正 E1（全部已有审批）**

| 操作 | 现状 | v2 动作 |
| --- | --- | --- |
| 改样式（`map_edit`） | ✅ 已审批（`agent.mjs:1801`）+ 写入锁 | **无需新增** |
| 导入图层（`map_import`） | ✅ 已审批（`:1875`）+ 写入锁 | **无需新增** |
| 保存分析（`map_save_analysis`） | ✅ 已审批 + 写入锁 | **无需新增** |
| 生成临时可视化 | 无（不落盘） | 保持无审批 |
| 新增 `map_visualize` | 新增工具 | **免审批**（只读数据 + 出临时层）；保存仍走 `map_save_analysis` |
| 新增 `map_datasets` | 新增工具 | 免审批（只读） |

### 3.7 G2 可追溯 —— **补 C2/C3**

- **C2**：`map_action` 是 `persist: false`（`事件注册表.mjs:97`），刷新后消失。若要 G2，需**新增落盘事件类型 `map_visualization`**（登记到 `事件注册表.mjs`，`persist: true`），并在前端事件展示注册表（`client/src/事件展示.js`）登记。**不修改 `map_action` 的 persist 设置**（会改变既有行为）。
- **C3**：地图图层写在 `maps/<project>/layers/*.geojson`，需验证是否被 `isInternalChangePath`（`运行展示投影.js:91`）判为 internal。若判为 internal，则 G2 的"在本轮产物可见"不成立，需要：① 确认产品上是否希望地图图层进产物；② 若不希望，G2 表述改为"可在图层仓库的版本记录里追溯"。
