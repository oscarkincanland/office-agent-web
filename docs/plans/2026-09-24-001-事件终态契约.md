# 事件终态契约（P0）

本文件是 [任务结论、事件流、对话层级与工具图标完整修改计划](2026-09-24-001-规聚任务结论事件流与工具图标完整修改计划.md) 第三节“共享产品契约”的落地版本。**先定契约、再改代码**；服务端与前端都以此为准。行号不是永久定位依据，代码演进后以符号名为准。

## 一、四层状态：唯一问题、唯一来源、写入位置

| 层 | 唯一问题 | 权威来源 | 写入位置 | UI 文案原则 |
| --- | --- | --- | --- | --- |
| Pi 回合 | 模型当前推理回合是否结束？ | Pi SDK `agent_settled` / `agent_end` | `server/agent.mjs` 事件桥（仅 SSE，不落“任务完成”） | 内部轨迹；只作阶段/进度，不写“任务完成” |
| Run 生命周期 | 本次运行是否仍在执行、等待、取消或已终结？ | `run.status` + `run_finished` 事件 | `server/runs.mjs` `finishRun()` | “运行结束/失败/已取消”，不偷换成目标达成 |
| 任务达成 | 用户目标成功、部分完成、受阻还是失败？ | `complete_task` 显式声明；缺失时 `inferCompletion` 保守推断；**须与客观结果一致** | `run.completion`（`finishRun` 收口） | 显示 `source`（模型声明/系统推断）；partial/blocked 不得用成功色 |
| 成果验收 | 文件、操作、交付物实际检查到什么程度？ | 发布前预检 + 显式校验 | `run.verificationStatus` / `run.validations` | 已验证/失败/未验证分别表达，不用绿勾替代证据 |

## 二、时序与写入路径（正常 / 缺声明提醒 / 失败 / 取消 / 重连）

1. **正常工具任务且调用 `complete_task`**
   `run_started` → `prompt`/`capability_plan` → `tool_start`/`tool_end` → `complete_task` 归一化写入 `entry.pendingCompletion`（带 `runId`）→ `agent_settled` 发 `assistant_final`（SSE）→ `run_finished`（`finishRun`）。Run Store 中 `assistant_final` **至多一条**，`completion.source = "explicit"`。
2. **缺 `complete_task` 触发收尾提醒**
   主回合结束后，`_promptEntry` 追加一次**声明专用**短回合（`COMPLETION_NUDGE_PROMPT`）。该回合 `entry.suppressFinalText = true`：**不得覆盖**主回合终稿、**不得**追加第二条 `assistant_final`。Run Store 终稿仍为主回合文本。
3. **产物验收失败、模型仍声明 success**
   `finishRun` 计算 `verificationStatus` 后调用 `applyObjectiveDowngrade`：`success` 下调为 `partial`，记录 `downgradedFrom`/`downgradeReason`；Run 全部产物不可发布时 `status = failed`。
4. **取消与迟到事件**
   `requestRunCancellation` → `run.status = cancel_requested`；`finishRun` 终态单调（已终结直接返回）。迟到 `assistant_final` 只补充诊断；`run_finished` 不改写终态。取消 → `completion.status = "cancelled"`。
5. **SSE 断线 / 重复 / 历史重放**
   终稿写入走 `recordRunFinalText` 幂等键：`runId + assistant_final 稳定事件`。相同文本 → no-op；文本被修正 → **更新同一条事件**（`version` 递增），不新增气泡。

## 三、终态枚举与来源

- `run.status`（终态，单调不可回退）：`completed` | `failed` | `cancelled` | `aborted`。
- `completion.status`：`success` | `partial` | `blocked` | `failed` | `cancelled`。
- `completion.source`：`explicit`（模型 `complete_task`） | `inferred`（系统按 Run 终态推断）。
- `completion.verification`：模型声明的验证说明（字符串，可为 null）。
- `run.verificationStatus`：`passed` | `warning` | `failed` | `not_checked`。
- 客观降级字段：`completion.downgradedFrom`、`completion.downgradeReason`、`completion.objectiveStatus`。

## 四、终稿幂等键与字段

`assistant_final` 事件 `data`：

| 字段 | 含义 |
| --- | --- |
| `text` | 权威最终回复全文 |
| `runId` | 归属 Run（跨 Run 隔离） |
| `messageId` | 稳定幂等键（默认 `final_${runId}`） |
| `version` | 文本版本；修正时递增，不新增事件 |
| `source` | 写入来源（`agent` / `run_finish` / `replay`） |

`run.finalText` / `run.finalMessageId` / `run.finalTextVersion` 为 Run 根级同名投影，供 `run_finished.finalText` 兜底与前端断线补齐。

## 五、优先级与不可违背的规则

1. `prefers-reduced-motion: reduce` 最高；产品“关闭动效”高于局部样式（延续 P3 动效计划）。
2. 取消 / 运行失败 / 写入或发布失败 / 验收失败等**客观结果可下调**声明结论。
3. 模型 `complete_task: success` **不可上调**客观失败。
4. `run_finished` 一旦发出，该 Run 终态单调不可回退；迟到事件只能补充诊断，不得把失败改成功。
5. `agent_end` ≠ `run_finished`。
6. `partial` / `blocked` 不能用 success 色。
7. 缺少证据显示“未验收”，不伪造成功。
8. 每个 `runId` 至多一个用户可见权威终稿；文本相同不是跨 Run 去重依据（用户可能连续提同一问题）。
9. 旧事件缺字段时保守展示（缺失 `completion` → 按 `run_finished.status` 推断，标 `inferred`）。

## 六、兼容与回滚

- 旧会话：无 `messageId` 的 `assistant_final` 按 `runId + 事件 seq` 回退识别；**不迁移、不改写用户历史**。
- 发布分批：先上后端契约与兼容读取，再上前端展示，最后开图标；旧客户端能读新事件、新客户端能读旧历史。
- 若终态回归失败，回滚新展示并保留原事件存储；**不得删除或重写用户 Run/会话历史**。图标/入场动效退化只撤该视觉改动。
