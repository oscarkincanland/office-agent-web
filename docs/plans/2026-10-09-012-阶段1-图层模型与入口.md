# 阶段 1 · 图层模型与图层入口

上级：`2026-10-09-010-地图与Agent平台化-总体计划.md`。依赖：阶段 0。

---

## 目标（D2）

> 地图既有的数据集（高速公路/国省道等）**共用**；只有**有权限才能编辑**；**每个工作区对应自己的图层管理**；需要一个**图层入口**。

拆成三件事：
1. **共享数据集与工作区图层物理分离**（共用、只读、可授权编辑）。
2. **图层仓库**——合并 `map.config.json` + `style.json` 的双写入口，消灭"真相两半"。
3. **图层入口**——用户与 Agent 都从一个地方进出图层管理。

**已有的基础**（不要重造）：`createProject({ baseProject })`（`map.mjs:493`）默认派生自 `zhejiang-map`；`getDefaultStyle(project, baseProject)`（`:305`）让基础路网的 tiles URL 指向基础项目；`defaultConfig`（`:348`）已记录 `baseProject` 并在注释里写明"基础路网可复用已有项目；业务图层、配置和 Run 产物仍归当前项目"。**本阶段把它从"派生时复制"升级为"运行时引用 + 权限区分"。**

## 改动点

### 1.1 路径模型：共享根 + 工作区根

**位置**：`server/map.mjs:19`

```js
// 现状：单一根，硬绑默认工作区（X6）
const MAPS_ROOT = path.join(WORKSPACE_DIR, "maps");
```

**改为**：

```js
const SHARED_MAPS_ROOT = path.join(WORKSPACE_DIR, "maps");          // 共享数据集（保持现状，不动 346MB 存量）
export function workspaceLayersRoot(workspace) {                     // 工作区私有图层
  const ws = String(workspace || WORKSPACE_DIR);
  return path.join(ws, "map-layers");
}
```

**兼容策略（关键）**：
- **共享根保持不变**（`office-workspace/maps/`），`zhejiang-map` 就是共享数据集。这样 `scripts/工作区隔离回归测试.mjs:51` 的 `mapsRoot` 与 `:70-118` 五个用例**不需要改写**。
- 工作区图层是**新增目录** `<workspace>/map-layers/`，与共享根并列、互不干扰。
- 若工作区就是默认工作区（`office-workspace`），两个根在同一父目录下——这是允许的（"默认工作区"拥有自己的私有图层 + 可读共享数据集）。

### 1.2 图层仓库（新模块）

**新文件** `server/图层仓库.mjs`。

**职责**：把 `map.config.json`（业务元数据：id/name/type/group/visible）与 `style.json`（渲染：paint/layout/order）的读写合并成单一入口，并统一"共享 + 工作区"的合并视图。

**对外接口**：

```js
// 合并视图：共享图层（只读）+ 工作区图层（可写）
listLayers(workspace, { project })        → [{ id, name, type, group, visible, origin: "shared"|"workspace", scope, editable }]
resolveLayer(workspace, selector)         → { ref: "shared/highways" | "workspace/my-layer", layer }
addLayer(workspace, { project, id, geojson, name, group })
updateLayer(workspace, ref, patch)        → 写 style.json / config.json
removeLayer(workspace, ref)
setStyle(workspace, { project, style })
```

**关键**：`resolveLayer` 返回的 `ref` 就是阶段 0.3 审批规则的 `pattern` 输入（`shared/*` / `workspace/*`）。

### 1.2b 共享数据集的编辑授权流程（审查 R5）

D2 要求"只有在我自己的权限下才可以编辑"。具体流程：

| 问题 | 做法 | 依据 |
| --- | --- | --- |
| 如何获得权限？ | **逐次审批**：`map_edit` + `shared/*` → `ask`，用户在弹窗确认 | `审批策略.mjs:7-9` 的 opencode 式模型 |
| 能否持久授权？ | **可以**：用户选"总是允许" → 追加一条 allow 规则到 `.oaw/permissions.json` | `审批策略.mjs:8-9` 明确写了这个交互 |
| 能否写进共享集？ | **禁止**：`map_import` / `map_save_analysis` + `shared/*` → `deny` | 共享数据集只接受"改样式"，不接受新增文件 |
| 无权限表现？ | 明确拒绝 + 说明"这是共享数据集，编辑需授权，或先保存到『我的图层』" | 避免静默失败 |

**与既有交互的一致性**：这与 Office 写入（`officecli set *` → `ask`）的体验相同——用户已经熟悉"改共享的东西要确认"。

列表接口**保留选择器**（供 Agent 用，D2 的"按数据集/分组操作"）：

| 形式 | 例 | 说明 |
| --- | --- | --- |
| `id:` | `id:highways` | 精确匹配图层 id |
| `group:` | `group:公路网` | 匹配 config 的 `group` 字段（实测图层树已有 4 个分组） |
| `name:~` | `name:~高速` | 名称模糊匹配 |
| `origin:` | `origin:shared` | 按归属筛选（共享 / 工作区） |

### 1.3 `map_edit` 支持选择器 + 归属前缀

**位置**：`server/agent.mjs:1773-1800`（`map_edit`）。

- 把 `layerId: Type.String(...)`（`:1785`）扩展为 `target: Type.String(...)`，走 1.2 的 `resolveLayer`。
- 审批前先解析出 `ref`，用 `ref` 作为 `pattern` 调用 `requireToolApproval`（`:1801`）。
- **保持向后兼容**：`layerId` 仍接受（映射为 `id:<layerId>`）。

### 1.4 图层入口（用户侧）

**这是 D2 明确要求的部分。** 设计三层入口：

| 入口 | 位置 | 面向 |
| --- | --- | --- |
| **主入口**：地图模块左栏图层树 | `MapPanel.jsx:1663-1689` → `LayerPanel.jsx` | 已在，需改造分组 |
| **快捷入口**：能力菜单 | `App.jsx:1695-1705`（`onMap={() => openExternalModule("map")}` 附近） | 从任意界面一步到地图 |
| **工作区入口**：文件侧栏 | `SessionSidebar.jsx` 文件页顶部工具条 | 让"图层"在工作区语境下可见 |

**图层树改造**（`LayerPanel.jsx`）：

```
▸ 共享数据集（只读）               ← 新增分组
    🔒 地市边界（面）
    🔒 高速公路（线）
    🔒 国省道（线）
▸ 我的图层（可写）                 ← 现有图层移入
    📄 my-od-20261009（线）
    📄 导入数据-1（点）
▸ 临时层（本次会话）               ← 新增分组
    ✨ 义乌热力图（未保存）
```

- **锁图标**：共享图层不可编辑时显示 `🔒`，悬停说明"共享数据集，编辑需授权"。复用现有 `Icon`（`icon-lock` 已存在，`Icon.jsx:39`）。
- **分组头计数器**：沿用现有 `lp-group-head` 样式与语义（实测有 4 个分组）。
- **组级复选框**：现有组头复选框是展开/折叠语义，**不要改成显隐**（实测已确认，改会破坏用户肌肉记忆）。

### 1.5 工作区切换时图层树跟随（修 X6）

**位置**：`client/src/App.jsx:678-725`（`handleWorkspaceChange`）+ `MapPanel.jsx` 数据加载。

- MapPanel 新增 prop `workspace`（`App.jsx:1390-1416` 已传 `workspace` 给 MapPanel？需确认，若无则补）。
- 工作区切换后，图层树重新拉取：`listLayers(newWorkspace, { project })`。
- **共享数据集不随工作区变**（这正体现"共用"）。

### 1.6 修复 X4：清理 `style.json` 残留层

实测 `zhejiang-map/style.json` 有 27 个非底图样式层，其中 `drawn-*`(3)、`__codex_shp_test__-label`、`yiwu-od-lines-style`、`highway_flow*`(4) 等属历史残留。

- 提供一次性清理脚本：`scripts/清理地图残留层.mjs`（列出可疑层 → 人工确认 → 删除）。
- **不自动删**：先输出清单让用户确认（可能含在用的图层）。

## 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 共享/工作区读写混淆 | 写错目录会污染共享数据集 | 仓库层强制 `origin` 前缀；写操作先 `resolveLayer` 再校验 |
| `zhejiang-map` 被当作"工作区图层" | 它是共享数据集，但物理上与默认工作区同级 | 用 `map.config.json` 的 `shared: true` 显式标记 |
| 图层树分组变化影响现有用户 | 现在只有"图层组"概念 | 保留现有"图层组"（用户自定义分组），新增的是**归属分组**（共享/我的），两者层级不同：归属在顶层，图层组在内层 |

**与原计划的偏离（均为实现中发现）**：

1. **归属数据不搬家**。原计划 1.1 要新增 `<workspace>/map-layers/` 物理目录，实际改为「数据物理位置不变，归属记在 `map.config.json` 的 `origin`/`owner`」。原因：瓦片构建、`style.json` 组装、静态路由、`hydrateBasemapSources` 四处都绑定项目目录，搬家需同时改四处且会拆散"一个项目一份瓦片"的结构。语义等价、风险低得多。「每个工作区对应自己的图层管理」由 `listLayers` 的 owner 过滤实现。
2. **残留判据改为"数据源是否缺失"**。仅按 id 模式（`drawn-*`/`__*`）会漏掉 `roads-rural`、`roads_flow_all_sp-label` 这类命名不显眼但数据已丢失的层。现在的判据是"引用的 source 不存在，或 source 的瓦片目录/GeoJSON 已删除"，更准且不会误删仍在用的层。
3. **临时层清单是新增能力**（计划里只提到分组）。用 `MapPanel` 内的 `syncTempLayers` 从地图实例读实际存在的临时图层（OD/等时圈/路径/绘制/分析），只读展示，不提供删除或保存入口。

**验证**：`scripts/地图图层模型与入口测试.mjs`（44 条断言，已进 `test:map-layers`）+ `scripts/地图图层入口场景测试.mjs`（真实 Chromium，覆盖 B1/B2/B3 与跨工作区隔离，`test:map-layers:live`）。阶段 0 的 L2 回归、`verify`、`任务结论事件流`、`工作区隔离回归`、`主任务流`、`对话流性能`、`审批作用域`、`SSE 协议`、`成果可信度` 均保持通过。

**对照计划补齐的四项（2026-10-10 二次核对）**：

1. **三个图层入口齐全**（§1.4 表）：主入口（左栏图层树）+ 快捷入口（能力页/命令面板）+ **工作区入口（文件页工具条新增「图层」按钮）**——第三项此前缺失，已补。
2. **Agent 视角的归属隔离**（D2/E1）：`map_read` 与 `map_datasets` 此前直接列全部图层，会暴露其他工作区的图层。现在两者都走 `图层仓库.listLayers(project, { workspace })`，只列共享数据集 + 本工作区自有图层，并标注归属（共享/我的）。
3. **产物归属可确认**（E4）：`map_import` / `map_save_analysis` 的 `write_started` 此前记的是项目目录（`maps/<project>`），而产物归属按**精确路径**匹配——保存的图层因此只会落到"待确认"（run-window）。现在逐文件记台账（图层 GeoJSON + style.json + map.config.json，含 `-lines` 派生层）。
4. **B5 的语义已满足、物理位置按 §1.1 的偏离**：原计划"保存到我的图层 → 落到 `<workspace>/map-layers/`"；实际落到 `maps/<project>/layers/` 并记 `origin=workspace + owner`（理由见上文"与原计划的偏离"第 1 条）。前端「我的图层」分组与工作区隔离行为一致。
