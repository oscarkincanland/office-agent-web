## 0. 开工前的三条确认

每阶段开工前跑一次，避免"基于过期状态动手"：

```bash
# 1. 工作区是否被其他会话写入（本仓库有并发开发）
git status --short
# 2. 目标文件是否被并发改动（看 mtime）
node -e "const fs=require('fs');for(const f of ['server/task.mjs','server/map.mjs','client/src/components/MapPanel.jsx','client/src/styles.css']){const s=fs.statSync(f);console.log(new Date(s.mtime).toLocaleString(),f)}"
# 3. 服务是否在跑（改后端需重启）
curl -s http://127.0.0.1:3002/api/status
```

**若有并发改动**：先等对方落定（或在其提交后再动手），不要把两边改动混在一起提交。

## 7. 提交策略

| 阶段 | 提交方式 |
| --- | --- |
| 0 | **分 6 个提交**（白名单 / map_datasets / 审批规则 / 注册表 / 模式切换 / 字形），每个可单独回滚 |
| 3 | 2 个提交（能力标注 / 提示文案+断言） |
| 1 | 5 个提交（路径 / 仓库 / 选择器 / 入口 / 清理脚本） |
| 2 | 5 个提交（确认 / 描述符 / 面板 / 顶栏 / 删旧） |
| 4 | 4 个提交（样式 / 状态行 / 图标 / 结果提示） |
| 5 | 3 个提交（适配层 / 适配器 / 接入） |

**每个提交前**：`npm run build` + 相关 `test:*` 全绿。
**每阶段结束**：更新 `变更日志.md` + 跑该阶段的 L3 浏览器场景。
