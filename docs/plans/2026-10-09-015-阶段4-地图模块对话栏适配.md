# 阶段 4 · 地图模块对话栏适配（轻量）

上级：`2026-10-09-010-地图与Agent平台化-总体计划.md`。依赖：阶段 0（模式切换）。

**修订说明（按用户 2026-10-09 澄清）**：本阶段**不是**对 `ChatPanel.jsx` 的整体重构。
- ❌ 不拆 5200 行、不改 SSE 链路、不动消息流主体、不动 `对话流性能回归测试.mjs` 的 118 条断言。
- ✅ 只做**地图模块内**对话栏的**样式与布局适配**，让它在 GIS 工作区里更合适、更精简。

因此本阶段**风险等级从"高"降为"低"**，且不再需要独占期。

---

## 目标

在地图模块里，对话栏要同时满足两件互相拉扯的事：
1. **不抢地图的地方**——地图是主角，对话是辅助。
2. **能让 Agent 出图**——用户在这里说一句话，地图上要出现结果。

## 改动点

### 4.1 地图场景的紧凑呈现（样式为主）

**现状问题**：地图里对话栏默认 420px + 完整工具栏（上下文组 + Agent 模型组 + 会话组），在 GIS 工作区里占位偏多。

**做法**（**只加 CSS + 传 prop，不改组件结构**）：

| 项 | 做法 |
| --- | --- |
| 默认宽度 | `--map-chat-w` 由 420px 收紧到 **360px**（用户仍可拖到 620px） |
| 紧凑模式 | 地图模式下给全局实例传 `compact`（现在只有 MapPanel 内那个被屏蔽的实例传了） |
| 工具栏精简 | 用 CSS 在地图场景隐藏低频组：`.app-chat-slot.map .toolbar-*-group` 选择性 `display:none`（保留：模型选择、发送、模式切换、地图上下文按钮） |
| 消息列宽 | 地图场景下放宽消息列占比（现在样式是通用值），减少换行 |

**落点**：`client/src/styles.css` 新增一节 `.app-chat-slot.map` 的覆盖规则。

### 4.2 地图上下文常驻可见（提升"能出图"的感知）

**现状**：视口上下文（`mapContext`）只在输入框旁有个按钮（`ChatPanel.jsx:3437`，`title="将当前地图视图加入下一轮上下文"`），且需手动点。

**做法**：
- 地图模式下在对话栏顶部显示一行**当前地图状态**：`地图项目: zhejiang-map · 视口: 义乌市附近 · 缩放 9`。
- 数据源：`mapContext`（`App.jsx:1304` 已传） + `currentMapProject`（`:190`）。
- **不新增 state**，纯展示，复用现有 props。
- 作用：用户知道 Agent"看得见"当前地图，才敢说"就画这里"。

### 4.3 工具调用的地图语义标识

**现状**：工具卡（`ToolCard`，`ChatPanel.jsx:5145`）对 `map_*` 工具显示通用卡片，用户看不出"这个工具在改地图"。

**做法**（**小改，不动渲染架构**）：
- 复用已有的 `ToolIdentityIcon`（`ChatPanel.jsx:5` import 自 `工具语义图标.jsx`）——若 `map_*` 未登记，补登记（`map_read`/`map_edit`/`map_import`/`map_analyze`/`map_save_analysis`/`map_clear_analysis`/`map_datasets`）。
- 地图工具卡片加一个轻量标记（如左侧色条），与普通文件工具区分。
- **注意**：`工具语义图标.jsx` 是既有单一来源（阶段 4 的规范 §1.3 规范 5），不要另建映射。

### 4.4 结果区的地图产物呈现

**背景**：阶段 0.1 开放 Chat 出图后，临时可视化是"不落盘"的（`map_action` 是 `persist:false`），Run 的 `artifacts` 为空（实测确认）。用户会问"我刚画的那层呢？"

**做法**：
- 结果区加一行轻提示：`已在地图上显示「义乌市点位热力图」（临时，未保存）`，附「保存为图层」按钮。
- **按钮行为**：Chat 模式 → 提示切 Work（阶段 3 的能力划分）；Work 模式 → 调用 `map_save_analysis`。
- 数据源：`map_action` 事件（前端已有 `handleMapAction`，`MapPanel.jsx:1352`）。
- **不改 SSE**，复用现有事件。

### 4.5 与阶段 2 的边界

阶段 2 会新增"可视面板"。**分工**：
- **可视面板**（阶段 2）：结构化入口——选数据集、看图层清单、管理图层。
- **对话栏**（本阶段）：自然语言入口——说一句话出图。

两者不重复：对话栏不做图层管理（那是左栏/可视面板的事），可视面板不做对话（那是对话栏的事）。

## 附：为什么原方案的重构建议被撤回

原阶段 4 建议把 5200 行拆成 5 个分区组件，理由是"不精简"。核对用户意图后确认：
- 用户要的是**地图模块内的前端设计优化**，不是对话栏整体重构。
- 且实测有 **118 条**源码文本断言依赖单文件结构，拆分成本高于收益。

**该重构作为独立议题保留**（若未来确有必要，参考本文"明确不做"清单与旧版方案 `docs/plans/2026-10-09-015` 的历史版本）。

**审查发现的边界问题（已如实记录）**：地图模块与主对话是两个挂载点（`.app-chat-slot.map` / `.center-chat-slot`），切换模块会重新挂载对话栏——服务端已持久化的历史会重新水合，而**仅本地的系统提示**（如 map_action 的一次性提示）不保留。这是既有结构，不是本阶段引入；真实对话消息不受影响。

**测试**：`test:map-chat`（源码断言 + 红线检查）+ `test:map-chat:live`（真实 Chromium：宽度 360、拖拽 300–620、状态行、临时未保存提示、Chat 模式切 Work 提示、退出后对话栏连续）。前者已进 CI。
