## 3. 目标架构

### 3.1 三层数据模型（回应 D2）

```
┌─ 共享数据集（只读，跨工作区共用） ────────────────────┐
│  office-workspace/maps/_shared/zhejiang-base/        │
│    layers/{boundary-*, highways, roads-trunk, ...}   │
│    tiles/...                                         │
│  map.config.json { shared: true, writable: false }   │
│  → 所有工作区可见可叠加；编辑需显式授权                │
└──────────────────────────────────────────────────────┘
                       ↓ 引用（不复制文件）
┌─ 工作区图层（可写，随工作区切换） ────────────────────┐
│  <workspace>/map-layers/                             │
│    my-*.geojson         用户导入 / Agent 生成         │
│    refs.json            引用哪些共享图层（tiles 指向共享）│
│  权限：工作区所有者可写                                │
└──────────────────────────────────────────────────────┘
                       ↓ 分析产出
┌─ 临时层（不落盘） ────────────────────────────────────┐
│  分析 / 测量 / 绘制结果；注册表统一管理（修 X5）        │
└──────────────────────────────────────────────────────┘
```

**图层权限模型**（复用 `审批策略.mjs` 的 `tool+pattern`）：

| 图层来源 | 读 | 改样式 | 删除 | 审批规则 |
| --- | --- | --- | --- | --- |
| 共享数据集 | 所有人 | 需授权 | 需授权 | `map_edit` + `pattern: "shared/*"` → `ask` |
| 工作区图层 | 当前工作区 | 可写 | 可写 | `map_edit` + `pattern: "workspace/*"` → `allow` |
| 临时层 | 当前会话 | — | — | 无（不落盘） |

### 3.2 Chat / Work 职责划分（回应 D1）

| 模式 | 地图能力 | 工具 |
| --- | --- | --- |
| **Chat**（查询） | 读数据集、查图层、做**只读分析并出临时可视化**、总结 | `map_read`、`map_analyze`、`map_clear_analysis`、`map_datasets`（新增，只读） |
| **Work**（操作） | 上述全部 + **新增/修改/删除图层** | 上述 + `map_edit`、`map_import`、`map_save_analysis` |

**实现**：`task.mjs:12-15` 的 `READ_ONLY_TOOLS` 追加三个只读地图工具（一行改动），写工具保持在 `AGENT_TOOLS`。

**配套（修 X2）**：地图模块顶栏加模式指示与快捷切换，用户不必返回主对话。

### 3.3 对话栏设计规范（回应 D4）

`ChatPanel.jsx` 5200 行的拆分目标：

```
ChatPanel（容器，~600 行）
├─ 对话流     ChatStream      消息列表 + 虚拟化窗口
├─ 过程区     ProcessSection  思考/工具/执行过程（现有 foldedProcessBlocks 逻辑抽出）
├─ 结果区     ResultSection   结论 + 本轮产物 + 文件改动（现有 RunSummary 抽出）
├─ 输入区     Composer        输入框 + 工具条 + 待处理条
└─ 顶部栏     ChatTopbar      模型/模式/上下文环/审批模式
```

**规范要点**（细节见阶段 4 文档）：
- 每个分区一个组件文件，props 显式，禁止跨分区直接读写 state。
- 工具调用统一走「工具卡片」单一渲染入口（现在 `ToolCard` + `ExecutionFlow` + `SubagentCard` 三处各自渲染）。
- 流式更新只 patch 对应分区（现有 `MemoMessage` 的 memo 策略保留并扩展）。

### 3.4 交通流量数据接口预留（回应 D5）

**核心思路**：不预设数据格式，而是定义**数据源适配层**。

```
server/交通数据源.mjs   （新增）
  registerSource({ id, kind: "od-flow"|"traffic-flow"|"speed", load(params) })
  listSources()
  loadSource(id, params) → 统一描述符
```

内置一个 `local-file` 适配器（读工作区里的 CSV/GeoJSON），未来接入实时接口时只加适配器，不改上层。

## 6. 全局约束

1. **不改既有 API 响应形状**（`验证脚本.mjs:165-174` 契约 10 个地图端点）。新增字段可以，改结构不行。
2. **新增地图工具必须同步** `scripts/任务结论事件流测试.mjs:114` 的工具分类表。
3. **不删 `zhejiang-map`**（`工作区隔离回归测试.mjs:108-109` 断言它受保护）。
4. **`server/runs.mjs` 有并发改动**，与其相关的部分（产物归属）只复用不新增判定分支。
5. **每阶段结束跑**：`verify` + 该阶段文档列出的受影响测试。
