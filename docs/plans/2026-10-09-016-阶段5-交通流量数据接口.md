## 设计：数据源适配层

### 5.1 新模块 `server/交通数据源.mjs`

```js
/**
 * 交通数据源适配层。
 * 每个数据源实现统一的 load(params) → 可视化描述符（阶段 2 §2.1 的形状）。
 * 新增数据源 = 新增一个适配器，不改上层。
 */

export function registerSource(adapter)   // { id, label, kind, paramsSchema, load }
export function listSources()             // 供 Agent 的 map_datasets / 可视面板发现
export function loadSource(id, params)    // → 描述符
```

### 5.2 内置适配器（本阶段交付）

| id | kind | 数据载体 | 说明 |
| --- | --- | --- | --- |
| `local-file` | `*` | 工作区里的 CSV / GeoJSON | **通用兜底**：用户丢一个文件进来就能画 |
| `bundled-xinchang` | `od-flow` | `server/xinchang-data/` | 把现有 M3 数据源包装为适配器（验证接口可用） |

**`local-file` 的定位**（关键）：交通流量数据很可能就是"一段时间的车流量 CSV"。本适配器负责：
- 自动识别经纬度/起点终点列（复用 `MapPanel.jsx:236-245` 的 `detectCols` 思路）；
- 数值列自动分级（复用 `LayerPanel.jsx:249-273` 的 `match`/`step` 表达式构造）；
- 输出描述符交给统一渲染。

### 5.3 未来接入点（本阶段只留桩，不实现）

| 预留位 | 形态 | 适配器要做的事 |
| --- | --- | --- |
| 实时交通流 API | HTTP 轮询 / SSE | 实现 `load()` 拉取 → 转描述符；`kind: "traffic-flow"` |
| 数据库直连 | SQL / PostGIS | 实现 `load()` 查询 → 转描述符；注意**不要**在 Phase 1 引入数据库依赖 |
| 车载 GPS 轨迹 | 大文件流式 | `load()` 分片读 + 抽稀（参考 `scripts/prepare-map-data.mjs:41-48` 的 simplifyLine） |

### 5.4 与 Agent 的接口

- `map_datasets`（阶段 0 新增）列出**适配器 + 数据集**，让 Agent 知道"有哪些流量数据可画"。
- `map_visualize`（阶段 2 的 `/api/map/visual`）接受 `dataset` 参数指向适配器 id。
- **只读数据源无需审批**；数据源若涉及写回（如修正后的流量数据），走阶段 0 的权限模型。

### 5.5 数据落地位置（与阶段 1 联动）

| 数据类型 | 位置 | 理由 |
| --- | --- | --- |
| 共享流量基础数据（如全省路网流量） | `office-workspace/maps/_shared/` | 跨工作区共用 |
| 用户导入的流量数据 | `<workspace>/map-layers/` | 私有 |
| 分析产出 | 临时层（不落盘）→ 用户确认后 `map_save_analysis` 落 `map-layers/` | 与阶段 1 一致 |

**验收对照**：

- G1「丢一个车流量 CSV 到工作区，说'画这个流量'」：适配器能自动识别列并出图（测试真造 CSV 验证）；Agent 侧可用 `map_analyze` + `dataSource=local-file` 触发。
- G2 `map_datasets` 列出 `local-file` / `bundled-xinchang`：✅
- G3 新增适配器只需实现 `load()`：测试用测试桩验证（含裸 GeoJSON 自动包装、抛错不冒泡）。
- G4 现有分析全部可走适配层：M2 / M3 / 柬埔寨 / 演示四类都产出了统一描述符（形状断言）。

**审查发现并已修复的数据层缺陷**（安全与正确性）：

1. **CSV 空单元格 → 坐标 (0,0)**：`Number("")` 为 0，Excel 导出的空行会在地图上造出几内亚湾的假点并污染统计。现在显式判空 + 中国坐标范围兜底（70–140E / 15–56N），错误信息回传跳过行数。
2. **同前缀兄弟目录绕过工作区边界**：字符串 `startsWith` 改为 `path.relative` 目录边界判定。
3. **业务列丢失**：路段名称、方向等非坐标非数值列现在带进 properties（地图标签与属性表要用）。
4. **x/y 列名误判**：`max_value` / `min_y` 不再被当成经纬度（单字符别名改精确匹配）。
5. **统计口径**：`stats.count` 恒为要素数，有值数单列 `valueCount`。

**测试**：`scripts/交通数据源与可视化描述符测试.mjs`（34 条，含上述 6 条回归断言）。已进 CI。

**与阶段 1 的落地位置差异**：原计划把工作区图层放 `<workspace>/map-layers/`、共享流量数据放 `maps/_shared/`；实际按阶段 1 的决策，图层数据仍在 `maps/<project>/`，归属由 `origin`/`owner` 记录（理由见阶段 1 文档"与原计划的偏离"）。流量数据作为普通工作区文件由 `local-file` 读取，不引入新目录。
