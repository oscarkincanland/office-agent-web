# P4 验收清单

本清单把 P4 的验收项拆成三类，**不把「构建通过」当成「交互验收通过」**：

- **已完成（可自动复核）**：有脚本与命令，任何人可重跑。
- **待人工走查**：需要真实浏览器或真实模型，脚本只能给出前置条件。
- **待桌面阶段验证**：桌面壳尚不存在，只登记共享规范与验收口径。

## 1. 五条跨层回归

命令：`npm.cmd run test:cross-layer`（`scripts/跨层回归测试.mjs`）。
每条都同时核对 API/SSE 层、React 状态/文案层与样式动画层。

| # | 场景 | API 层证据 | 客户端证据 | 动画层证据 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 1 | 首次启动部分失败 | 四分区各自独立返回；单分区 404 不级联 | `setScopeStatus(分区,"error")`、保留上次数据、统一重试、`.load-recovery` | 失败态无任何无限动画 | 已完成 |
| 2 | 会话恢复失败 | `POST /api/agent/resume` 404/400；`POST /api/runs/:id/resume` 404 | 失败落为只读 + `retrySessionResume` + 「历史已加载为只读」 | `.session-resume-warning` 无无限动画 | 已完成 |
| 3 | 并行任务等待审批 | `/api/agent/approvals`、`/api/agent/pending` 可枚举；审批决定 400/404 可区分 | `data-approval-id`、`locateApproval` 只找未决审批、状态条可定位 | 审批卡无无限动画（等待靠文案，不靠循环） | 已完成 |
| 4 | 工具部分失败仍结束 | `inferCompletion` 校验失败 → `partial`，失败 → `failed` | 摘要暴露「N 失败」「验收失败」；结果卡列出未完成/受阻项 + 可展开技术细节 | `.run-result` 一次性入场，无循环跳动 | 已完成 |
| 5 | 成果不可回滚 | `/api/artifacts` 返回可判定能力的列表；回滚必须 `confirm=true` | `canRollback` 由 `rollbackTarget` 决定；首个版本显式说明需手动恢复 | 成果列表无无限动画 | 已完成 |

判定要点（防回归）：

- 有失败步骤时摘要**不得**出现「全部成功/全部完成/一切正常」。
- 失败/错误/恢复/审批等待这类状态**不得**挂 `infinite` 动画：状态先于动效。
- 结果卡必须保留可展开的技术细节，失败步骤可查。

## 4. 桌面端验收清单（待桌面阶段验证）

桌面壳当前不存在。以下为网页端已定的共享规范，桌面阶段必须复用而不是另起一套：

- 状态语义：运行结束 / 任务达成 / 步骤进度 / 验收结果 四项独立表达，来源是同一套事件与 `complete_task` 契约。
- 动效闸门：桌面端也要读系统「减少动效」，并与产品「关闭动效」合成同一套闸门；不得只在网页端生效。
- 动效时长区间：按钮 80–150ms、菜单/卡片 150–220ms、面板 180–280ms；持续动画清单与 `docs/plans/2026-09-23-001-P3动效清单.md` 一致。
- 无障碍：Windows 通知、系统焦点、读屏（Narrator）下的状态播报需另做平台适配；共享组件层不得绕过 `role`/`aria-live`。
- 审批作用域：`.oaw/permissions.json` 为应用全局持久化，桌面端必须使用同一份语义（`ask`/`allow`/`deny` 三值与「总是允许」前缀通配规则）。
- 验收方式：复用 `test:cross-layer`、`test:a11y`、`test:motion`、`test:perf-budget`；桌面壳新增的窗口/通知/浏览器视图另写专项。
