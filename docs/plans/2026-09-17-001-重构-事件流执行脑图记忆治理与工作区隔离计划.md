# 重构事件流完整性、执行脑图、记忆治理与工作区隔离

## 1. 计划定位

本计划承接既有计划中尚未闭环的问题：

- `docs/plans/2026-09-07-001-修复-对话事件流性能与打字机计划.md`
- `docs/plans/2026-08-31-001-规聚后续稳定性与智能体工程管理改造计划.md`

本轮聚焦四条链路：**事件流完整性与可恢复**、**对话/Run 编排与执行脑图**、**记忆准入治理**、**工作区与会话隔离（含地图项目）**。

优先级原则：

1. 先保证事件不丢、Run 状态准确。
2. 再建立 workspace/project 隔离。
3. 然后实现脑回路执行图。
4. 再治理长期记忆。
5. 最后迁移地图项目和历史数据。

不能先做脑图，否则只会把不完整、可能串项目的事件画得更漂亮。

## 2. 问题背景（审查结论）

### 2.1 事件流会真实丢事件

最严重的问题是 Runtime 重建后事件序号从 0 开始，前端仍携带旧 cursor，新 Runtime 前 N 个事件在服务端 SSE 出口就被过滤。

- 新 Channel 序号重置：`server/agent.mjs` 会话创建与恢复路径
- 前端按 client/thread 长期保存旧 cursor：`client/src/components/ChatPanel.jsx`
- 服务端按 `seq <= after` 过滤回放：`server/index.mjs` 的 `/api/agent/stream`

典型场景：

```text
旧 Runtime cursor = 300
长时间空闲后 Runtime 重建
新 Runtime seq 从 1 开始
前端仍请求 after=300
新 Runtime 的 1～300 号事件全部被过滤
```

这能解释：SSE 正文丢失、前几个 read/write/bash 不显示、只看到最后一个工具、长时间不对话后更容易发生。

此外存在三层截断：

- 实时 Channel 只保留约 2000 个事件，token/thinking/tool_output 与工具边界共用同一窗口；
- Run 历史超过约 800 条后不再追加普通事件（`server/runs.mjs`）；
- 前端执行流只保留最后 80 条（`ChatPanel.jsx` 的 appendExecutionFlowEvent）。

当前协议没有 `truncated/resync` 通知，前端收到孤立 `tool_end` 时也不会补建工具卡。

### 2.2 read/write/bash 实际都存在，但展示不完整

服务端统一监听 Pi SDK 工具生命周期并归一化：

```text
tool_execution_start → tool_start
tool_execution_update → tool_output
tool_execution_end → tool_end
```

前端支持多个工具卡（创建/输出/完成），但受 2.1 的事件丢失与截断影响，实际界面可能只显示最后一个工具调用。

工具按模式分白名单：

- Chat：read/grep/find/ls/ask_user/kb_*/skills_*/context_read
- Agent：Chat + bash/write/edit/map_*/memory_update/todo/officecli

工具定义位置：`server/task.mjs`。模型按任务判断实际调用哪些工具，不应要求每轮都出现全部工具。

### 2.3 “执行过程”只是原始事件列表，不是编排模型

当前 `ExecutionFlow` 是 SSE 事件的过滤渲染（`ChatPanel.jsx`），缺少上层任务结构（理解目标→读取上下文→计划→工具→验证→完成），折叠态只显示最新事件，容易误读为“只执行了一个工具”。

当前没有显式完成工具（如 complete_task），Run 是否“成功”主要靠回合结束、Promise 返回和文件 diff 推断，无法区分：成功完成 / 部分完成 / 被阻塞 / 只回答了文字 / 文件生成但未验证。

### 2.4 记忆体系缺少准入治理

当前实际有三层：

- 工作区长期记忆：`<workspace>/memory/MEMORY.md`
- 全局候选队列：`.oaw/memory-proposals.json`
- Pi 会话历史：`.规聚会话/*.jsonl`

问题：

- 记忆准入完全依赖模型自觉（提示词要求每轮自行判断调用 memory_update），服务端只校验非空、分类合法、长度 ≤1200；
- 临时错误、一次性网络状态、Harness 内部实现、无来源数字、单次观察偏好都会进入 pending 队列（实际 29 条建议中 24 条 pending，含大量短期环境状态）；
- 没有真正区分 user/project/session/run 作用域，正式记忆只写 `<workspace>/memory/MEMORY.md`；
- 没有过期、撤销、supersede；删除 MEMORY.md 后旧 JSONL 会话中仍残留旧记忆；
- 去重只在批准时做完全字符串比较；全局建议队列无锁、无事务，最后 300 条无差别 slice；
- `memoryPolicy=manual` 存在于项目设置，但运行时没有真正生效；
- 读取是固定前缀截断（AGENTS.md/memory 各取前 1800 字再合并截断），不是按任务相关性检索；
- 记忆面板可见的 `.txt`/子目录 `.md` 实际不会被 Agent 读取；
- 根目录 `AGENT.MD` 与运行时读取的 `AGENTS.md` 不一致。

### 2.5 工作区不是可靠隔离边界

- 当前工作区是进程级全局可变状态（`server/workspace.mjs` 的 `_currentWorkspace`，`/api/workspace/switch` 直接修改），两个标签页切换项目会互相影响；
- Runtime key 只有 `client::thread`，健康 Runtime 无条件复用，不校验 cwd 是否变化；切换项目后可能继续使用旧项目的工具、JSONL、记忆和资源加载器；
- 会话恢复接口接受调用方传入的 cwd，不校验是否等于 JSONL header.cwd，可把 A 工作区历史绑定到 B；
- 地图项目固定写入 `office-workspace/maps`，完全绕过当前工作区（跨项目地图污染、错误锁定、Run 快照漏报）；
- `.agent-context.md` 是同工作区多线程共享文件，并发会话互相覆盖；
- 会话引用 `&会话[...]` 跨工作区扫描，可把 B 工作区历史注入 A 上下文；
- Bash 只设 cwd，无工作区外路径边界；managed read 校验失败时回退原始绝对路径。

## 3. 目标与非目标

### 3.1 目标

- **R1 事件完整性**：长空闲、Runtime 重建、SSE 断线、切换会话后不丢正文、不丢工具调用、不重复消息、不串 Run，终态可准确恢复。
- **R2 对话/Run 编排**：明确区分能力准备、模型思考、实际工具调用、文件写入、结果验证、成功/部分/阻塞/失败。
- **R3 脑图式执行轨迹**：回复前展示脑回路图，呈现真实执行阶段与工具节点，不暴露原始隐藏思维链。
- **R4 工具可见性**：完整展示 read/write/edit/bash/officecli/map_*/kb_*/skills_*/memory_update/todo/ask_user 的实际调用。
- **R5 记忆治理**：只有稳定、可复用、有证据、作用域明确的内容才能进入长期记忆候选。
- **R6 工作区隔离**：workspace/project/session/thread/run/artifact/map/memory 具有不可混淆的身份与归属。
- **R7 地图项目管理**：统一基础路网共享，项目图层、分析、会话、产物和恢复状态分别隔离。

### 3.2 非目标

- 不替换 Pi SDK，不修改 Pi 内核。
- 不展示模型不可见的完整思维链原文铺满图表。
- 第一阶段不引入向量数据库。
- 不实现多用户权限系统（但 API 归属校验要先行）。
- 不把 Bash 包装成真正的安全沙箱；第一阶段只做防误操作的工作区路径约束。
- 不重做整体视觉主题。
- 不强制每次对话都调用工具。

## 4. 目标架构

### 4.1 事件链路

```text
Pi Runtime
   ↓
Event Protocol V2
   ├─ 生命周期日志：阶段、工具边界、错误、终态（语义保留）
   └─ 高频缓冲区：token、thinking、tool_output（有限环形窗口）
   ↓
RunTrace Reducer
   ├─ 阶段状态
   ├─ 工具调用（按 toolCallId 聚合）
   ├─ 文件变化
   ├─ 验证结果
   └─ 完成状态（success/partial/blocked/failed）
   ↓
   ├─ 对话消息
   ├─ Agent 脑回路图
   ├─ Run 历史
   └─ 任务中心
```

### 4.2 工作区归属

```text
Workspace
├── shared
│   ├── basemaps
│   └── road-network        # 统一基础路网，只读/版本化引用
└── projects
    └── Project
        ├── sessions
        ├── runs
        ├── artifacts
        ├── maps
        │   ├── layers
        │   ├── analyses
        │   └── exports
        ├── memory
        └── context
```

Runtime 唯一键调整为：

```text
workspaceId::projectId::clientId::threadId
```

### 阶段 0：建立行为基线

**目标**：在修改核心状态机前，先建立真实集成测试，替代现有以源码正则为主的测试（现有 `scripts/对话流性能回归测试.mjs` 主要做字符串断言，且等待窗口 10s 与实现 3s 已漂移）。

**文件**：

- 新增：
  - `scripts/SSE事件协议回归测试.mjs`
  - `scripts/执行轨迹归约测试.mjs`
  - `scripts/工作区隔离回归测试.mjs`
  - `scripts/记忆准入治理测试.mjs`
- 修改：
  - `scripts/对话流性能回归测试.mjs`
  - `scripts/第二阶段记忆治理测试.mjs`
  - `scripts/第三阶段项目与会话测试.mjs`

**必测场景**：

1. 一个 Run 连续调用 3 次 read、2 次 write、2 次 bash，事件齐全且配对。
2. SSE 中途断线再连接，终态一致。
3. Runtime 重建后前端携带旧 cursor，新 Run 首个事件仍能收到。
4. `tool_start` 已丢失但收到 `tool_end`，前端创建恢复卡片。
5. 切换 workspace 后使用相同 client/thread，不复用旧 Runtime。
6. 用 B workspace 的 cwd 恢复 A workspace 的 JSONL，应被拒绝。
7. 两个会话同时改动同一工作区，写入锁与产物归属正确。
8. 临时错误、一次性网络状态尝试进入长期记忆候选，应被拦截。
9. 两个 workspace 存在同名地图项目，互不污染。

**验收**：测试能稳定复现当前的事件丢失、记忆污染和跨 workspace 串用问题。

### 阶段 1：Event Protocol V2

**目标**：解决长空闲、Runtime 重建、SSE 重连导致的确定性事件丢失。

**文件**：

- 修改：
  - `server/agent.mjs`
  - `server/index.mjs`
  - `server/runs.mjs`
  - `server/事件存储.mjs`
  - `client/src/components/ChatPanel.jsx`
- 新增：
  - `server/事件协议.mjs`
- 测试：
  - `scripts/SSE事件协议回归测试.mjs`

**实施要求**：

1. 事件信封统一携带 `protocolVersion / streamId / seq / eventId / runId / threadId / workspaceId / projectId / at / type / data`。
2. `connected` 握手返回 `streamId / earliest / latest / truncated / 服务端时间`。
3. 前端 cursor 按 `threadId + streamId` 保存；`streamId` 变化时清空旧 cursor（代际变更，不再只比数值）。
4. 生命周期事件与高频增量分层保存：
   - 生命周期日志：工具开始/结束、错误、`assistant_final`、`run_finished`，语义保留、永不因 token 挤掉；
   - 高频缓冲：token/thinking/tool_output，有限环形窗口。
5. 高频窗口溢出或游标落后时，服务端先发 `stream_resync`；前端用 Run 历史 + Pi JSONL 重建终态。
6. 前端修复：
   - 事件处理成功后才提交应用层 cursor；
   - `tool_end` 找不到对应 start 时创建“恢复的工具调用”卡片（`startMissing` 标记）；
   - `assistant_final` 永远是正文权威，丢失 token 时补齐/替换；
   - 修复 `runtime_init_failed` 调用未定义的 `setStatusMsg`（改用已有 `setModelMsg`，并统一置 busy/runState failed 终态）。
7. `recordRunEvent()` 满 800 后不再静默停止：终结/错误/工具边界/`assistant_final` 永不淘汰，仅对 stats/边界采样。

**验收**：

- Runtime 重建后第一条新事件仍可显示，无需刷新页面。
- 断线超过高频缓存范围后收到明确 resync，正文与工具终态一致。
- 10 个工具调用全部可恢复。
- 最终正文与服务端 `assistant_final` 一致。

### 阶段 2：统一 RunTrace 与完成语义

**目标**：把原始事件列表升级为明确的 Agent 执行状态机。

**文件**：

- 新增：
  - `server/运行轨迹.mjs`（服务端归约，供 Run 历史/任务中心/恢复使用）
  - `client/src/运行轨迹.js`（前端同构归约，实时流与历史恢复共用同一 reducer）
- 修改：
  - `server/agent.mjs`
  - `server/task.mjs`
  - `server/runs.mjs`
  - `server/index.mjs`
  - `client/src/components/ChatPanel.jsx`
  - `client/src/components/任务中心.jsx`
- 测试：
  - `scripts/执行轨迹归约测试.mjs`

**实施要求**：

1. RunTrace 结构：目标 / 上下文加载 / 计划 / 推理阶段 / 工具调用 / 文件写入 / 验证 / 产物 / 完成状态。
2. 工具按 `toolCallId` 聚合，不再把 start/output/end 当成三条独立展示记录；聚合项内含 `input / output / result / isError / duration`。
3. 新增显式完成工具 `complete_task(success|partial|blocked|failed)`，携带完成摘要、未完成事项、产物、验证结果、阻塞原因。
4. 兼容旧模型：模型未调用 `complete_task` 时由 `agent_end` 收尾，但终态标为“兼容推断”，不伪装成显式验收成功。
5. 能力与执行分离展示：
   - 本轮允许使用的工具（模式白名单）；
   - 能力计划预计使用的工具（`planTaskCapabilities` 输出）；
   - 实际调用的工具；
   - 失败和跳过原因。
6. 折叠执行流改为聚合统计（如“已调用 6 个工具 · 5 成功 · 1 执行中 · 最近：读取文件 xxx”），不再只显示最后一条事件。
7. 每个 RunSummary 支持展开查看自己的 RunTrace 工具事件（历史恢复不再只有最新 Run 可见）。

**验收**：

- 文件生成但未验证时不能显示“完全成功”。
- 工具失败但任务降级完成时显示 partial。
- 用户可区分“模型回答结束”与“任务真正完成”。

6. 数据源为 RunTrace（阶段 2 输出），不直接消费原始事件。
7. 不增加新的模型调用，不影响首响应时间。

**验收**：

- 复杂任务能直观看到多个工具节点，不再只显示“最后一个事件”。
- 脑图与消息流工具卡数量一致。
- 隐藏思考内容时图表仍完整可用。

### 阶段 4：Workspace 与会话隔离

**目标**：取消进程级全局 workspace，建立请求级归属边界。

**文件**：

- 新增：
  - `server/工作区注册表.mjs`（workspaceId ↔ canonical realpath 映射）
  - `server/请求上下文.mjs`（中间件解析 workspaceId/projectId）
- 修改：
  - `server/workspace.mjs`
  - `server/index.mjs`
  - `server/agent.mjs`
  - `server/Pi运行时管理.mjs`
  - `server/context.mjs`
  - `server/项目管理.mjs`
  - `server/写入协调.mjs`
  - `server/runs.mjs`
  - `server/成果管理.mjs`
  - `server/记忆管理.mjs`
  - `client/src/App.jsx`
  - `client/src/api.js`
- 测试：
  - `scripts/工作区隔离回归测试.mjs`
  - `scripts/第三阶段项目与会话测试.mjs`

**实施要求**：

1. 删除服务端全局 `_currentWorkspace` 作为业务依据；`/api/workspace/switch` 只保存客户端 UI 偏好，不再修改服务端全局变量。
2. 每个 API 请求显式携带 `workspaceId/projectId`，由中间件解析为规范化根目录。
3. workspace 注册表保存稳定 ID 与 canonical realpath（继续使用 realpath 规范化与路径越界拒绝）。
4. Runtime key 改为 `workspaceId::projectId::clientId::threadId`；健康 Runtime 复用前验证完整身份，不一致则拒绝而不是静默重绑。
5. JSONL session header 固定保存 `workspaceId/projectId`；恢复时强制校验调用方 cwd 与 header.cwd 一致。
6. Session/Run/Artifact/Memory/Map 的 ID 路由接口全部校验资源归属（详情/删除/回滚/恢复/重试/发布/验收）。
7. `.agent-context.md` 改为线程级（`.agent-context/<threadId>.md`）或取消磁盘共享文件，改为 Runtime 内存注入。
8. `&会话[...]` 默认只能引用同 workspace/project 会话。
9. managed read 校验失败时不再回退工作区外绝对路径；Bash 增加工作区外路径的防误操作拦截。
10. Run diff 继续排除其他 run 暂存清单文件（并行任务产物不相互污染）。

**验收**：

**实施要求**：

2. 服务端硬性拒绝候选：
   - 含 Token、密码、身份证号等敏感信息；

   - `manual`：禁用 `memory_update` 工具与沉淀提示；
   - `approval_required`：允许创建候选，必须用户批准；
   - 每个 Run 默认最多一条候选（去重后）；
   - 用户明确“请记住/以后都这样”时提高优先级，但仍进入可见审核流程。
4. 生命周期：
   - pending 14 天过期；
   - 临时环境经验 1～7 天；
   - 工具 workaround 绑定应用版本，默认 30 天；
   - 项目数据绑定数据版本或复核日期；

9. 记忆面板直接编辑通道保留（本地用户有权编辑），但要求记录编辑来源/时间，不做无痕覆盖。

## 6. 系统级验收标准

### 事件与对话

- 空闲 30 分钟后首次发送不丢事件。
- Runtime 重建后无需刷新页面。
- 10 个连续工具调用全部可见。
- SSE 断开、重连、切换会话后最终正文一致。
- `run_finished` 丢失时可从 Run 状态恢复。

### 编排与脑图

- 能区分计划工具与实际工具。
- 工具节点数量与 RunTrace 一致。
- 成功 / partial / blocked / failed 判定准确。
- 脑图不增加模型请求与首响应等待。

### 记忆

- 临时错误、网络状态、工具故障不进入长期记忆。
- 所有记忆都有作用域与来源。
- manual 策略真正生效；项目切换后无记忆泄漏。
- 支持过期、撤销、替换。

### 工作区

- 两个标签页、两个项目、两个会话并发时不串 cwd。
- Runtime 不跨 workspace 复用。
- Session/Run/Artifact API 验证归属。
- read/write/bash/map 不越过当前项目边界。

### 地图

- 基础路网统一共享。
- 项目图层与分析隔离。
- 地图会话与恢复状态绑定项目。
- 同名地图项目可存在于不同 workspace。

## 7. 主要风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 历史 JSONL 已包含旧记忆，删除 MEMORY.md 不会自动遗忘 | 记忆版本化；压缩时排除 revoked 内容；必要时提示分叉新会话 |
| Bash 不是安全沙箱 | 路径检查仅防误操作；对外服务前必须 OS 级隔离 |
| 事件协议升级影响面大 | 保留旧事件名称，先升级 envelope 与握手，避免一次性重写所有消费者 |
| 地图数据体积大 | 基础路网只引用/版本化，不物理复制 |
| 记忆治理拖慢首响应 | 准入检查在 memory_update 调用时执行；语义去重 Run 完成后异步执行 |
| 全量改造一次性合入风险高 | 分阶段独立验收，开关可回滚 |
